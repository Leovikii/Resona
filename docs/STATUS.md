## 当前版本

目标版本为 `0.1.0`，计划状态为 In Progress；包版本暂保持 `0.1.0-rc.4`。功能稳定化已通过当前 Windows 实机验收；现阶段只处理最终视觉细节、图标收尾和发行门禁，不再增加产品能力。

当前范围见 [0.1.0 计划](plans/0.1.0.md)；rc.4 完成事实保留在 [rc.4 计划](plans/0.1.0-rc.4.md)。

## 0.1.0 正式版收口已实现

- 压缩窗口关闭时以 Rust 权威批次状态区分当前任务与旧工作区：运行或取消中的批次完整保留，扫描、待开始和所有终态立即恢复初始状态；窗口保持关闭时，活动批次在完成后自动清理，完成前重开则保留完整结果。
- 桌面歌词保留 Tauri `always_on_top`，并在显示、锁定、解锁、失焦、系统恢复和 DPI 变化时执行一次无激活 Win32 topmost 校正；锁定 helper 同步校正物理边界，不增加定时器、全局 hook 或轮询。
- 解锁 helper 继续使用 ADR 0012 规定的无 WebView 原生窗口。图标改用 Windows 系统矢量字体，命中尺寸、小圆角、白色图标和 hover 层级与桌面歌词工具栏一致，不新增图形依赖。
- 完整播放器的活动歌词定位只滚动歌词 `ScrollArea` 的纵向 viewport，不再使用会影响祖先容器的 `scrollIntoView`；高亮歌词取消横向位移，有歌词歌曲打开播放器时封面位置保持稳定。无歌词页使用静态占位区域，不挂载 `ScrollArea`，窄屏下不能上下滚动。
- 切歌时保留当前可用播放器分页，歌词和当前曲目元数据足以确定默认页后再一次性切换；新封面先由 WebView 解码，再与标题和媒体信息共同提交，避免旧信息清空、临时页面跳转或未解码图片造成的可见闪烁。窄屏默认页按“有效歌词 → 真实内嵌封面 → 播放信息”回退，占位图不再被误判为真实封面。
- 宽屏播放列表、窄屏标签和曲目列表右键菜单统一使用 Mantine `Menu.ContextMenu`，所有命令采用同尺寸 Lucide 图标与简短文本，删除、清空、移除和关闭其他列表使用危险语义色。共享适配器只允许一个菜单处于打开状态，并在窗口失焦或原生关闭/退出确认弹窗显示前关闭活动菜单。“关闭其他列表”由单个后端事务保留目标列表并删除其余用户列表，活动列表被删除时继续按既有规则转移到默认列表。
- 文件夹导入改由 Rust 递归扫描全部子目录，稳定排序、规范化去重且不跟随链接类路径；schema v6 为每项保存可空导入根目录。播放列表按原顺序生成可折叠目录段，顶层默认展开、子目录默认折叠，目录节点不进入播放序列，折叠目录仍携带完整拖放插入范围。
- 播放列表行删除路径副标题，按可见范围批量读取“音轨号 + 标题”轻量摘要，标题缺失时回退无扩展名文件名；Rust 与前端摘要缓存均限制为 256 项。曲目右键菜单新增“文件信息”，按需读取标签、格式、码率、音频属性和路径，并通过 Tauri opener 的跨平台定位能力打开系统文件管理器。
- 播放列表目录展开状态按列表在当前前端会话内记忆，不写入 SQLite。底栏最右恢复播放列表按钮，点击后退出完整播放器、切换到 Rust 权威当前列表、展开当前歌曲祖先目录并在列表 viewport 内定位和聚焦；自然切歌不改变展开、滚动或焦点状态。全部播放 ActionIcon 在宽/窄屏保持 Mantine `xl` 44 px，核心三键相对整个底栏严格居中；宽/窄屏的音质角标均以紧凑描边尺寸位于信息区时间右侧。窄屏下音量/播放模式左对齐，桌面歌词/播放列表右对齐。辅助按钮使用 Mantine 原生 `transparent` 变体，正常、激活和禁用状态均无背景；hover/focus 与持久激活切换为高辨识度主题色。中央播放/暂停使用 Mantine `filled` 圆形实体背景、阴影 token 和白色实心图标，禁用时保留原生灰色实体轮廓。Button、ActionIcon、侧栏导航与桌面歌词工具按钮统一复用 Mantine 主题级 `activeClassName`，按下时只降低亮度，不再改变根节点几何或浮层锚点。
- 桌面歌词字体透明度限制为 10–100%，背景透明度限制为 0–90%，两者均按 10% 步长拖动并实时应用；旧的非整十偏好会归一化到最近刻度。音量滑杆拖动时以有界的最新值队列实时提交到 Rust 权威播放状态，不再等到松开鼠标后才生效。
- 品牌视觉已确认：应用图标为紫色轻拟物唱片机（黑胶与玫红唱针），无封面曲目使用独立的深紫外圈、近黑盘面与玫红中心标唱片 SVG，不再复用应用图标。Resona 字标以连续文字作为镂空视窗，露出由首个 `o` 向外扩展的紫、梅紫与玫红唱片标签层次。MP3/WAV/FLAC 文件关联图标复用同一唱片机，并分别采用 blue/yellow/canonical violet 上半部、深灰格式信息带与白色大标签；正式 SVG 源、应用多尺寸图标和 Windows 关联 ICO 均已更新。

## rc.4 已实现

- 宽/窄屏播放列表拖放语义已统一：拖到默认/用户列表标题会添加项目并切换目标，拖到用户列表间隙会按位置新建、导入并切换列表；顶部工具/设置与播放列表统一 hover、focus 和激活层级。
- Mantine Modal 全局使用 180 ms `pop` 过渡；更新弹窗关闭时保留挂载，播放列表清空/重命名不再使用浏览器原生对话框。
- 完整播放器取消文字分段开关：宽屏右侧为歌词/信息两页，窄屏为封面/歌词/信息三页；无文字圆点和左右按钮只在 hover/focus 时显示，不增加手势或轮播依赖。
- 有效歌词默认歌词页；无歌词时宽屏默认信息，窄屏仅在存在真实内嵌封面时默认封面，否则回退信息；异步结果不会覆盖同曲目内的用户选择。压缩树按扫描批次只自动展开首次出现的顶层目录。
- 播放列表导航统一为普通序号，当前列表在同一槽位显示播放动画；默认列表固定首位，用户列表可在宽/窄屏拖曳排序并支持右键上移/下移，窄屏鼠标滚轮横向浏览标签。
- 导入拒绝提示使用 Mantine Notification 的原生图标插槽替代左侧强调线，可关闭且 4 秒自动退出；前端保留后端已有的拒绝原因枚举，并以简短文本列出实际原因。窄屏播放列表通过 Mantine ScrollArea 原生偏移为横向滚动条留出空间，激活项不再遮挡滚动条。窄屏完整播放器标题区与封面/歌词/信息正文保留 16 px 安全距离，封面同时受可用宽高约束。
- 外部文件拖放与内部排序在宽屏播放列表导航、窄屏横向标签和曲目列表靠近边缘时持续自动滚动；滚动后重新计算插入目标，到达实际边界、拖放结束或组件卸载时停止动画帧。
- 窄屏默认列表与用户列表的标题区统一为“标题 + 右上添加”两列；360/420 px 下按钮不再换行，长路径和可编辑列表名仍可收缩。
- 共享封面统一归一化为最大 512 px PNG/BGRA，并携带稳定内容指纹。`MetadataService` 以源字节指纹复用最多 8 个封面对象，同专辑相同封面不再重复解码、缩放和 PNG 编码；任务栏按归一化指纹复用整组 GDI 位图。DWM 回调始终即时提交最近的不超界缓存，不再等待补偿渲染。SMTC 直接以指纹复用 PNG，按最近使用顺序保留最多 16 个不同封面，避免立即删除竞态和长会话磁盘无限增长；时间轴按 5 秒节流。
- 测试 EXE 构建收口为 `npm run build:exe`；裸 `cargo build --release` 产物仍访问 Vite `devUrl`，不得交付。

## rc.3 已实现

- SMTC 将共享封面按内容哈希写入应用缓存，再以 WinRT 可接受的本地文件路径提交；扩展路径前缀会正规化，失败时回退应用占位图和纯文本，adapter 启动和退出时清理应用自有缓存。
- 底栏音量弹层改为垂直滑杆；弹层内滚轮单次增减 10 个百分点。420px 及以下播放列表与宽屏一致，普通歌曲显示序号，当前歌曲在同一位置显示动态状态。
- 关闭音频压缩窗口会取消扫描并丢弃输入列表，不中断已启动转换；子窗口补齐重新显示与标题更新所需的最小权限。

## rc.2 基线

- 最近播放已从宽/窄屏导航、页面、前端模型、Tauri commands、播放写入和 SQLite 中完整删除。schema v5 会删除旧 `recent_plays` 表，同时保留用户播放列表、项目和应用状态。
- `MetadataService` 以路径、文件大小和修改时间为键维护最多 4 首曲目的有界缓存；封面限制源大小、解码内存和尺寸。底部播放器、完整播放器、SMTC、托盘投影与 Windows 任务栏共用同一份当前曲目元数据和封面结果。
- 底部播放器显示 52 px（窄屏 44 px）封面；无封面使用统一占位图。Windows DWM iconic thumbnail/live preview 只提交等比居中的封面或占位图，不再使用窗口实时截图；窗口消息回调只读取缓存 BGRA，不进行文件 I/O 或解码。
- 设置“关于”已置顶。版本号与检查更新合并为动态按钮；应用首帧后每进程静默检查一次，发现更新才打开懒加载弹窗。弹窗安全渲染 Markdown/GFM 更新日志，外链只允许 HTTP(S)，可直接下载、验签、取消和安装。
- WAV 到 FLAC 继续使用 FFmpeg。扫描和转换前后参数校验改为进程内 `hound`/`lofty`，转换热路径不再启动 ffprobe；批次按可用核心数启用 1–4 个文件级 worker。每个 worker 使用独立临时文件，取消时终止其 FFmpeg，验证成功后原子提交，提交后才允许删除源文件。
- 压缩快照改为逐项 `progress/sourceBytes/outputBytes`。文件行本体显示进度覆盖层和终态，标题区在转换前显示数量与输入体积，结束后按成功项显示输入、输出、节省体积/比例，并附简短失败或取消计数。
- 版本已统一切换到 `0.1.0-rc.2`。

## 长期基线

- Rust 拥有播放、列表、偏好、压缩、更新和原生窗口权威状态；React 只负责展示与意图。
- Rodio 是唯一播放引擎；FFmpeg 只用于按需音频压缩。
- SQLite 只持久化用户播放列表、列表项目和应用状态，不建立媒体库、封面数据库或最近播放历史。
- 主分支发布只经受保护 PR 合并与单一 GitHub Actions 工作流完成；版本号决定 prerelease/stable，不提供手工 tag 或旁路发布。
