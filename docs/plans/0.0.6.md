# 0.0.6 Windows 媒体会话与硬件控制

- 状态：Completed；SMTC 浮层身份显示问题已在 0.0.19 安装身份阶段关闭
- 前置版本：0.0.5 应用壳与文件夹播放闭环
- 所属阶段：P2 播放体验 / Windows 平台集成
- 计划日期：2026-07-18

## 名称与目标

Windows 对应能力是 SMTC（System Media Transport Controls），不是 MSRP。它把 Resona 注册为系统媒体会话，接收耳机和键盘媒体键，并向 Windows 媒体浮层、锁屏及系统媒体界面提供播放状态和曲目信息。通知中心 Toast 和系统托盘图标是不同能力，不纳入本阶段承诺。

## 技术策略

- 先做隔离技术验证，对比 `souvlaki` 与直接使用 `windows` crate 的 SMTC API。
- 优先候选为 `souvlaki`：代码量较少，并为未来 Linux MPRIS 保留同类 adapter；只有其 Windows 行为或维护状态不满足要求时才改用 `windows` crate。
- 媒体会话位于 `platform/media_session` adapter，不让 Windows 类型进入 `PlaybackEngine`、队列模型或前端契约。
- adapter 在应用启动时注册一次，退出时显式释放；设备重建和切歌不重复注册系统会话。
- 系统回调只转换为 typed playback command，不直接操作 Rodio `Player`，不持有 UI 或 actor 锁。

## 播放状态桥接

- 增加可合并的播放状态发布通道，向 UI 和媒体会话广播曲目、播放/暂停、时长和位置变化。
- 曲目和播放状态变化立即发布；时间轴最多每秒更新一次，避免高频跨边界通信。
- 自动切歌、手动切歌、定位和设备恢复都必须更新同一媒体会话。
- 该通道后续可以替代前端当前 750 ms 全量轮询，但 0.0.6 不强制一次性移除所有轮询。

## 系统命令

- 支持播放、暂停、播放/暂停切换、停止、下一曲、上一曲和系统定位请求。
- 上一曲行为：当前曲目位置大于 3 秒时回到曲首，否则切换到前一有效队列项。
- 系统音量键继续由 Windows 管理，不把它们映射为 Resona 应用内音量。
- 队列不存在对应项目时禁用相关 SMTC 按钮，而不是接收后返回通用错误。

## 系统显示信息

- 首版标题使用文件名；艺术家、专辑和封面未知时留空，不伪造占位元数据。
- 后续接入 lofty-rs 后，用统一元数据模型丰富 SMTC，不在 Windows adapter 内重复解析标签。
- 发布播放状态、标题、时长和时间轴；具体出现于 Windows 哪个系统面板由系统版本决定。

## 明确不包含

- 自定义 Windows Toast、系统托盘菜单、任务栏 Jump List 和全局自定义快捷键。
- 锁屏封面下载、在线元数据、蓝牙 AVRCP 自研协议或音量键拦截。
- Linux MPRIS 实现与验证；只保留 adapter 契约。

## 验收标准

1. 键盘和蓝牙耳机的播放/暂停、上一曲、下一曲能可靠驱动现有 Rust 播放队列。
2. Windows 系统媒体界面显示与 Resona 一致的播放状态、文件名、时长和位置。
3. 自动切歌、定位、暂停、恢复和设备重建后系统状态不会停留在旧曲目。
4. 快速连续按媒体键不会阻塞音频 actor、Tauri 主线程或 WebView。
5. 未启用或不支持的平台能力通过 adapter 明确降级，不影响普通播放。
6. Rust test/Clippy、Windows 实机媒体键测试和 Tauri release build 通过。

## 需要审阅的决策

1. SMTC 作为 0.0.6 独立增量，不与 0.0.5 UI 重构同时实现。
2. 先验证 `souvlaki`，不预先承诺或引入长期依赖；直接 `windows` crate 作为备选。
3. 系统托盘和 Toast 与 SMTC 分开规划，不在本阶段顺带实现。
