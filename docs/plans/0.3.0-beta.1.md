# 0.3.0-beta.1：NFS 文件打开、原生文件选择与窗口内键盘控制

- 状态：Accepted；基础实现与本机主要验证已完成，Windows CI 已通过、实机待验收；所有者追加的网络文件夹支持已接入 KIO 目录边界，最终本机验证与 Windows 回归按记录验收。授权提交并推送 dev，暂不合并发布。
- 日期：2026-10-29。
- 基线：`0.3.0-alpha.4`；当前开发版本为首个 beta `0.3.0-beta.1`，继续作为预发行版本。
- 范围：Windows 与 Arch x86_64 / KDE Wayland；NFS 与 portal 专项在本机 KDE 验收，键盘控制双平台验收。
- 长期边界：[ADR 0036](../decisions/0036-native-file-access-and-focused-playback-controls.md)。当前事实仍以 [STATUS](../STATUS.md) 为准。

## 目标与已知事实

1. 修复从 Dolphin 打开 NFS 音频时，被同目录扫描阻断的问题。
2. 文件、文件夹选择通过桌面提供的标准原生对话框，KDE 下能够选择 OMV NFS 网络位置。
3. 应用获得焦点时提供空格、方向键播放控制，并给音量操作明确的视觉反馈。

已确认 Dolphin 映射的 KIO-FUSE 文件原可读，但父目录枚举为空，且枚举后原文件可能返回 ENOTDIR。旧入口要求所选文件出现在扫描结果中，因此解码前失败。beta.1 使用 GIO 挂载类型识别，网络目录改走原生 KIO 列举，先经官方 D-Bus 刷新父目录与文件映射；两首真实 NFS 音频已完整解码、定位并通过低音量真实输出测试。不能据此断言服务端内部缺陷。

Linux 选择器已改为标准 XDG portal；所有者在隔离原生测试中看到 OMV、完成选择和取消，Rust 可读/单文件上下文及取消结果断言通过。整套界面变英文随后已复现，现通过原生系统语言接口修复，所有者确认主界面中文；不扩展为所有入口或 Windows 语言验收通过。详细通过项与待测项分别见 [Linux 验证](0.3.0-beta.1-linux-validation.md) 和 [Windows 交接](0.3.0-beta.1-windows-validation.md)。

### 追加要求：网络文件夹完整支持（已选择最小补修）

所有者不接受将网络文件夹拒绝提示作为最终交付：从 Dolphin 拖到列表区域创建列表、拖到内容区追加、原生对话框手动添加均须支持。“提示明确”只验证错误文案；本轮用 KIO 列举替换临时禁用保护，继续避免已知有害的 FUSE readdir。

- **系统方案不作为前提**：所有者反馈内核挂载在 OMV 离线时会使 Dolphin 卡死，这是其改用网络路径的原因；撤回内核挂载优先建议。应用不得要求用户改用本地挂载入口或修改书签，systemd automount 也不能视为已解决远端失联时的 I/O 阻塞。尚未执行挂载或修改系统配置。
- **已实施的程序方案**：KIO ListJob 只负责列出网络目录，排除有错误类型元数据的“.”/“..”；保留现有 KIO-FUSE 明确文件映射及 Rodio。C++ 代码编译进同一可执行文件，通过内部工作模式在 GTK/单实例初始化前运行独立 QtCore 事件循环，避免新增 sidecar、播放器或数据库迁移。Rust 统一目录边界覆盖递归导入、同目录上下文、CUE、歌词、外置封面和压缩扫描；一次导入复用 CUE 候选，避免按曲目重复列网络目录。原始 NFS URI 与已映射路径共用该边界，拖入创建列表的名称使用解析后的导入根目录。
- **故障依据**：本机 KIO 原生列举音频父目录得到 6 文件、4 子目录，但“.”自身类型为普通文件（32768）；KIO-FUSE 源码会用“.”更新目录节点，解释了此前枚举后 ENOTDIR。排除这些条目后的真实导入与解码另行实测；尚未确认对应的上游缺陷编号。
- **离线与边界**：KIO 工作任务 15 秒，父进程 20 秒兜底并终止/回收工作进程；每目录最多 100000 条、输出最多 16 MiB，拒绝路径穿越名称，失败返回可诊断错误。保留地址失联测试只验证此目录边界，不声称任意 FUSE stat/read 可立即中断。持久列表仍保存物理路径；应用重启可在同一桌面映射下读取，但注销/重启机器后的永久 URI 恢复留待独立数据模型变更。
- 验收覆盖三个入口共用的 Rust 后端、递归、排序、同请求去重与读取后播放；真实鼠标落点仍与后端自动验证区分。Windows 实机完成前不合并发布。

### 上游实现参考与诊断边界

本次调查确认本机 KIO 原生列举成功、KIO-FUSE 映射目录枚举异常；本轮补修的真实递归导入和文件读取已通过，但未找到足以确认同一根因的上游缺陷报告。KIO-FUSE 是桌面系统服务，也属于当前应用访问链路，不能将“应用依赖”与“系统缺陷”简单二分。内核挂载提供常规文件接口，并不保证远端失联时具有本地磁盘的响应行为，本轮也未重新试挂载。

- [Dolphin KFileItemModel](https://github.com/KDE/dolphin/blob/master/src/kitemviews/kfileitemmodel.cpp)：通过 KDirLister/KCoreDirLister 按 URL 加载目录，连接条目、完成、取消和错误事件。适合参考 KDE 下的异步目录访问；Resona 批量导入可使用更直接的 KIO ListJob，无需复制 Dolphin 视图模型。
- [KIO-FUSE 设计](https://github.com/KDE/kio-fuse/blob/master/DESIGN.md)：POSIX lookup/stat 与 readdir 分别触发 KIO 操作，解释为什么明确文件可读与目录枚举成功不能互相替代；该设计文档不证明本机故障的具体原因。
- [MPD NfsStorage](https://github.com/MusicPlayerDaemon/MPD/blob/master/src/storage/plugins/NfsStorage.cxx)、[NfsInputPlugin](https://github.com/MusicPlayerDaemon/MPD/blob/master/src/input/plugins/NfsInputPlugin.cxx) 与 [NFS Connection](https://github.com/MusicPlayerDaemon/MPD/blob/master/src/lib/nfs/Connection.cxx)：用户态 libnfs 负责目录、输入流、定位、取消回调及重连状态，网络来源保留 URI。适合参考网络访问与解码分层；无需引入 MPD 或替换播放引擎。
- [Kodi NFSDirectory](https://github.com/xbmc/xbmc/blob/master/xbmc/filesystem/NFSDirectory.cpp) 与 [NFSFile](https://github.com/xbmc/xbmc/blob/master/xbmc/filesystem/NFSFile.cpp)：同样以 libnfs 提供目录和文件访问，连接设置包含超时、重连次数与协议版本。其符号链接跟随策略不符合本项目导入规则，不照搬。

以下为选型时的比较记录；本轮已选择 KIO 目录最小补修，未引入 libnfs：相较 KIO 目录桥接加 FUSE 读取，它有机会统一控制网络枚举与文件读取，避免桌面/挂载前提；代价是 Rust FFI、双平台原生依赖及元数据/CUE/歌词/封面访问适配。本项目锁定 Rodio Decoder 支持 Read + Seek，理论上可接网络读适配而保留单引擎，但当前实现仍固定 File，尚未验证集成。选型前应比较两者在本机的递归、读取/定位、离线期限、取消和资源回收；不同时引入两套新网络后端。libnfs 的默认重试不保证快速失败，必须显式设计有界失败策略；另需核查实际 NFS 版本、UID/GID 及服务器端口权限，不能承诺任意 OMV 配置免调整。

## 一、文件打开与 NFS 路径

### 先保证所选文件可播放

- 将“验证用户明确选中的文件”与“发现同目录其他音频”分开。后者只扩展一次性默认列表，不能作为打开目标文件的前提。
- KIO-FUSE 挂载的目录通过直接 KIO 列举恢复同目录音频、自动 CUE、伴随歌词、外置封面和递归文件夹发现；不对该 FUSE 路径执行 readdir。本地及内核挂载目录正常时保留当前排序、同目录上下文和同名 CUE 展开。扫描为空、失败或遗漏目标时，至少保留所选音频；能取得可靠同目录结果时按原有排序纳入目标，不重复添加，也不把 CUE 逻辑曲目合并成物理文件。
- 所选文件仍必须存在、格式受支持，并由既有 Rodio 解码验证。文件不可读、格式损坏和网络中断必须明确失败；不把这些错误伪装成“只有一首”的成功。
- 同目录扫描降级返回稳定的警告码并记录原因；成功播放与目录警告分开展示。空目录、读取失败与缺少目标须可区分，不在日志输出完整私人文件名或网络凭据。
- 外部首次启动、第二实例激活和应用内“打开”共用该入口。冷启动结果/错误在前端 ready 后仍可读取，不只依赖可能早于监听注册的一次性事件；沿用现有快照/ready 协调，不建设通用消息队列。
- 已明确选择的多个文件全部按现有导入语义处理，不因首个文件的扫描降级丢掉其他选择。手工添加仍只加入所选项目；递归文件夹导入保留原有扫描和不跟随链接规则。

### 使用桌面的文件访问能力

- 内核挂载的 NFS 路径、KIO-FUSE 路径以及 portal 返回的可读本地路径进入同一 Rust 文件边界，Rodio 继续只消费物理路径。
- `file://` 使用成熟 URL 解析与路径转换，不手工删除前缀或替换转义字符。Linux 收到原始 `nfs://` 时，通过 KDE KIO-FUSE 官方 D-Bus 接口取得本地映射；该能力放在 Linux 文件访问 adapter 中，外部打开与 portal 返回值共用它。
- 不把 `nfs://...` 当作相对路径拼到工作目录；不把 URI 直接传给 `File::open`。缺少映射服务、服务不可达、权限不足或未知协议时，返回可翻译错误及可操作提示。
- 外部打开的 desktop `%F` 路径兼容保留；不为支持原始 URI 而未经验证直接改为 `%U`。解析本地路径时不误判 Windows 盘符、UNC 或带空格/中文的文件名。
- 不自动执行 mount、提权、修改 `/etc/fstab`、改用户书签、缓存整首音频或引入网络播放引擎。映射与目录 I/O 放在现有后台任务边界，避免阻塞 GTK/IPC 主线程；映射请求有失败/取消边界，不承诺中断内核中的任意阻塞文件读取。
- beta.1 承诺当前会话内的网络文件选择、打开、播放与定位。现有用户列表仍保存物理路径，不新增网络源数据库模型；临时 FUSE/portal 路径在注销、重启或断线后可能失效，必须明确提示重新选择，不宣称网络列表已具备永久稳定的路径恢复能力。

## 二、标准原生文件选择

- Linux 直接调用同一锁定 ashpd 0.11.1 的标准 XDG FileChooser API。锁定 Tauri dialog 2.7.1 / rfd 0.16.0 会丢弃无法转换为本地路径的 URI，Linux 未设置 parent，且部分服务错误折叠为取消；因此在最小平台 adapter 保留 URI、错误和真实 Wayland parent。插件仍禁用默认 GTK chooser、启用 `xdg-portal`；Tauri/WebKit 继续依赖 GTK。
- 由 portal 按桌面配置选择 backend；在 KDE 下应显示 KDE 文件选择界面，共用桌面位置和 KIO 网络能力。Windows 继续使用原生 Windows 文件对话框。
- 不运行 Dolphin 子进程充当文件选择器，不手写 KDE 书签读取器，不全局设置 `GTK_USE_PORTAL` 或覆盖用户 portal 配置。
- 音频打开、添加文件、添加文件夹、压缩 WAV/文件夹选择共用现有 `audioDialog` 边界；保持过滤器、单/多选、取消返回空结果和对话框单飞。
- 先实测锁定插件返回的 NFS 选择值：若是本地映射路径直接使用；若是文件 URI 或原始 NFS URI，在 Rust 文件访问边界转换。不在 React 中复制协议解析、挂载或播放逻辑。确认路径交给 Rust 后实际可读，不能仅凭“对话框可浏览”通过验收。
- 检查原生父窗口/Wayland 窗口关联、模态行为、取消与焦点归还。portal 打开期间暂停应用级快捷键，即使窗口焦点状态短暂滞后也不能控制后台播放。
- 当前直接 ashpd 调用不走 rfd 的 zenity 回退；服务失败明确报错，用户取消返回空结果。KDE 原生选择单独实测，不以回退界面代替验收。
- Arch 包按实际链路声明 `xdg-desktop-portal`、KDE backend 与 NFS 映射所需的 KIO-FUSE 依赖；核查 zenity 是否为锁定后端的必要运行依赖后再决定。新增传递依赖需审查许可证、离线行为并重新生成许可证清单，不升级现有依赖大版本。

实现参考：[Tauri dialog](https://v2.tauri.app/plugin/dialog/)、[XDG FileChooser](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.FileChooser.html)、[KIO-FUSE](https://invent.kde.org/system/kio-fuse)。最终选择以锁定源码与原生实测为准，偏离初始插件包装方案的原因见 ADR 0036。

## 三、窗口内键盘控制

### 按键与边界

| 按键 | 行为 |
| --- | --- |
| 空格 | 播放中暂停；暂停时继续；没有可播放的当前曲目时不操作，不自动选择第一首 |
| 左方向键 | 从当前权威位置后退 5 秒 |
| 右方向键 | 从当前权威位置前进 5 秒 |
| 上方向键 | 应用音量增加 10 个百分点，例如 35% → 45% |
| 下方向键 | 应用音量减少 10 个百分点，例如 35% → 25% |

- 快进/快退步长为 5 秒；本版不增加快捷键编辑或步长设置页面。
- 音量限制为 0%–100%，按当前值增减 10 个百分点，不吸附到十的整数倍，不改变系统总音量。空闲时仍可调应用音量，沿用既有偏好持久化。
- 定位限制在当前音轨的 0–时长范围内；CUE 使用逻辑音轨相对位置。不可定位或时长未知时不操作，不切到上一首/下一首；暂停定位后仍保持暂停。
- 主窗口的宽/窄模式、列表/完整播放器/工具/设置视图，以及压缩窗口，在窗口可见且获得焦点时可用；仅注册窗口内 DOM 按键，不注册全局快捷键或原生键盘 hook。桌面歌词保持现有不主动获取键盘焦点的行为。
- 输入框、文本编辑、输入法组合、原生/ARIA 滑块、按钮的空格激活、列表选择、下拉框、Tabs 和菜单优先保留自身键盘语义；已 `preventDefault` 的事件不再次处理。曲目行现有空格选中行为保留，不同时触发播放暂停；Enter 仍播放所选曲目。快捷键说明需明确“控件操作优先”。
- 模态对话框、原生文件选择、确认弹窗打开时暂停应用级快捷键。带 Ctrl/Alt/Meta/Shift 的组合不匹配上述裸键，避免抢占编辑、多选和系统操作。
- 空格忽略自动重复，防止长按反复切换。方向键支持系统重复，但同类操作有界串行/合并：相对步数累积，不无限堆积 IPC，释放按键后不继续产生重复操作。失焦/隐藏时清除尚未发出的重复输入；已提交的单次命令正常结束。
- 仅在匹配并接管快捷键时阻止默认滚动；不停止无关事件传播，也不在组件卸载/重建后留下重复监听。

### 状态归属与反馈

- 前端 hook 只负责按键匹配、焦点/交互排除与提交意图；播放/暂停切换、相对定位和音量增减由现有 Rust 播放 actor 基于处理时的权威状态计算。复用现有 pause/resume/seek/set-volume 实现，不以轮询快照计算绝对目标，避免快速按键使用旧音量或旧位置。
- command handler 保持 DTO 转换与转发；不在 `App.tsx`、压缩页面或 command handler 中另建播放状态机。既有 SMTC/MPRIS 和鼠标操作继续共用 actor，不为本版无关重写原生媒体控制。
- 返回权威快照后立即更新现有进度、播放按钮、音量值和图标；键盘定位与现有拖动定位事务协调，不能让旧 pending 目标把进度拉回。
- 主窗口音量调整成功后，复用现有音量 Popover 显示滑条和百分比，约 1.2 秒后关闭；继续按键重置计时，不抢焦点，不自动关闭用户手动展开的音量控件。手动拖动期间保留滑块自身按键语义。
- 压缩窗口没有播放器底栏，使用既有通知组件呈现单条可替换的“音量 45%”与小型音量条反馈；其他播放控制也提供简短状态/位置反馈。连续按键更新同一反馈，不堆积通知，不新建可编辑播放器。
- 操作失败沿用本地化错误提示，不显示虚假的成功数值；错误反馈不能以播放快照误清掉文件任务的独立错误。补充中英文快捷键说明、按钮提示及适用的 `aria-keyshortcuts`；音量反馈不通过连续焦点移动或高频读屏播报实现。

## 实施顺序与文件范围

1. **文件打开回归**：在 `filesystem` / `media_import` 补“文件可读、父目录空/失败/缺少目标”的确定性 fixture，再实现目标文件保留、CUE 与警告语义；处理首次/二次打开的结果交付。
2. **原生文件选择与 URI 边界**：核查锁定插件/rfd feature、返回值及 portal 行为；接入 Linux 映射 adapter、所有选择入口与错误翻译；调整 Arch 依赖和许可证。
3. **键盘与反馈**：在播放 actor 增加最小相对操作与测试；在 playback feature / shared bridge 维护统一窗口内控制，接入主/压缩窗口与现有音量、定位 UI。
4. **原生验收与版本交付准备**：双平台回归、NFS 实机与 UI 验收后再记录通过项。实施阶段统一更新 npm/Cargo 清单与锁文件、Tauri 配置、Arch 版本及 `docs/releases/0.3.0-beta.1.md`；已统一版本字段并新增发行说明，尚未发布。

## 验收门禁

| 层次 | 必须验证 |
| --- | --- |
| Rust 文件入口 | 同目录正常/空/不可读/缺少目标、所选文件不可读/损坏；中文/空格/转义路径；CUE 相对区间；扫描降级不丢目标、不重复项目；新旧入口一致 |
| URI / portal | 本地路径、`file://`、原始 `nfs://` 映射、未知协议、服务缺失/超时/权限不足；取消与失败分开；单/多文件和文件夹；Windows 路径不回归 |
| 播放 actor | 空闲/播放/暂停的切换；相对定位上下界与 CUE；35% ±10 个百分点、0/100 截断；快速连续命令与鼠标/平台控制混用不读旧状态 |
| 前端键盘 | 焦点/失焦/隐藏、主/压缩窗口切换；输入/IME、按钮/滑块/曲目行/菜单/弹窗排除；空格重复抑制；方向键重复有界；挂载清理；音量成功与失败反馈 |
| KDE 原生 | 真实 KDE chooser 中看到并选择 OMV 位置，返回值可由 Rust 读取；从 Dolphin 冷启动与已运行实例打开；本机实际 NFS 文件连续播放、暂停、定位、切歌、中文/空格路径；断线/权限失败可诊断且本地音频仍可恢复 |
| UI / Windows | 主窗口四个规定尺寸、压缩 720×500、明暗与中英代表组合；音量条/百分比可见且不移焦、不溢出；Windows 原生文件选择与物理键盘专项通过 |

- 本机按变更范围运行 Node、TypeScript/build、Rust、fmt/Clippy；feature/依赖变化核查 Cargo tree、许可证与真实 Linux Release 构建。实际运行结果单独记录，不用设计清单冒充通过项。
- 快捷键冲突与 actor 逻辑用自动测试覆盖；portal/KIO/NFS 的真实结果由隔离原生测试补足，浏览器截图和 CI 容器不能替代。
- 现有数据、播放列表与音频不能丢失；没有数据库 schema 变更计划。压缩模块只更换文件选择入口及接收播放控制，不放宽远端输出不覆盖/原子提交安全检查。
- beta 升级排序应满足 `alpha.4 < beta.1 < beta.2 < rc.1 < 0.3.0`；Arch 包版本为 `0.3.0beta1`、包名仍为 `resona`。PR 双平台 `PR validation` 通过并跟上 main 后才允许合并；main 仅执行既有签名 CD，发布单一 `v0.3.0-beta.1` pre-release。

## 范围与保留风险

- 本轮不增加全局快捷键、可定制按键、媒体库、自动连接网络盘、第二播放引擎、缓存下载或新 UI 架构。
- 语言跟随系统的人工反馈已复现：清除工具 LC_ALL 覆盖后仍英文，同机 WebKit 返回 `C` 而 GLib 为中文。按 ADR 0036 从原生接口读取系统界面语言，渲染前初始化，保留手动选择与可诊断回退；Windows 新增语言名/原生交互验收，不能仅凭环境变量或浏览器预览宣布原生界面通过。
- 标准文件选择器能访问网络位置，与播放器能读取/定位该文件是两个独立门禁。临时映射失效、真实网络中断恢复及已有硬件/动画开放门禁必须如实记录，不能因进入 beta 自动标为通过。
- 后续所有者已授权实施、测试与推送 dev。草稿 PR 用于双平台 CI 与后续评审；Windows 测试完成前不合并，不创建 tag/Release。
