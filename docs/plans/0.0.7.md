# 0.0.7 持久化播放列表与媒体库基础

- 状态：Completed
- 前置版本：0.0.6 Windows 媒体会话与硬件控制
- 所属阶段：P3 本地媒体库
- 完成日期：2026-07-18

## 阶段目标

建立 Rust 权威的持久化数据基础，完成用户播放列表和最近播放的最小闭环，并为受管理文件夹与媒体记录预留可迁移 schema。扫描和元数据索引拆分到 0.0.8，不做全盘扫描、在线元数据或 UI 视觉重构。

## 实际完成

- SQLite 数据库位于 Tauri `app_data_dir()/resona.sqlite3`，通过 `PRAGMA user_version` 执行 schema version 1 migration。
- `rusqlite` bundled adapter 已实现播放列表、播放列表项目、最近播放、受管理文件夹和媒体记录表；数据库行不穿透到 UI。
- Tauri commands 已覆盖列出/创建/重命名/删除播放列表、按位置添加项目、读取播放列表项目和读取最近播放。
- 播放文件、播放队列项目和下一曲命令会记录最近播放；相同路径去重并累计播放次数。
- 播放列表页可创建并保存当前队列、加载已保存列表到当前队列、删除已保存列表；最近播放页可直接重新播放历史文件。
- 已增加空、加载中和错误状态；未进行视觉重构，保留现有应用壳和主题/语言系统。
- 自动验证：Rust library tests 15 passed，真实 Windows 音频设备 tests 8 passed，Clippy、格式检查和前端 production build 通过。

## 延后项

- 自然结束自动切歌的最近播放 observer 尚未接入，下一阶段补齐播放事件桥接。
- 受管理文件夹的新增、扫描、取消和重试，以及 `lofty-rs` 元数据/封面索引尚未实现。
- 元数据编辑、歌词、转换、AAC/M4A、Linux 和 SMTC 浮层“未知应用”身份显示继续延后。

## 技术策略

- 先比较 `rusqlite` 与 `tauri-plugin-sql` 的依赖体积、线程模型、迁移能力、许可证和离线行为，再形成新的 ADR。
- 数据库连接和迁移只存在于 Rust persistence adapter；React 不直接执行 SQL，也不接触数据库行类型。
- 所有 schema 通过版本化 migration 创建；应用启动时迁移失败必须进入可诊断错误状态，不静默创建不完整数据库。
- 扫描和索引使用后台任务，批量提交事务；单文件解析失败只标记该文件，不阻断同批其他文件。
- `PlaybackQueue`、`Playlist`、`RecentPlay` 和 `MediaRecord` 保持不同领域对象，不能用播放队列代替持久化播放列表。

## 实施范围

### 1. 数据模型与迁移

- 数据库位置、首次创建、版本表和失败恢复策略。
- `playlists`、`playlist_items`、`recent_plays`、`managed_folders`、`media_records` 最小 schema。
- 稳定 ID、排序字段、缺失文件状态和更新时间字段。
- 迁移、重复执行、回滚前置检查和临时数据库测试。

### 2. 用户播放列表

- 创建、重命名、删除播放列表。
- 按位置添加、删除和重排曲目引用。
- 从持久化播放列表生成当前 `PlaybackQueue` 快照。
- 保留当前播放项 ID 和播放位置，不让数据库操作重建输出设备。

### 3. 最近播放

- 播放开始、自然结束和手动停止事件记录。
- 最近播放去重、排序和保留数量策略。
- 文件删除或移动后保留可诊断的缺失状态，不静默丢失历史。

### 4. 文件夹与媒体索引

- 添加、移除和重新扫描受管理文件夹。
- 首次扫描与增量扫描的任务状态、取消和错误摘要。
- 首版只扫描直属目录和已明确支持的 MP3/WAV/FLAC；递归扫描单独评估。
- 使用 `lofty-rs` 只读提取标题、艺术家、专辑、时长和封面引用；不实现标签写入。

### 5. 前端功能接入

- 播放列表页显示真实持久化列表和空/加载/错误状态。
- 最近播放页显示真实历史。
- 设置或工具入口增加受管理文件夹配置。
- UI 只增加完成上述流程所需的控件，不进入间距、颜色、图标和动画打磨。

## 明确不包含

- 元数据编辑和封面写入。
- LRC 歌词解析、桌面歌词窗口和歌词锁定穿透。
- FFmpeg 转换、WAV → FLAC 和转换队列。
- AAC/M4A 扩展支持。
- 全盘扫描、实时文件监控和在线元数据。
- Linux 实现和验证。
- 0.0.5 已有 UI 的视觉重构；只修复功能阻塞、无障碍或布局回归。

## 验收标准

1. 新安装、重复启动和迁移升级都能创建或升级数据库，失败有明确错误。
2. 创建播放列表、添加/删除/排序曲目、关闭重启后数据保持一致。
3. 从持久化列表播放不改变现有 Rodio 输出生命周期和当前播放位置契约。
4. 最近播放能够记录、去重、排序，并正确显示缺失文件。
5. 受管理文件夹扫描在部分文件损坏时继续完成其他文件，支持取消和重试。
6. MP3/WAV/FLAC fixture 的元数据读取结果稳定，坏标签不污染其他记录。
7. Rust migration、persistence、scan、metadata adapter 有自动测试；前端 build、Clippy、许可证检查和 Release 构建通过。
8. 常用桌面尺寸、窄屏、浅色/深色和中英文下新功能无溢出或状态混乱；不要求完成视觉微调。

## 风险与决策点

- SQLite crate 的 bundled/native 选择会影响构建时间、体积和发布许可，必须在实现前形成 ADR。
- 文件路径可能失效、大小写规则和跨盘移动需要稳定的媒体记录匹配策略。
- `lofty-rs` 的标签兼容性和封面读取成本需要用固定 fixture 验证，不在 UI 层补解析逻辑。
- 数据库迁移和扫描任务属于共享基础设施，测试覆盖优先级高于页面细节。
