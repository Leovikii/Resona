# 0.2.1 UI 方案（已接受）

日期：2026-10-19。所有者已同意本方案并授权实现。本文保留审阅时的现状依据与取舍；当前实现与验证结果见[版本计划](0.2.1.md)。

## 现状核对

- `App.tsx` 的关闭询问已有“隐藏到托盘 / 退出应用”两个按钮，另有长正文和“不再询问，将本次选择设为默认”开关。退出若遇到扫描/压缩，还会进入独立任务确认。
- `compressionRootExpansion.ts` 按 `scanId` 仅展开首次出现的顶层根目录，尊重后续手动收起；子目录不跟随任务展开。用户看到文件树折叠可能是活动文件藏在子目录，不能把它记成“代码中所有根目录始终折叠”。若实机连根目录也未展开，实施时另查扫描快照与根节点时序。
- `AudioCompressionApp.tsx` 的文件行已有百分比与进度底色，汇总栏只有文本；每个展开目录先渲染 200 个子项，之后手动“显示更多”。主窗口工具入口已有简单平均进度条，但失败项和终态口径尚未统一。
- Rust 快照提供 `taskId`、项目状态、`progress`、体积和错误；`completed` 是已结束项数，包含失败和取消，不能作为成功数。转换轮询现为 300 ms，扫描为 250 ms，隐藏时暂停。

## 关闭询问：推荐精简文案，保留两个直接动作

| 元素 | 中文提案 | English |
| --- | --- | --- |
| 标题 | 关闭 Resona？ | Close Resona? |
| 正文 | 隐藏到托盘可继续播放。 | Hide to tray to keep playback running. |
| 记住选择 | 记住选择 | Remember my choice |
| 普通按钮 | 隐藏到托盘 | Hide to tray |
| 退出按钮 | 退出 | Exit |
| 活动任务标题 | 退出并取消任务？ | Exit and cancel tasks? |
| 活动任务正文 | 正在扫描或压缩。退出将取消任务，已完成文件保留。 | Scanning or compression is active. Exiting cancels tasks; completed files are kept. |
| 安全返回 / 确认退出 | 返回 / 取消任务并退出 | Go back / Cancel tasks and exit |

保留标题栏关闭和 Esc 返回，点击遮罩不执行动作；默认焦点放在“隐藏到托盘”或安全返回，Enter 不默认触发退出。“记住选择”初始不选，沿用 Rust 保存偏好，设置页仍可改回“每次询问”。错误留在当前弹窗，提交中防止重复点击；失败后允许重试。

当前“询问 → 退出 → 活动任务确认”最多两步。推荐本版保留这条保护链，只缩短文字；无活动任务时只需一次选择。合并弹窗需要改变任务快照、确认竞态及偏好提交时机，收益不足以纳入此次文案优化。注意现有 Rust 会先保存勾选的偏好，再进入活动任务确认；在第二步返回不会撤销已记住的选择，本版保持该语义。

## 压缩目录：推荐进入运行时展开，不持续追踪滚动

| 方案 | 评价 |
| --- | --- |
| 开始时展开全部目录 | 易实现，但大树噪声高，也违背增量展开目标 |
| 展开活动项祖先 + 固定总进度 | **推荐**；展示工作位置，同时保留手动浏览权 |
| 持续自动滚动到当前项 | 并行时目标争抢，容易打断阅读错误和结果，不建议 |

具体规则：

- 开始前沿用现有顶层默认展开，子目录默认收起。项目首次被快照观察为 `running` 时，一次性展开它在扫描树中的全部祖先；同时运行的 1–4 项取祖先并集。
- 自动展开只增加目录，不自动收起已展开目录，不改变项目顺序、选中或键盘焦点，也不滚动。短任务若在两次轮询之间已完成，不追溯展开全部完成项。
- 用户手动收起的目录，在本 `taskId` 内压过之后的自动展开，包含随后进入该目录的新任务；手动展开后恢复其后代的自动展开资格。已观察项目记录与手动收起集合只保存在当前窗口会话。
- 新 `taskId` 清除上批次自动处理/手动抑制记录，保留仍有效的手动展开；新 `scanId` 重置扫描树相关展开。窗口重开读取当前 Rust 快照，只为仍在运行的项目恢复活动分支；已结束批次不追溯展开。
- 批次结束保留现有展开以检查结果；失败不强制抢焦点或展开其他历史分支。
- 自动展开保证“目录打开”，不保证条目位于当前视口。仍沿用每目录 200 项增量显示；活动项在未渲染部分时，该目录显示“后续条目中有 N 项正在压缩”，可用现有“显示更多”查看，总进度始终可见。本版不自动挂载数千行。若必须一键定位任意深页项目，应单独确认有界分页方案。

## 总进度：固定汇总栏使用文件行同款底色

在“输入文件”汇总栏本体增加低对比度进度覆盖层，保留文字在上层；复用文件行视觉语言，不将整个窗口铺成进度背景，也不新增结果面板。百分比与状态不只靠颜色表达，固定栏随树滚动仍可见。

| 状态 | 推荐展示 |
| --- | --- |
| 未开始 / 扫描 | 保留输入数量/体积及原扫描进度，不显示虚构压缩百分比 |
| 运行 | `总体处理 42% · 已结束 3/12 · 正在压缩 2 项`，中性品牌底色 |
| 取消中 | `正在取消…`，显示当前处理进度，保留后端控制权 |
| 全部成功 | `已完成 12/12`，100% 成功底色，沿用成功项体积和节省统计 |
| 有失败 | `处理结束 · 成功 10 · 失败 2`，100% 处理进度及警示状态，保留逐项原因 |
| 已取消 | `已取消 · 成功 3 · 失败 1 · 取消 8`，不强制补满进度，不渲染成功底色 |

推荐按文件等权计算“总体处理进度”，避免暗示剩余时间：`completed/failed` 项贡献 1，`pending` 贡献 0，`running/cancelled` 使用 Rust 的 `[0,1] progress`；总和除以 `total`，空批次不显示百分比。失败项贡献 1 表示处理已结束，不表示成功。体积加权在短文件/大文件混合时更贴近数据量，但不等于耗时，本版先不引入第二套口径。

运行/取消中显示整数最多 99%，只有 Rust 确认全部处理结束才允许显示完成态；最终是否成功仍以批次状态及逐项结果判断。已取消使用快照投影，不伪造剩余项完成。成功体积/节省空间继续只取成功项。主窗口工具入口复用同一投影，避免两个窗口百分比不一致；不预测 ETA、不增加快照字段或轮询频率。

进度层不拦截鼠标，动画沿用短时宽度过渡并遵守减少动态效果。汇总最多保留两行，长路径省略且可查看完整内容；无障碍为总进度提供名称/当前值，状态变化使用低频提示，不能每 300 ms 播报。

## 审阅结论（2026-10-19 已接受）

建议本版接受：精简后的两动作关闭询问、保留活动任务确认链、活动分支自动展开且手动折叠优先、固定汇总底色与按文件等权的总体处理进度。

所有者已接受两处取舍：不持续自动滚动；超过 200 项时保留手动“显示更多”并用目录提示兜底。目录本体的聚合进度、自动收起已完成目录、一键定位任意深页、持久化“跟随任务”开关均暂缓；不影响此次固定总进度的可见性。
