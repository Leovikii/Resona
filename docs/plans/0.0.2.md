# 0.0.2 播放能力闭环

- 状态：Accepted
- 日期：2026-07-17
- 所属阶段：P0 收尾 + P1 播放技术验证

## 目标

在不扩张到正式播放器 UI、队列或设备管理的前提下，把 0.0.1 的“可以发声”推进为可自动回归、可定位、可调音量且覆盖首版三种必选格式的单曲播放核心。

## 推荐范围

### 1. 封板与质量基线

- 提交当前 0.0.1 工作区并创建 `v0.0.1` 标签。
- 建立 Windows CI：前端构建、Rust format、test 与 Clippy；需要音频设备的测试继续显式忽略。
- 生成当前 npm/Cargo 直接与传递依赖许可证清单，确认无运行时激活、许可证注入或 GPL-3.0-only 分发冲突。

### 2. 固定音频 fixture

- 在 `tests/fixtures/audio` 保存项目自行生成、可再分发的小型 WAV、FLAC、MP3 和损坏文件。
- 按格式语义覆盖以下矩阵，避免制造 MP3 96/192 kHz 或“MP3 位深”等无效组合：

| 格式 | 采样率 | 位深/编码模式 | 计划样本数 |
| --- | --- | --- | ---: |
| WAV 整数 PCM | 44.1/48/96/192 kHz | 16/24/32-bit | 12 |
| WAV 浮点 PCM | 44.1/48/96/192 kHz | 32-bit float | 4 |
| FLAC 整数 | 44.1/48/96/192 kHz | 16/24/32-bit | 12 |
| MP3 | 44.1/48 kHz | 128/320 kbps CBR、VBR | 6 |

- 另设空文件、截断文件、扩展名与内容不一致、单声道和较长定位样本。
- 自动测试覆盖完整矩阵；Windows 实机只抽检代表组合，避免人工重复劳动。
- 记录生成方式、校验值和期望时长，自动验证解码、时长、自然结束及错误恢复。

### 3. 单曲播放契约

- 为 Rodio 启用稳定版公开的 `mp3` feature，文件选择支持 MP3/WAV/FLAC。
- `PlaybackSnapshot` 增加毫秒级 `position`、`duration`、`volume` 与 `seekable`。
- `PlaybackEngine` 增加定位和音量命令；继续由 audio actor 串行执行。
- Tauri 边界返回稳定错误码与用户消息，不再只传递无结构字符串。
- 保持默认设备延迟打开，不实现第二套播放引擎。

Rodio 0.22.2 已直接提供 `Player::get_pos`、`Player::try_seek` 与 `Player::set_volume`，预计不需要新增音频依赖或自研时钟。

### 4. 最小验证界面

- 展示当前时间/总时长。
- 提供一个定位滑块和一个音量滑块。
- 保留当前文件选择与播放控制，不设计媒体库、导航或正式视觉系统。
- 继续使用组件局部状态；本范围不需要 Zustand、TanStack Virtual、Mantine Form、Combobox 或 factory skill。

## 明确不包含

- 播放队列、上一首/下一首、随机或循环模式
- Gapless 与混合采样率连续切歌
- 输出设备选择、蓝牙断开、休眠或默认设备变化恢复
- AAC/M4A、媒体库、元数据、歌词和格式转换
- Linux 实现或验证
- 安装包、自动更新或正式 UI 重构

## 验收标准

1. Windows 默认 WASAPI Shared 端点可播放固定 MP3、WAV、FLAC fixture 和真实文件。
2. 暂停/继续后进度连续，定位前后误差处于解码器合理粒度内，曲目结束状态准确。
3. 音量可在播放中调整，静音与恢复不重启曲目。
4. 损坏或不支持的文件返回稳定错误码；失败后仍可播放下一份有效文件。
5. WAV/FLAC 完成 44.1/48/96/192 kHz 与 16/24/32-bit 矩阵验证；WAV 额外区分 32-bit integer/float，MP3 覆盖 44.1/48 kHz 的 CBR/VBR 代表码率。
6. `npm run build`、Rust format/test/Clippy、Tauri release build 和 Windows CI 全部通过。
7. 文档、版本号、依赖清单和验证记录同步更新。

## 后续顺序

- 0.0.3：队列、混合采样率连续播放、Gapless 与切歌错误隔离。
- 0.0.4：输出设备枚举、选择、默认设备变化、蓝牙断开和恢复。
- P2：在 P1 播放契约稳定后建立正式应用壳与播放体验。

## 确认点

批准该计划意味着按上述范围开始开发 0.0.2，并先执行 0.0.1 封板提交与标签。任何增加队列、设备管理或正式 UI 的请求应进入后续版本，避免扩大本次技术验证。
