# 0.0.9 本地多格式歌词解析与播放同步

- 状态：Completed
- 前置版本：0.0.8 受管理文件夹与元数据索引
- 所属阶段：P4 歌词
- 目标平台：Windows；通用解析契约保留 Linux 兼容性，但不在本阶段验证 Linux
- 提案日期：2026-07-18
- 实施完成日期：2026-07-18
- 限定名匹配修订日期：2026-07-19
- 项目所有者验收日期：2026-07-19

## 阶段目标

完成本地歌词的第一个可用闭环：播放曲目时自动发现同目录同名 LRC、SRT 或 WebVTT，由 Rust 解析并根据权威播放时间推进当前歌词行，在既有“正在播放”页面歌词区域显示和同步滚动。

本阶段不改变播放列表、受管理文件夹或媒体库交互，也不创建第二份播放时间状态。

## 实施范围

### 歌词领域与文件适配

- 新增 Rust `LyricsService`、Resona 自有 `LyricsDocument`/`LyricsLine`/`LyricsSnapshot` 契约和稳定错误码。
- 自动发现与音频同目录、共享基础 stem 的 `.lrc`、`.srt` 或 `.vtt` 文件；支持 `song.vtt`、`song.flac.vtt`、`song.wav.vtt`、`song.zh-CN.vtt` 等限定名。优先级固定为 LRC、SRT、WebVTT，同格式内精确 stem 优先，不递归搜索，不访问网络。
- 解析常见 `[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]`、同一文本多时间戳、`[offset:]` 以及 `ti`/`ar`/`al` 等元信息标签。
- 使用 `subtp` 解析 SRT 和 WebVTT cue、起止时间、多行文本及 WebVTT cue settings；统一为 Resona 歌词行，不暴露字幕库类型。
- 对时间相同、乱序标签、空行和缺失文本采用确定性归一化；单个坏行可诊断且不污染其他合法行。
- 使用 `encoding_rs` 支持 UTF-8、UTF-8 BOM、UTF-16 BOM，并在 UTF-8 无效时以 GBK 解码常见 Windows 中文文件。无法可靠解码时返回明确错误，不显示乱码。
- 文件读取、编码和解析错误终止在歌词 adapter/service 内，不向 UI 暴露第三方类型。

### 播放同步

- 歌词服务消费现有权威播放快照或内部播放时钟，不让 React 自行维护竞争时间轴。
- 切歌、停止、自然结束、暂停、继续和 seek 后正确重置或重新定位当前歌词行。
- 复用现有 750 ms 低频播放状态轮询，不增加逐音频 tick 事件；歌词全文只在 revision 变化时跨 WebView IPC，普通轮询只返回状态和当前行索引。
- 没有 LRC、LRC 为空和解析失败使用不同状态，且都不阻塞播放。

### 最小前端闭环

- 复用既有 `NowPlayingView` 右侧歌词区域，不新增导航入口或改变应用壳布局。
- 显示当前行、相邻歌词和明确的无歌词/加载/错误状态。
- 当前行变化时使用低成本滚动动画；遵守减少动态效果偏好，并避免整棵歌词列表重渲染。
- 保持底部播放器稳定挂载；进入或退出“正在播放”视图不改变歌词与播放状态。
- 覆盖中文/英文界面、浅色/深色、窄屏、长歌词和空状态。

## 自动验证

- LRC fixture 覆盖常见时间戳精度、多时间戳、offset、元信息、乱序、重复时间、空文本和坏行。
- SRT/WebVTT fixture 覆盖多行 cue、间隔、重叠、WebVTT header/settings/markup 和非法时间轴。
- 文件发现覆盖无歌词、大小写扩展名、音频格式/语种限定名、精确名优先、前缀碰撞和曲目切换。
- 同步覆盖播放、暂停/继续、seek、上一曲/下一曲、自然结束和停止。
- 验证同一 revision 不重复返回歌词全文，且不形成额外高频 IPC。
- 现有播放、队列、播放列表、文件夹扫描和最近播放回归测试。
- 前端 build、Rust format/test/Clippy、许可证检查和 Windows Release 构建。
- 常用桌面尺寸、窄屏、浅色/深色及中文/英文视觉验证。

## 验收标准

1. 同名或带格式/语种限定名的本地 LRC、SRT、WebVTT 能随 MP3/WAV/FLAC 自动加载，并在正在播放页按播放位置同步；例如 `1.wav.vtt` 可匹配 `1.wav` 或 `1.flac`。
2. 暂停、继续、seek 和切歌后当前歌词行正确，无持续漂移或旧歌词残留。
3. 无歌词、坏歌词或不支持编码不影响音频播放，并给出可区分状态。
4. 歌词同步不引入高频 IPC、音频线程文件读取或明显 UI 卡顿。
5. 播放列表和受管理文件夹交互没有变化。

## 明确不包含

- 独立桌面歌词窗口、置顶、透明、锁定穿透、拖动和多显示器状态。
- 在线歌词搜索、下载、歌词编辑、翻译和逐字歌词。
- 播放列表与受管理文件夹交互调整。
- 媒体库查询页面、专辑/艺术家聚合和封面缓存。
- 元数据写入、转换、AAC/M4A 和 Linux 实现。

## 验收结果

- 项目所有者确认 LRC、SRT、WebVTT 的发现、显示和播放同步正常。
- 项目所有者确认 `1.wav.vtt` 等带音频格式或语种限定名的歌词匹配正常。
- 播放列表、文件夹浏览、受管理文件夹、最近播放和既有播放功能未发现回归。

## 后续顺序建议

继续 P4 的独立桌面歌词窗口；媒体库与播放列表交互等项目所有者给出完整需求后统一设计，复用现有持久化、扫描和元数据基础。
