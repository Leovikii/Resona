# 0.3.0-alpha.3：Arch 安装与应用内更新

- 状态：Development Complete；所有者已批准实施，双平台 CI 与公开发布待验证。
- 日期：2026-10-28
- 代码基线：现有 `0.3.0-alpha.2`；下一发布版本为 `0.3.0-alpha.3`，tag 为 `v0.3.0-alpha.3`。
- 参考：[alpha.3 聊天](codex://threads/01a18035-14a0-7d43-9c26-2933012c9548) 中的 GitHub 原生包安装、Tauri 下载验签与 Pacman 更新方案。
- 本轮约束：界面样式和 Windows 沿用 Resona 当前设计，不移植参考项目的 WinUI 3 改版或按钮进度设计。

## 目标与范围

本版确定一条可维护的 Arch 安装、更新和卸载路径：首次从 GitHub Releases 下载 `.pkg.tar.zst` 并用 Pacman 安装；以后由应用发现新版本、下载验签，再经系统授权交给 Pacman 安装。Pacman 继续拥有系统文件和依赖管理权，应用不自行覆盖 `/usr`。

Linux 仍只支持 Arch 系 x86_64 / KDE Plasma / 原生 Wayland。删除 AUR 发布和 yay/paru 引导；不增加自建软件源、AppImage、deb/rpm、特权常驻服务或第二套下载器。FFmpeg 继续使用系统包，播放、歌词、主题和窗口行为沿用 alpha.2。

Windows 保持用户级 NSIS、Tauri updater、启动检查、预览版开关和现有更新弹窗。除统一版本、清单兼容及必要回归外，不扩展 Windows 功能、不改变其安装体验。

## 首次安装与卸载

| 操作 | Windows | Arch / CachyOS |
| --- | --- | --- |
| 首次获取 | GitHub Release 的 NSIS `.exe` | 同一 Release 的原生 `.pkg.tar.zst` |
| 安装 | 沿用现有安装器 | `sudo pacman -U ./resona-preview-bin-0.3.0alpha3-1-x86_64.pkg.tar.zst` |
| 后续更新 | 现有 Tauri 流程 | 应用下载验签、安装预览、Polkit 授权、Pacman 安装 |
| 卸载 | 沿用现有卸载器 | `sudo pacman -R resona-preview-bin`，保留用户数据与音频 |

README 提供具体版本下载链接、本地包安装命令及 SHA-256 核验说明；可补充下载、核验和安装串联的一行命令，不执行远程 shell 安装脚本。图形包安装器只作为系统已有能力，不作为必需依赖。

不把 `pacman -U URL` 作为默认入口：远程包与本地包的签名策略可能不同，Tauri/Minisign 签名也不是 Pacman 的 OpenPGP 签名。alpha 不能依赖 GitHub `releases/latest` 找到预发行版，下载链接必须定位具体 tag。首次安装遵循系统 `LocalFileSigLevel`，不修改系统签名策略；要求 OpenPGP 签名的自定义系统策略本版不绕过。

GTK、WebKitGTK、gtk-layer-shell 等依赖由 PKGBUILD 准确声明并交给 Pacman 解析。系统数据库过期或依赖冲突时明确失败，不自动执行 `pacman -Sy`、全系统升级或关闭依赖检查。

## 应用内更新流程

复用现有 `ApplicationUpdateService` 的 Releases 分页、SemVer、预览偏好、single-flight、超时和签名清单校验。Linux 开启发现能力及首帧后的每进程一次静默检查；主动检查失败在原位置显示，后台检查失败不打扰播放。没有稳定版时正常返回无候选；API 限流或网络失败不能显示为“已经最新”。

Rust 继续拥有候选和操作阶段，前端仅渲染快照和发送意图。新增 Pacman 安装行为通过 `platform` adapter 隔离，不在通用服务或 React 中散布命令行和平台判断。

### 下载与准备

1. 用户在现有更新弹窗点击下载后立即进入忙碌状态，复用当前进度条和取消入口；已知总量显示实际进度，未知总量显示等待状态，下载 100% 不代表安装完成。
2. 当前锁定的 `tauri-plugin-updater =2.10.1` 已提供独立 `download()`，返回验签后的字节。Linux 复用此 API，只替换后续安装动作，不调用插件的 Linux `install()`。先以原生包 fixture 验证完整链路，不升级插件来实现本版。
3. 将包存入本事务独占、权限受限的临时目录；使用成熟临时目录库，优先复用已锁定版本。路径由后端生成，拒绝外部路径和符号链接，不使用固定 `/tmp/resona.pkg.tar.zst`。安装前复核落盘内容与已验证字节一致，取消/失败只清理本事务文件。
4. 核对包名 `resona-preview-bin` / `resona-bin`、x86_64、目标 Arch 版本及 Release/tag，禁止将其他包交给安装器。保留当前包名，避免升级 alpha.2 时出现不必要的替换/冲突。
5. 用 Pacman 的只读查询取得目标版本及依赖事务，在现有弹窗中给出精简预览。开发版、解压运行或程序不归系统 Resona 包所有时拒绝应用内安装，提供正式包安装入口。

### 系统授权与安装

1. 用户确认具体安装预览后才调用系统授权；不在检查或下载时提权。使用固定 `/usr/bin/pkexec`、`/usr/bin/pacman` 和独立参数，不拼 shell、不新增免密 Polkit 规则。
2. 预期执行形态为 `pkexec --disable-internal-agent /usr/bin/pacman -U --noconfirm -- <已核验的绝对包路径>`。`--noconfirm` 只用于已明确确认的事务；若预览需要移除其他包、交互式解决冲突或扩大操作范围，则停止并提示用户处理，不自动替用户选择。
3. 安装前复核候选、预览偏好、本地安装版本及只读事务；变化时重新预览。只读预览不持有 Pacman 数据库锁，最终依赖/冲突判断仍由实际 Pacman 执行，不宣称跨进程事务原子性。
4. 安装期间禁止重复操作和完整退出；与现有生命周期服务协调，活动音频转换必须先完成或由用户明确取消，不在文件任务运行中替换程序。下载取消仍可用，进入系统安装后不再提供强杀安装的“取消”。
5. 授权取消、缺少授权代理、数据库锁、依赖/文件冲突和安装失败分别报告。安装事务不受下载超时强杀，不删除 Pacman 的锁、不清系统缓存、不自行回滚系统包。
6. 退出码成功后查询包数据库确认目标版本，再显示“更新完成，请重新启动”。保留旧进程版本显示，由用户退出后重新打开；本版不增加重启 helper。Pacman 完成后才释放临时包。

Polkit/依赖可用性须纳入安装检查，不能假定所有 Arch 会话都有图形授权代理。系统 `LocalFileSigLevel` 继续生效；`.tauri.sig` 不能冒充 OpenPGP 签名，也不能通过命令参数关闭系统签名校验。

## 界面保留范围

沿用当前 Mantine 弹窗、字体、颜色、材质、按钮与独立进度条，不引入参考项目的 WinUI 3 规范、按钮背景进度条或新设置页。Linux 将“包管理器更新说明”替换为现有检查/更新流程，只补安装预览、授权/安装状态和重启结果；不叠加多层确认框。

文案只保留当前阶段、必要的事务内容和实际错误。下载、校验及安装阶段不能混成一个不变的“安装中”；沿用当前 UI 结构，通过类型化状态补足 Linux 反馈。Windows 视觉和操作保持现状，只有共享代码兼容和错误修复需要变更时才调整。

## 打包与 Actions

- 在 `packaging/arch/` 维护供 CI 使用的 PKGBUILD，封装已编译的安装树；用户无需 makepkg。保留预览/稳定包名、桌面入口、图标、文件关联、系统依赖及许可证。
- 删除 `scripts/sync-aur.sh`、`aur-sync` job、AUR 参数与专属测试、公开 PKGBUILD/SRCINFO 配方和额外 Linux tar 载荷；仍有实际用途的构建输入留在内部。
- 保留现有 `latest.json` 及其签名，为清单增加 `linux-x86_64` 平台资产；将当前“恰好一个 Windows 平台”的校验改成双平台契约。不为本版替换 Windows 的签名清单格式或删除现有身份绑定。
- Linux 原生包使用现有 Tauri 签名工具与发布密钥签名；独立签名文件命名为 `<package>.tauri.sig`，避免 Pacman 把相邻 `.sig` 当成 OpenPGP 包签名。Windows `.exe.sig` 保持原样。
- 发布用户资产为 Windows 安装包及签名、Arch 包及签名、`latest.json` 及签名、`SHA256SUMS`。继续保留现有源码归档和许可证交付，不照搬参考项目的固定六文件限制；诊断构建信息优先随程序内嵌，构建清单可留 Actions artifact。
- 继续使用 `main-merge-delivery.yml` 和双平台 `PR validation`。Windows/Arch 同一 SHA 构建、验签、校验资产后上传草稿，全部成功才公开为 pre-release；不照搬参考项目的“先公开、最后上传 manifest”。失败清理/重试仅作用于草稿，已公开资产不可覆盖。
- 不新增手动发布旁路，不在本机上传发行包。远端凭据/Environment 清理以实际核对为准，不把未配置的 AUR 当成已发布渠道。

必要验证：

- 共享更新：稳定/预览选择、仅有 alpha、分页/限流、缺失/篡改清单、平台匹配、候选失效、重复操作和真实下载进度。
- Arch 包：makepkg/vercmp、依赖元数据、干净容器首次安装、同包名旧/新版本升级、桌面入口/文件关联和卸载。隔离根若用 `-dd`/`--noscriptlet`，只证明载荷和包数据库，不代替依赖安装及 hooks 验证；产品命令不得沿用这些测试参数。
- 安装边界：固定命令/参数、临时目录、包身份、预览变化、授权取消/缺代理、数据库锁、依赖/文件冲突、事务失败及安装后版本不符。不把模拟授权当成真实 Polkit 通过。
- Windows：现有 Rust 测试、签名清单和 updater 回归、NSIS 构建；有隔离 Windows 环境时做真实跨版本覆盖、取消、卸载和单实例验证。
- UI：沿用 `1080×700`、`760×520`、`420×720`、`360×600` 的代表组合，覆盖明暗、中英、键盘和缩放；重点检查长依赖列表不遮住操作区、等待状态及错误/重启提示。原生材质不靠浏览器宣布通过。
- 质量：按影响运行 Node/Rust 测试、前端 build、fmt、Clippy、许可证检查、actionlint 和 `git diff --check`；不重跑无变化的完整播放矩阵。

当前主机是 Windows；Linux 编译、打包和可自动化安装由 Arch CI/隔离环境覆盖。真实 KDE Wayland、Polkit 授权、依赖拉取及更新后桌面重启需 Linux 实机或 VM，不能用 Windows 模拟结果替代，也不能在没有证据时标记为通过。
