# 0.0.11 Windows 应用生命周期与桌面歌词交互闭环

- 状态：Completed
- 前置版本：0.0.10 Windows 桌面歌词窗口技术原型
- 架构决定：[ADR 0013](../decisions/0013-windows-lifetime-and-desktop-lyrics-controls.md)
- 所属阶段：P4 歌词
- 目标平台：Windows；不实现或验证 Linux
- 提案日期：2026-07-19
- 接受日期：2026-07-19

## 背景

0.0.10 已由项目所有者确认桌面歌词显示、同步、拖动、整窗穿透和原生解锁按钮基本功能正常，证明双窗口方案可行。同时暴露三个产品化缺口：关闭主窗口后歌词与播放继续存活；运行时入口错误地放在设置页；锁定后的原生解锁按钮常驻显示而不是只在鼠标进入热点后出现。

任务管理器中的多个进程不等于多套 Resona 播放核心。Resona 仍只有一个 Rust 应用进程中的一份 `RodioPlaybackEngine`、队列和歌词服务；WebView2 按浏览器架构创建 renderer/GPU/utility 子进程。真正需要修复的是窗口和应用生命周期没有显式所有权，以及隐藏后的歌词 WebView 仍可能保留 renderer 与 750 ms 轮询。

## 阶段目标

在继续扩展其他功能前，完成 Windows 应用退出、单实例、桌面歌词运行时入口、窗口内最小控件和原生解锁热点显隐闭环。该阶段只解决已确认的结构性问题，不提前打磨最终字体、配色、窗口持久化或一般主界面 UI。

## 范围

### 1. 应用与窗口生命周期

- 当前 Windows 首版不提供系统托盘或关闭后后台播放。主窗口是应用生命周期所有者；用户关闭主窗口必须退出整个应用。
- 退出顺序由 Rust 应用层统一协调：恢复歌词窗口鼠标交互、隐藏并销毁原生辅助窗口和歌词 WebView、停止播放并释放音频输出，然后退出 Tauri 事件循环。
- 桌面歌词窗口是辅助窗口，不得独立维持应用生命周期；关闭主窗口后不得残留歌词窗口、辅助 HWND、播放声音或 Resona 进程。
- 隐藏桌面歌词后停止该窗口的 750 ms 快照轮询，并释放不再需要的歌词 WebView/原生辅助窗口资源；再次显示时按需重建。优先选择清楚的生命周期，而不是为偶发开关保留隐藏 renderer。
- 使用 Tauri 官方单实例插件或等价官方能力，防止用户重复启动形成两套真正独立的 Resona 播放核心。第二次启动只激活已有主窗口；文件参数转发留到文件关联阶段，当前不得丢失或覆盖正在播放状态。
- 不引入“关闭到托盘”隐式行为。未来若加入托盘，必须以新 ADR 明确关闭、隐藏和退出语义。

### 2. 主窗口运行时入口

- “显示/隐藏桌面歌词”是播放操作，主入口移动到底部播放控制区，使用歌词图标按钮和 tooltip；设置页不再承载运行时开关。
- 没有当前曲目时入口禁用；有当前曲目时按钮明确显示隐藏/显示状态，忙碌和失败状态可恢复且不改变播放。
- 桌面歌词窗口顶部控件按“上一曲、播放/暂停、下一曲 | 设置、锁定/解锁、关闭”排列；上一曲和下一曲都复用 Rust 播放队列语义。
- 主窗口始终保留锁定状态下的恢复路径。锁定/解锁可以使用播放区相邻图标或该按钮的紧凑菜单，最终选择以不挤压窄窗口播放控制为准，但不能退回设置页。
- 设置按钮打开主界面设置页；设置页提供歌词字号、歌词颜色和窗口背景透明度，偏好在两个 WebView 间共享。
- 继续遵守 Mantine 边界：播放区组合位于 `src/app`，领域状态与 command 仍由 `features/lyrics` 和类型化 bridge 提供。

### 3. 歌词窗口最小控件

- 解锁状态下，歌词上方显示低干扰控制条，至少包含“锁定”和“隐藏桌面歌词”；锁定后控制条隐藏，避免穿透窗口留下不可用控件。
- 拖动区域与按钮命中区域分离，点击控件不得触发窗口拖动。
- 锁定后 WebView 继续整窗穿透，WebView 控制条完全不可见；只保留原生解锁热点。
- 本阶段只实现必要图标、tooltip/可访问名称和中英文文案，不实现字体、颜色、描边、逐字歌词或皮肤设置。

### 4. 原生解锁热点显隐

- 原生 helper HWND 在锁定期间保持存在且可命中，但空闲时使用近透明 alpha=1；鼠标进入热点后显示解锁图标，离开后隐藏。淡入淡出时长不作为本阶段验收条件。
- 优先使用 `WS_EX_LAYERED`、窗口 alpha 和 Win32 mouse/timer 消息实现；动画只在短暂过渡期间运行，不增加全局 hook、持续鼠标轮询或 WebView。
- 必须验证近透明状态能稳定接收首次 `WM_MOUSEMOVE`，且不会激活后方或 Resona 窗口。完全透明 alpha=0 在部分 Windows 环境下可能跳过命中，不作为实现条件；不使用全局输入监听补偿。
- helper 点击仍遵守“先恢复歌词 WebView 交互，再隐藏 helper”的顺序。

### 5. 歌词无活动行定位

- Rust `LyricsService` 的 `active_line_index` 在时间轴空白区必须保持 `None`，不将其转换为第一行。
- 桌面歌词在无活动行时清空当前/下一行显示，下一次进入有效 cue 时重新使用权威索引；拖动进度经过空白区不得复用第一行或旧行。

## 不包含

- 窗口位置/尺寸持久化、启动自动恢复、多显示器拓扑修正。
- 最终桌面歌词视觉、字体和主题偏好。
- 系统托盘、关闭到托盘、开机启动、文件关联和安装包。
- 播放列表、受管理文件夹交互和一般 UI 微调。
- 在线歌词、翻译、逐字歌词和歌词编辑。
- Linux/Wayland 实现或验证。

## 自动验证

- Rust 生命周期状态机覆盖主窗口关闭、歌词显示/隐藏、锁定退出、重复退出和部分资源创建失败。
- 验证隐藏歌词后前端轮询停止，重新显示只创建一组窗口资源，不重复创建播放服务。
- 验证第二实例不会创建第二播放核心，并能请求激活已有主窗口。
- 前端构建验证播放区入口、禁用/忙碌/错误状态、中英文和窄窗口不溢出。
- 歌词回归覆盖 LRC/SRT/WebVTT 时间轴：第一条开始前 `active_line_index == None` 且不提前显示第一行；第一条开始后在下一条开始前持续保留最近一行。
- 普通 Rust tests、真实默认音频设备 tests、format、Clippy、许可证报告和 Tauri Release 构建通过。

## 项目所有者 Windows 验收

1. 正在播放时可从底部播放区显示/隐藏桌面歌词；设置页不再出现运行时开关。
2. 解锁歌词窗口上方显示完整控制条，控件点击不会触发窗口拖动。
3. 锁定后解锁按钮空闲不可见，鼠标进入原位置后显示，点击立即解锁，离开后再次隐藏。
4. 锁定区域外仍正常穿透；helper 不抢焦点、不进入任务栏。
5. 关闭主窗口后播放停止，所有 Resona 窗口和进程退出。
6. 连续启动两次 Resona 时只保留一个应用实例和一份播放状态。

## 成功标准

- 主窗口关闭语义明确且无残留播放、窗口或进程。
- 桌面歌词运行时入口位于播放控制区，窗口内存在可用的最小锁定/隐藏控件。
- 原生解锁按钮只在热点 hover 时可见，显隐不依赖全局输入监听。
- 隐藏歌词不会继续轮询或永久保留额外歌词 WebView 资源。
- 桌面歌词控件顺序稳定，设置偏好能在主界面和桌面歌词窗口间生效。
- 既有播放、SMTC、歌词解析、播放列表和文件夹基础没有回归。

项目所有者确认本计划后方可开始实现。

## 实现与自动验证结果

- 已实现主窗口关闭时调用 Tauri 应用退出、Tauri 官方单实例插件和隐藏歌词时销毁歌词 WebView/helper 资源。
- 已实现桌面歌词顶部“上一曲、播放/暂停、下一曲 | 设置、锁定/解锁、关闭”控件；设置按钮通过 Rust command 激活主窗口并切换设置页。
- 已实现主界面歌词字号 16-64 px、颜色和背景透明度偏好，并通过共享本地存储在主窗口与桌面歌词 WebView 间同步。
- 已实现原生 helper 锁定空闲 alpha=1 的近透明命中、鼠标进入后显示解锁图标；透明热点的首次命中仍需项目所有者实机确认。
- 已修复桌面歌词在时间轴无活动行时错误显示第一行的问题；无活动行现在清空当前/下一行。
- 版本更新至 0.0.11；`npm run build`、`npm run licenses`、Rust format、26 个普通测试、8 个真实设备测试、Clippy、`git diff --check` 和 Tauri Release 构建通过。
- 真实 Windows 的透明 helper 首次命中、主窗口退出、单实例、控件交互和偏好同步已由项目所有者验收通过；最终视觉、位置持久化和多显示器恢复后置。
