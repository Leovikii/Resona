# 0.3.0-beta.1 Windows 测试交接

状态：Windows 自动检查由 PR CI 验证，实机验收待完成。当前开发分支 `dev`，基线为 alpha.4 `832005a`；本轮禁止合并 main、打 tag 或发布，Windows 测试完成后再统一评审合并。

## 本轮改动与风险入口

- Linux 文件访问/portal 通过平台 adapter 隔离，Windows 继续 Tauri dialog 原生选择，并新增显式 parent。Windows 不实现原始 `nfs://` 映射，应显示不支持位置；正常盘符、UNC、系统挂载路径沿用物理文件链。
- Rust 播放 actor 新增相对控制：Space 切换、左右 ±5 秒、上下 ±10 个音量百分点。前端只提交意图，主/压缩窗口共用 actor。
- 外部文件打开的成功/失败先由 Rust 保留，前端注册 ready 监听后一次消费，覆盖冷启动时事件早于前端的情况。
- 没有数据库迁移；既有列表、偏好、源音频应保留。当前版本字段为 `0.3.0-beta.1`，Arch 为 `0.3.0beta1`。

## 已完成与尚未完成

2026-10-29 的 [CI（a527638）](https://github.com/Leovikii/Resona/actions/runs/40850949129) 中，Windows Node 64 项通过（4 项平台跳过），前端构建、品牌资源、许可证、fmt 与 Rust 139 项通过（12 项条件忽略），Arch job 通过。Windows Clippy 发现共享错误枚举中仅 Linux 构造的 `NetworkLocationUnavailable` 未使用；已按 ADR 0028 添加仅非 Linux 生效的局部 lint 标注，本机 fmt/Clippy 复核通过。修正提交的双平台最终结果以 PR 最新 `PR validation` 为准；Windows 原生操作仍需逐项记录。

## Windows 自动测试与构建

在 VS Developer PowerShell 中检出最新 `origin/dev`，记录 `git rev-parse HEAD`、系统版本、Node/Rust 版本。使用仓库锁文件：

```powershell
npm ci
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --all-targets --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings
npm run licenses
git diff --exit-code -- docs/THIRD_PARTY_LICENSES.md
npm run build:exe
```

`npm run build:exe` 才生成嵌入前端的原生测试程序；不要交付裸 cargo build 的开发服务器产物。通常忽略的真实播放/CUE 测试可在有输出设备时单独运行，先降低测试音量：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml focused_controls_preserve_paused_cue_position_on_real_output -- --ignored --test-threads=1
npm run prepare:test-tools
cargo test --manifest-path src-tauri/Cargo.toml pinned_ffmpeg_test_tools_preserve_matrix_and_quantize_32_bit_to_24 -- --ignored --test-threads=1
```

不要在 Windows 运行 Linux 原生 portal 或需要 KDE 的 NFS 条件测试。

## 必须实机验证

| 项目 | 操作与预期 |
| --- | --- |
| 原生选择器 | 主窗口打开、添加文件、添加文件夹；压缩 WAV/文件夹。核对系统原生界面、父窗口/模态、单选/多选、取消、重复点击单飞、焦点归还；选择器打开期间按键不能控制后台播放 |
| Windows 路径 | MP3/WAV/FLAC 的盘符、中文、空格、`#`、`%` 文件名及 UNC（有共享时）；文件不存在/拒绝访问须可诊断，恢复打开本地音频后可播放 |
| 外部打开 | 关闭全部实例后从 Explorer 打开，再在已运行实例中打开另一个文件；默认列表、当前项目、错误提示均更新，单实例不回归；不能只检查 MPRIS/引擎而漏掉主 UI |
| 播放快捷键 | 主窗口宽/窄、列表/完整播放器/工具/设置、压缩窗口；Space 暂停/继续，左右各 5 秒且不切歌；空闲 Space/定位不自动加载；暂停定位保持暂停 |
| 音量 | 设置 35%，Up→45%、Down→35%；35.5%→45.5%（若原生接口可设置）；0/100 截断，连续按键累加；只改应用音量；主窗口滑条/百分比立即反馈，压缩窗口单条百分比/音量条，不移焦 |
| 控件优先 | 新建列表输入框含空格/中文 IME；按钮 Space、曲目行 Space 选择/Enter 播放；滑块 Up 按自身 1% 步长；Tabs、菜单、下拉、确认/设置弹窗不抢键；带修饰键组合不触发全窗操作 |
| 重复与焦点 | Space 长按只切换一次；方向键长按有界，释放/切换窗口/最小化后不持续操作；回到窗口仍可用；反复挂载布局不增加监听器 |
| 反馈生命周期 | 自动音量弹层约 1.2 秒关闭；手动展开的弹层不会被自动计时关闭；错误不显示虚假成功值，压缩任务错误不被播放反馈清掉 |
| CUE 与进度 | 本地同名 CUE 展开、逻辑区间定位边界、暂停前后定位；拖动进度与键盘交错时无旧目标跳回 |
| 原生集成回归 | SMTC/物理媒体键、任务栏按钮/进度、托盘显示/退出、文件关联、Mica/标题栏、最大化/Snap、桌面歌词、DPI；记录真正观察过的项目 |
| 数据保留 | 备份测试数据后用既有列表/偏好启动；无列表丢失、不修改源音频、不改变系统默认播放器；NSIS 覆盖/卸载等仍按既有安装门禁独立验收 |

## 回报格式与合并条件

记录 commit SHA、Windows/缩放/音频设备、各自动命令结果及忽略项；逐项填写原生清单通过/失败/不具备条件。失败提供最短复现步骤与脱敏日志，勿提交用户音频、临时路径或凭据。

仅当 Windows 编译/自动检查通过、实机清单完成或所有者明确接受保留项，且同一 PR 的双平台 `PR validation` 成功并跟上 main 后，才进入合并评审。当前交接不授权自动合并。
