# 0.3.0-alpha.4：无边框标题栏与连续材质外壳

- 状态：代码已实施并推送 dev；本机检查完成，Linux 原生交接待实机验收，暂不合并、不发布。
- 日期：2026-10-28。
- 范围：前端布局、共享无边框标题栏、Windows Mica/Snap 与 KDE 模糊适配；版本统一提升到 alpha.4。最新 CI 规则为仅 main 更新触发，日常 dev 推送/PR 更新不自动验证；已有 CI 失败跟踪为临时安排，见 ADR 0034。
- 当前应用版本为 `0.3.0-alpha.4`。长期约束见 [ADR 0033](../decisions/0033-frameless-titlebar-and-kde-material.md)。

## 目标

1. 宽屏保留标题栏左侧的小图标与 Resona 名称，右侧最小化、最大化/还原、关闭；删除侧栏大号渐变 Resona 字标，使播放列表直接位于标题栏下。
2. 窄屏删除单独的品牌/工具导航行；将工具、设置放入标题栏、位于三个窗口按钮左侧。播放列表仍为独立横向导航，新增按钮固定在右侧。
3. Windows 保留 Mica；KDE Wayland 将当前 Mica 覆盖的外壳区域接入 compositor 原生背景模糊，失败或不可用时使用完整实色。
4. 继续使用 Mantine 的交互与无障碍能力，以 WinUI 3 的标题栏、表面层级和间距原则建立统一外观。

## 参考与适用边界

- [Microsoft 标题栏设计](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)：应用身份、完整窗口按钮、空白拖动区、双击最大化、系统菜单、激活/失焦及高对比度。
- [Microsoft 标题栏定制](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar?tabs=wasdk)：交互内容与拖动区分离；带交互内容的示例使用 48px 高度。其 WinUI/XAML API 不是 Tauri 的实现接口。
- [Microsoft 内容布局与间距](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics)：以 4px 为步进，8/12/16/24px 形成布局节奏。
- [Mantine ActionIcon](https://mantine.dev/core/action-icon/)、[Menu](https://mantine.dev/core/menu/)、[Tooltip](https://mantine.dev/core/tooltip/)、[ScrollArea](https://mantine.dev/core/scroll-area/)：复用按钮、点击菜单、键盘焦点、辅助标签及滚动行为。
- 本地没有 `.local-docs/llms-full.txt`；预览基于已安装 `@mantine/core` **9.4.1** 的实际类型，未升级依赖。在线文档当前版本可能更高，不直接采用未安装的新 API。
- 以下尺寸是项目的逻辑像素提案，不是声称所有数值都由 WinUI 强制规定。标题栏文字继续遵守项目 `system-ui, sans-serif`，不内置 Windows 字体。

## 宽屏

```text
┌──────────────────────────────────────────────────────────────────┐
│ [图标] Resona                         拖动区           ─  □  ×   │ 48
├────────────────┬─────────────────────────────────────────────────┤
│ 播放列表    ＋ │ 默认                                      添加 ▾│
│ 1 默认         │ 6 首歌曲 · 24 分 36 秒                          │
│ 2 夜间聆听     │                                                 │
│ 3 通勤         │ 曲目列表／设置／工具                            │
│                │                                                 │
│                ├─────────────────────────────────────────────────┤
│ 工具           │ 封面与曲目信息     上一首 播放 下一首    辅助控件 │104
│ 设置           │                                                 │
└────────────────┴─────────────────────────────────────────────────┘
```

- 默认/最小尺寸保持 `1080×700` / `760×520`；布局仍由显式模式决定，不随浏览器断点自行切换。
- 侧栏继续为 **208px**，左右内边距 **12px**，顶部留白 **12px**；播放列表分组标题 **36px**、列表入口 **40px**。
- 删除大号字标及其下方多余留白，不把其他信息填回腾出的空间。工具、设置保留侧栏底部位置。
- 主内容上缘与标题栏下缘相接；右侧留 **12px** 外边距、内容内边距 **24px**。保持单层内容背景与 **8px** 圆角。
- 本轮不重做列表领域交互、完整播放器或底栏信息架构；预览中的演示曲目和简化播放器只用于观察布局密度。

## 窄屏

```text
┌────────────────────────────────────────────┐
│ [图标] Resona  拖动区  工具 设置  ─  □  × │48
│ 1 默认  2 夜间聆听  3 通勤              ＋ │36
│ ┌────────────────────────────────────────┐ │
│ │ 默认                            添加 ▾ │ │
│ │ 曲目列表／设置／工具                    │ │
│ │                                        │ │
│ └────────────────────────────────────────┘ │
│ 封面  曲名 · 时间与音质                     │
│ 音量 循环     上一首 播放 下一首   歌词 定位 │120
└────────────────────────────────────────────┘
```

- 默认/最小尺寸保持 `420×720` / `360×600`。
- 新顶部只保留 **48px 标题栏 + 36px 播放列表导航 = 84px**，不再保留旧的独立品牌/工具行。
- 空间收益按完整窗口计算：若旧系统标题栏为 32px，则原 `32 + 76 = 108px` 缩为 84px，净增加 **24px** 内容高度；不能把删除 40px 品牌行误报为净省 40px。KDE 原装饰高度由实际主题决定。
- 标题栏应用图标 **16px**，左边距 **16px**，图标与名称间距 **8px**；窄屏名称 **12px**，宽屏 **13px**。紧凑间距是为 360px 下的独立按钮和拖动区域做的项目选择。
- 工具、设置及三个窗口控件均占 **44×48px** 槽位，保持同一垂直中心；应用图标 **18px**，窗口符号 **12–16px**，避免齿轮与关闭符号争抢视觉权重。工具组与窗口组间留 **8px**。
- 360px、100% 字号下预览保留约 **48px** 连续空白拖动区域。更大文字缩放下优先省略应用名称，保证窗口按钮与应用控件可达；不通过重叠、缩小点击区域或隐藏关闭按钮解决拥挤。
- 列表导航左右 **8px**，标签 **32px** 高、行高 **36px**；列表过多时横向滚动，新增 **36px** 按钮固定在右侧。现有原生应用的拖放、排序、滚轮横移行为必须保留。
- 主内容左右 **8px** 外边距、**16px** 水平内边距、**20px** 顶部内边距；页标题 **22px**。底栏维持 **120px** 两行结构与 **44px** 控件。

## 交互与状态

- 工具和设置默认透明，hover/focus 为中性浅背景，激活为主题色浅背景；关闭按钮 hover 使用红色，其余窗口按钮使用中性反馈。pressed 不改变几何。
- 每个图标按钮都有明确名称，Tooltip 同时支持键盘焦点；菜单使用 Mantine 点击触发、Portal 和 Escape 关闭。
- 全部空白标题区域可拖动；按钮、菜单、输入框不可被拖动区吞掉。支持双击最大化/还原、标题栏系统菜单、键盘操作和焦点恢复。
- Windows 最大化按钮悬停的 Snap Layouts、Alt+Space、系统移动/缩放和边缘命中都属于原生门禁；网页按钮调用 maximize 不能视为这些行为已完成。先核查 Tauri/Tao 的官方能力，再决定是否需要局部 Win32 adapter，不引入第二窗口框架。
- 关闭必须经过现有 `ApplicationLifetimeService`，保持关闭到托盘、退出确认、安装期间退出保护；不能直接结束进程。
- 压缩窗口正式实现时复用同一标题栏与材质，标题表达窗口用途；桌面歌词继续使用专用透明 layer-shell/Win32 路径。

## 材质

| 区域 | Windows 11 | KDE Wayland | 实色回退 |
| --- | --- | --- | --- |
| 标题栏、宽屏侧栏、窄屏列表导航、底栏 | 透出同一 Mica | 同一透明 surface + 原生背景模糊与底色 | 同一实体外壳色 |
| 主内容 | 单层低 alpha 内容表面 | 单层内容遮罩，单独校准浓度 | 实体内容色 |
| 菜单、Modal、输入控件 | 可读实体表面 | 可读实体表面 | 可读实体表面 |

- 模糊由 KWin/GPU 承担，不增加 React 轮询或每行 CSS 模糊，不通过降低整个窗口 opacity 实现透明。
- 原生接入需探测目标 KWin 实际提供的背景效果协议与 capability，核对 GTK 的同连接 surface 生命周期；不把 Qt `QWindow` API 当成可直接用于 GTK 的接口，也不要求用户安装强制模糊脚本。
- GTK/WebKit 透明、阴影、圆角、最大化、重建和模糊区域更新必须一起验证；无协议、关闭桌面效果或初始化失败时记录诊断并退回实色，不能留下透明黑窗或不可读背景。
- 只为实际露出材质的区域请求效果，并检查合成器的实际处理范围；不能仅凭正文更不透明就宣称 GPU 成本下降。
- 网页中的 Mica/KDE 使用静态色调示意，不运行 CSS 背景模糊，不模拟实时桌面采样；当前颜色不是最终原生材质验收值。

## 实施顺序与验收

1. **本轮：设计审阅。** 独立入口 `alpha4-preview.html`，复用已安装 React/Mantine/Lucide 和正式品牌图；不导入生产入口、不改 Tauri 配置、不写用户偏好、不调用后端。
2. **方案确认后：实色无边框壳。** 提取共享标题栏，迁移宽/窄布局；补齐 typed 窗口操作与生命周期。更新 ADR 0020/0021/0022、DEVELOPMENT、架构与结构规范。版本号在正式实施时按项目版本契约统一提升。
3. **原生材质。** Windows 保留 Mica；KDE 增加 capability/adapter 与可靠实色回退，不更换播放引擎或 UI 库。
4. **验证。** 四个规定尺寸、明暗主题、中英文、长名称、125%/150% DPI 与文字放大、键盘及高对比度；主/压缩窗口冷暖启动、失焦、缩放、最大化、吸附、重建、托盘及退出保护。Linux 在真实 KDE Wayland 上检查协议、透明、按钮与窗口菜单，WSLg 网页预览不能代替。
5. **性能。** 相同构建与机器对比实色/模糊下静置、滚动、拖动缩放、背后播放视频的帧时间、KWin/WebKit GPU 负载、显存和功耗；不从 React CPU 低推断总开销低。

- 运行预览：在仓库根目录启动 Vite，打开 `/alpha4-preview.html`。当前会话地址为 `http://127.0.0.1:1425/alpha4-preview.html`，服务结束后需重新启动。`npm run dev -- --port 1425 --host 127.0.0.1` 可复用该地址；本机执行环境未提供 npm 命令，本轮通过已安装的 `node node_modules/vite/bin/vite.js --port 1425 --host 127.0.0.1` 启动。

## 实施验证与交接

- 生产组件已替换原有主/压缩窗口壳；`/alpha4-preview.html?production=1` 加载实际 App 和浏览器 demo bridge，可选择主窗口四种尺寸及压缩 720×500。正式验收模式隐藏不会控制实际设置的设计稿主题/内容开关，主题与语言在应用设置内操作；页面材质仍只是色调示意。

- Windows 本机 Rust 134 通过、10 条件忽略，包含四种 DPI 比例的最大化命中几何；fmt、Clippy、TypeScript、生产 build、Node 59 通过/4 平台跳过，嵌入前端 debug 构建通过。原生按钮最大化/还原有实际状态变化，后续自动化读取失败；不宣称 Snap hover、系统菜单、Mica、阴影或真实 DPI 视觉通过。文字放大、高对比度、多屏仍属人工门禁。
- [第二轮 CI](https://github.com/Leovikii/Resona/actions/runs/40667001692) Windows 成功；Arch 编译、124 Rust 与 2 FFmpeg 通过，Clippy 的多余 return 已修复但未在 Linux 重跑，打包回归尚未到达。完整历史、命令和实机清单见 [Linux 实机交接](0.3.0-alpha.4-linux-validation.md)。
- 按 [ADR 0034](../decisions/0034-main-only-ci-and-dependency-cache.md) 改为 main 更新后的 CI 与 npm/Cargo 缓存；最后 dev 推送不再自动启动验证。本轮未合并 main、未建 tag 或发布；没有 KDE 的主机不继续模拟原生通过。
