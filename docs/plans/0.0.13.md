# 0.0.13 播放器范围收束与列表信息架构

- 状态：Implemented，待项目所有者 Windows 实机验收
- 前置版本：0.0.12 播放列表与媒体库交互闭环
- 所属阶段：0.1.0 收敛
- 目标平台：Windows；Linux 仅维护 capability/adapter 边界
- 提案日期：2026-07-20
- 接受日期：2026-07-20
- 实现日期：2026-07-20

## 背景

项目所有者将 0.1.0 收束为纯粹的本地播放器：不维护受管理文件夹或媒体库数据库，默认播放列表只保存当前会话的外部打开上下文，用户创建的播放列表才持久化。侧栏改为“最近播放 + 播放列表树 + 工具/设置”，原“正在播放”和“文件夹”页退出信息架构，未来完整播放页改由底部播放器展开。

当前代码仍包含 `managed_folders`、`media_records`、`media_library.rs`、`useManagedFolders`、文件夹导航页和侧栏“正在播放”路由；“默认播放列表”只是当前队列页面标题。主窗口默认 680×440，React 根组件又使用无内容的 lazy/Suspense fallback，Tauri 原生背景与主题初始化之间会暴露白色空窗。

本阶段先修正领域模型、持久化和应用壳，不实现完整播放覆盖页、音频压缩、标签编辑、托盘或更新器。

## 阶段目标

1. 删除 0.1.0 不再需要的媒体库数据和 UI，使代码范围与产品决定一致。
2. 建立 Rust 权威的临时默认列表和统一外部打开协议。
3. 把用户播放列表作为侧栏一级工作对象，完成新增、选择、添加和拖入的可用闭环。
4. 调整默认窗口尺寸并消除可感知的启动白屏闪烁。
5. 保持既有播放、最近播放、SMTC、歌词、桌面歌词和应用生命周期不回归。

## 实施范围

### 1. SQLite 收缩与迁移

- schema 升级到下一版本，删除 `managed_folders` 和 `media_records`。
- 保留 `playlists`、`playlist_items` 和 `recent_plays`；最近播放最多保留 100 项，记录新播放事件时在同一后台任务中清理更旧记录。
- 为用户播放列表增加稠密 `position`，支持侧栏稳定排序和在列表间隔创建。
- migration 在事务中执行，必须证明旧 0.0.12 数据库中的用户列表、项目顺序和最近历史保持不变。
- 删除 managed-folder 错误码、DTO、commands、service、测试和前端 bridge/model；保留 `metadata.rs` 供后续当前曲目按需读取。

### 2. 临时默认列表服务

- 新建框架无关的 `DefaultPlaylistSnapshot`：稳定路径集合、目标索引、来源目录和 revision；不包含 Rodio、Tauri 或 SQLite 类型。
- 所有单文件打开入口调用同一 `open_media_context(path)` 应用服务：枚举直属支持格式、稳定排序、验证目标、更新默认列表并投影到播放队列。
- 每次打开都执行廉价路径枚举并生成规范化路径快照。快照相同且目标存在时保持 default revision，不重建列表，只选择并播放目标；快照变化时原子替换。
- 不使用目录修改时间作为唯一缓存条件，不解析整目录元数据，不扫描子文件夹。
- 应用内打开、初次进程参数和 Tauri single-instance 回调的后续参数统一进入该服务。无效或不支持路径返回稳定错误，不影响现有播放。

### 3. 播放列表侧栏与交互

- 侧栏顺序改为：最近播放、轻量分隔、播放列表标题与新增按钮、默认列表、持久化用户列表；工具和设置保持底部。
- 普通冷启动选择“最近播放”；外部或应用内打开媒体后选择“默认”详情。
- 默认列表固定第一位、不可重命名或删除；用户列表按 `position` 显示。
- 点击默认或用户列表只切换右侧详情，不隐式覆盖当前队列。播放、载入和追加继续使用明确命令。
- 新建列表后可通过按钮选择文件并追加；外部文件拖入列表详情时按曲目间隔位置插入。
- 外部文件拖到侧栏用户列表项时追加；拖到播放列表间隔时在对应位置创建持久化新列表并加入文件。
- 自动命名优先使用所有拖入文件的共同父文件夹名；无法确定或冲突时使用本地化缺省名称和稳定序号。创建与加项必须作为一个应用服务流程，部分失败不得留下意外空列表。
- 删除原“文件夹”页、managed-folder UI 和侧栏“正在播放”入口。底栏封面与展开按钮在完整播放覆盖页实现前不提供无效跳转。

### 4. 启动窗口与首帧

- 主窗口默认尺寸调整为约 1080×700，最小尺寸调整为适合新侧栏的可用下限；窗口由系统居中并在超出工作区时自然约束。
- Tauri 主窗口启动时先隐藏，HTML 中用同步的最小 boot script 读取已保存主题或系统主题并设置根背景；React provider 和主壳完成首帧后再显示窗口。
- boot script 只处理首帧颜色，不复制 Mantine 主题逻辑；浏览器预览不调用 Tauri show。
- Release 启动检查必须能发现根组件失败导致的隐藏窗口；冷启动、暖启动、浅色、深色和跟随系统均需实机检查是否仍有白色闪烁。

### 5. 桌面歌词边界核对

- 保持 `platform/desktop_lyrics.rs` 为通用 facade，Windows 原生实现继续位于 `platform/desktop_lyrics/windows.rs`。
- 通用 command、DTO 和前端不新增 Windows 判断或 HWND/WebView2 类型。
- 本阶段不新增 Linux trait、Wayland 实现或模拟后端；只用编译边界和现有 unsupported capability 保证非 Windows 结构不退化。

## 不包含

- 底部播放器展开的完整播放覆盖页及封面/元数据详情
- 播放模式、会话恢复和桌面歌词位置持久化
- 桌面歌词文字透明度、hover 交互背景和两行滚动动画；统一进入 0.0.15
- 音频压缩、FFmpeg sidecar、标签编辑
- 托盘、Tauri updater、安装包和正式文件关联注册
- 受管理文件夹、媒体库索引、搜索、递归扫描或文件监听
- Linux 实现或验证

## 自动验证

- migration：从 schema v2 样本升级后，用户列表、项目顺序和最近播放不变，媒体表不存在，新列表位置稠密。
- 默认列表：同目录相同快照复用 revision、目录增删后替换、目标索引正确、排序稳定、不递归、不支持路径可诊断。
- 外部打开：初次 argv 与第二实例 argv 映射到同一 typed request；第二实例不创建第二播放核心。
- 播放列表：创建并加项的事务边界、列表位置、曲目插入位置、自动命名冲突和失败回滚。
- 前端：TypeScript/Vite build；浏览器验证中英文、浅色/深色、最近播放、空默认列表、多个用户列表、长名称和常用窗口尺寸。
- Rust：format、普通测试、真实默认音频设备测试、Clippy 和许可证检查。
- Windows Release：使用 `npm run release:windows`，验证内嵌前端、单实例、无终端窗口和退出后无残留进程。

## 项目所有者实机验收

1. 冷/暖启动主窗口大小合理，无明显白屏闪烁。
2. 从应用内或命令行打开目录中的 `1/2/3.mp3`，默认列表显示三项并从目标开始播放。
3. 再打开同目录另一项时列表不发生可见重载；新增或删除文件后再次打开能更新默认列表。
4. 新建用户列表、按钮添加、拖入指定曲目位置，以及拖到侧栏列表间隔自动创建列表均符合位置预期。
5. 重启后用户列表及最近播放保持，默认列表为空。
6. 既有播放、SMTC、歌词、桌面歌词、主窗口退出和单实例没有回归。

## 后续接口

- 底部播放器未来通过独立 overlay 状态打开完整播放页，不恢复侧栏“正在播放”路由。
- `metadata.rs` 后续只为当前曲目详情提供按需读取，不重新建立媒体库。
- Windows 安装阶段注册文件关联时，只需要把 Shell 参数接到本阶段已验证的 external-open 协议。

- schema v3 migration 已删除媒体表并通过 v2 样本回归，用户列表、曲目顺序和最近历史保持不变；最近历史上限为 100。
- 临时默认列表、相同路径快照 revision 复用、初次/第二实例参数解析与统一 external-open 服务已接入并通过单元测试。

- 主窗口改为 1080×700、最小 760×520、隐藏首帧并在 React 完成两帧绘制后显示；Release 探针会检查 HWND 实际可见。
