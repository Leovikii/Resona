# 0.0.19 Windows 深度集成、托盘与分发设计

- 状态：Completed
- 日期：2026-07-23
- 前置条件：0.0.18 已完成；ADR 0023、ADR 0024 已接受

## 目标

在不改变 Rodio 权威播放边界和已冻结页面结构的前提下，消除播放切换时的全局 UI 闪烁，完成 Windows 媒体会话、任务栏、托盘和应用生命周期闭环，并把便携 Release 转化为可安装、可卸载、可关联文件且具有明确更新路线的发行候选版本。

## 已确认范围

1. 更深入接入 Windows：补全 SMTC，增加任务栏缩略图播放控件、播放状态和播放进度。
2. 设计并实现托盘图标、托盘菜单和唯一的默认退出逻辑。
3. 设计 Windows 安装方法及更新方法；本阶段实现安装与文件关联，更新器实现归并到 0.1.0-rc.1。
4. 修复播放列表双击播放或切换曲目时整个 UI 闪烁重绘，尤其是底部控制栏的明显闪烁。
5. 补充发行前仍缺少的诊断、性能、兼容性和验收计划。

## 实施顺序

### P0：播放切换渲染隔离

- 当前 `playDefaultItem` 和 `playUserPlaylistItem` 会把共享 `pending` 置为 `true`；它又被映射为全局 `playback.busy`，导致列表、底栏和设置中的大量控件在一次播放 command 前后统一切换两次 `disabled`。这与 0.0.18 的“即时播放 command 不进入全局 busy”约束冲突，是本阶段首先修复的回归。
- 将播放、暂停、上一曲、下一曲、切歌和模式切换等即时操作与文件对话框、批量列表写入等真正阻塞操作拆分。即时操作只保留局部的重复提交保护和结构化错误，不改变页面级 `busy`。
- `PlayerBar` 建立稳定的 memo 边界；曲目切换只更新曲名、时间、进度、播放按钮、音质和必要的桌面歌词状态，不重新挂载底栏，不改变底栏网格，也不重新触发 `view-in`。
- 默认列表和用户列表的双击播放共享同一行为约束。播放命令期间曲目列表 DOM、滚动位置、选择集合、侧栏、设置和工具页保持稳定。
- 增加可控延迟的前端回归：记录 command 前后底栏根节点身份、普通内容 DOM、禁用属性、入场动画和渲染次数；不能只凭肉眼判断“看起来不闪”。

### P1：Windows 媒体与任务栏 adapter

- 以 [ADR 0023](../decisions/0023-windows-shell-media-integration.md) 为边界扩展现有 `platform/media_session`，不让 HWND、COM、`ITaskbarList3`、souvlaki 或 Windows 消息进入播放领域和 React。
- SMTC 继续接收播放/暂停、上一曲、下一曲、停止和定位；补全可用控件状态、播放状态、时间轴，以及当前按需元数据能够提供的标题、艺术家、专辑、时长和封面。无法读取的字段省略，不以文件名猜测艺术家或专辑。
- SMTC、任务栏和托盘只消费同一份可合并的原生正在播放投影，不建立三套 500ms 轮询，也不通过 WebView 转发播放 tick。
- 任务栏缩略图工具栏固定注册“上一曲 / 播放或暂停 / 下一曲”三个槽位。Windows 限制注册后不能增删或重排按钮，因此运行时只更新中间按钮图标、提示和 enabled 状态。
- 处理 `TaskbarButtonCreated`，在 Explorer 重启或任务栏按钮重建后重新注册缩略图工具栏。Win32 回调只发送 typed command，不直接持有播放 actor 锁。
- 任务栏进度映射为：有确定时长且正在播放时使用正常进度；暂停时保留当前位置并使用暂停状态；停止、空闲、不可定位或未知时长时清除进度；真实播放失败可短暂显示错误状态，但不得把无下一曲等可恢复边界错误映射为任务栏失败。
- 原生集成初始化失败必须记录可诊断原因并降级为普通播放器；SMTC、任务栏控件或进度中任一失败不能阻止音频播放和应用启动。

### P2：托盘与应用生命周期

- 以 [ADR 0024](../decisions/0024-windows-tray-distribution-and-update.md) 修订 ADR 0013 的“关闭主窗口即退出”语义。默认值为“每次询问”；关闭主窗口时弹出“退出应用 / 隐藏到托盘并继续播放”，并提供“不再询问”。勾选后把本次选择写入 Rust 偏好。设置中提供“每次询问 / 隐藏到托盘 / 退出应用”三个选项，可随时恢复询问，不能只保存在 WebView localStorage。
- 最小化继续表示普通最小化并保留任务栏按钮，不自动最小化到托盘。关闭按钮才按上述偏好执行，避免相同手势在不同播放状态下产生不同结果。
- 托盘左键释放显示、还原并聚焦主窗口；右键显示紧凑原生菜单。菜单最小集合为：打开 Resona、截断后的当前曲目只读标题、上一曲、播放/暂停、下一曲、桌面歌词开关、退出 Resona。Windows 原生托盘菜单不承载横向自绘控件；若未来需要媒体浮窗，以独立平台窗口另行设计。
- 托盘菜单的 enabled、勾选和播放/暂停文案由 Rust 权威投影更新。菜单事件只进入应用服务或 typed playback command，不直接操作 Rodio。
- “退出 Resona”是唯一的显式完整退出入口：保存几何和播放偏好、停止播放、关闭桌面歌词/helper、协调停止扫描/转换、移除托盘并退出。退出后不得残留 Resona 主进程或播放核心。
- 音频压缩正在扫描或转换时，退出请求不得静默破坏文件流程。原生退出协调器返回“可退出 / 需要确认”；需要确认时显示并聚焦主窗口，由现有 UI 展示确认，不在托盘回调中复制一套业务对话框。
- 第二实例或文件关联在主窗口隐藏时打开媒体，必须显示并聚焦主窗口，再统一进入 `open_media_context`；不得只在后台替换当前列表。

### P3：安装、文件关联与应用身份

- 0.1.0 首发只维护 Tauri 官方 NSIS `currentUser` 安装路径和 x64 架构，不同时维护 MSI。只有出现企业部署、组策略或 MSI 特有需求时再新增第二种安装路径。
- 安装器包含应用、最终应用图标和许可证通知，不包含 FFmpeg/ffprobe。支持的 Windows 10/11 通常已有 Evergreen WebView2；标准安装器使用 Tauri WebView2 bootstrapper 回退。若后续存在明确的完全离线安装需求，再提供单独离线产物并接受约 127 MiB 的额外运行时体积，不把固定 WebView2 Runtime 当默认方案。
- 音频压缩入口检查固定版本 FFmpeg/ffprobe；缺失时只提供明确的依赖下载动作。下载使用固定 GitHub Release HTTPS 资源、流式进度、取消、SHA-256 校验、安全解压和同卷原子启用，只有依赖处于 `ready` 才允许打开压缩窗口。依赖存放在 Windows 当前用户本地应用数据目录，不进入 Roaming 数据。
- 注册 MP3/WAV/FLAC 的友好文件类型、最终格式图标和 `Open` verb。首次实例、第二实例和应用内打开继续统一进入既有 `external-open` / `open_media_context` 边界。
- 安装器、开始菜单快捷方式、运行进程、任务栏分组、文件关联和 SMTC 使用同一个 `io.github.vki.resona` AppUserModelID；显式 AppUserModelID 不能只设置进程而遗漏快捷方式和关联。
- 升级覆盖保留 SQLite、播放列表、窗口几何、歌词偏好和退出偏好；卸载清理安装目录、Resona 专属注册表项、WebView 缓存、数据库、偏好、临时下载和按需依赖。卸载脚本只删除明确的 Resona 应用目录，绝不跟随播放列表路径或删除用户音频。
- NSIS 产物名称固定包含平台和架构：`Resona_<version>_windows_x64-setup.exe`；签名文件沿用相同基名。未来 Linux 发行物使用相同的平台显式命名约束。
- 0.0.19 可生成明确标记的未签名内部测试安装包，但公开 0.1.0 前必须确认 Windows Authenticode 证书或可信云签名方案。临时自签名证书不能描述为正式签名。

### P4：更新方法设计

- 0.0.19 只冻结更新协议和密钥边界；Tauri updater plugin、下载 UI、托管和更新回归在 0.1.0-rc.1 实现。
- 首版采用用户主动“检查更新”，入口只位于设置“关于”；不启动即联网、不强制更新、不后台静默下载。无网络、服务不可用或用户取消不能影响本地播放。
- 推荐使用 GitHub Releases 托管 NSIS 更新产物与静态 `latest.json`。发布仍以已安装 NSIS 版本为主，不把便携 EXE 作为另一条可自动更新的正式渠道。
- Updater 的签名密钥与 Windows Authenticode 代码签名是两套不同信任边界。Updater 私钥不得进入仓库、安装包、日志或普通开发环境；公钥进入应用配置，私钥备份、轮换和发布注入在 0.1.0-rc.1 单独记录。
- 更新前显示版本、说明和下载大小；下载完成后再次确认安装。签名错误、版本清单损坏和下载失败必须明确诊断，不能降级为运行未验证的安装包。

## 补充建议与待完善计划

### 原生设置与退出协调

- 将关闭行为、更新检查策略等必须在 WebView 不可用时仍生效的偏好放入 Rust 设置服务；主题、语言等纯展示偏好可继续留在现有前端边界，暂不做无收益的大迁移。
- 抽出单一 `ApplicationLifetimeService` 或等价协调边界，统一处理主窗口关闭、托盘退出、第二实例激活、转换任务和桌面歌词清理；Tauri run event handler 保持薄。

### 可诊断发行版本

- 当前 GUI Release 主要使用 `eprintln!`，用户环境没有终端时难以获取失败原因。0.0.19 应设计本地、有限大小、可清理且默认不上传的诊断日志，至少覆盖启动、SMTC、任务栏、托盘、文件关联和退出失败；日志中的文件路径需有明确隐私边界。
- 不为日志引入遥测、账户或联网服务。若增加日志依赖，先审查许可证、体积、轮转和退出成本。

### 性能与资源预算

- SMTC、任务栏和托盘共享低频/事件合并投影，位置更新不高于视觉需要；任务栏进度建议 250–500ms 更新，不进入 React。
- 托盘驻留时停止不可见 WebView 的无意义工作，但播放 actor、SMTC 和必要的任务栏/托盘投影继续工作。记录隐藏前后空闲 CPU、内存、WebView2 子进程和播放连续性。
- 安装包必须记录未压缩/压缩体积；FFmpeg/ffprobe 单独记录下载体积、安装后体积和来源。只有在依赖下载体积成为阻塞且能够保持固定功能、GPL 义务和转换回归时，才评估更小的自定义 FFmpeg 构建。

### 兼容与可访问性

- Windows 原生验收覆盖 Windows 10 与 Windows 11、100%/125%/150% DPI、浅色/深色/高对比度、Explorer 重启、多显示器、睡眠恢复和任务栏自动隐藏。
- 缩略图按钮图标提供适合 16–32px 的独立单色资源，不直接缩放应用品牌图标；托盘图标检查浅/深任务栏和高 DPI。
- x64 是 0.1.0 唯一承诺架构；ARM64、32 位 Windows、Microsoft Store、开机启动、Jump List、Toast、全局快捷键和 Linux MPRIS 不进入本阶段。发行命名仍提前保留平台字段，避免未来 Linux 产物产生歧义。

## 非范围

- 0.0.19 不实现 updater 下载和安装；该实现归入 0.1.0-rc.1。
- 不增加第二套播放引擎、AAC/M4A、新媒体库、在线歌词、账户、遥测、联网激活、强制更新或静默后台更新。
- 不同时维护 NSIS 与 MSI，不实现 Microsoft Store、企业集中部署、开机启动或最小化到托盘。
- 不因任务栏/托盘新增前端权威播放状态，也不让 Windows 回调直接操作 Rodio。

## 验收

### 自动验证

- 可控延迟播放 command 下，双击默认/用户列表曲目不会切换全局 busy；底栏根节点、普通内容根节点和滚动 viewport 不重挂载，`view-in` 不重新触发，底栏控件不批量切换 disabled。
- 单元测试覆盖播放快照到 SMTC/任务栏/托盘投影的映射、未知时长、暂停、停止、真实失败、无下一曲和 Explorer 任务栏重建。
- 生命周期测试覆盖默认询问、不再询问持久化、三态设置、关闭到托盘、设置为关闭即退出、托盘退出、第二实例、隐藏状态外部打开、重复退出和活动转换确认。
- 安装配置测试或脚本检查版本一致性、AppUserModelID、文件关联、图标、无 bundled sidecar、平台化产物名、许可证、bundle target 和 updater 公钥/私钥边界。
- TypeScript/Vite build、许可证、Rust format/test/Clippy `-D warnings`、差异检查和 `npm run release:windows` 全部通过。

### Windows 实机

- SMTC 媒体键、系统浮层名称/图标/元数据、播放状态、定位和蓝牙耳机控制通过；便携构建与安装版身份差异有记录。
- 任务栏缩略图三个播放控件、播放/暂停图标切换、禁用状态、进度/暂停/清除状态、Explorer 重启恢复和多窗口分组通过。
- 托盘左键恢复、右键菜单、默认关闭询问、不再询问、三态设置、关闭到托盘、设置为关闭即退出、桌面歌词、转换确认和退出无残留进程通过。
- 干净用户完成安装、开始菜单启动、MP3/WAV/FLAC 双击、第二实例转发、同版本修复安装、旧版覆盖升级和卸载；覆盖升级保留数据，卸载后应用数据、缓存、依赖和专属注册表项均清理，用户音频不被删除。
- 宽屏/窄屏、100%/125%/150% DPI、浅色/深色/高对比度下无图标模糊、菜单截断、窗口闪烁或不可达操作。

## 完成定义

- 播放切换不再造成整个 UI 或底栏闪烁，自动回归能证明渲染隔离而非仅凭观感。
- Windows 媒体会话、任务栏、托盘和退出遵循单一 Rust 权威状态与生命周期规则，失败可诊断并可降级。
- 生成可重复构建的 NSIS 安装产物，应用身份、文件关联、升级和卸载通过 Windows 实机验收并记录 SHA-256。
- 更新协议、托管、两套签名边界和密钥保管已冻结，0.1.0-rc.1 可在不重新设计发行渠道的前提下实现。
- `docs/STATUS.md`、`docs/DEVELOPMENT.md`、ADR、版本号、测试结果和实际产物一致。

## 当前证据

- 0.0.18 已完成，品牌应用图标、字标和 MP3/WAV/FLAC 文件图标资源已准备。
- 0.0.19 实现与项目所有者安装版 Windows 原生验收均已完成。SMTC 使用统一 AppUserModelID 和品牌封面；任务栏缩略图按钮、进度状态、Explorer 重建、托盘菜单、三态关闭偏好及活动转换退出确认均已进入隔离的 Rust adapter/lifetime 边界。
- SMTC、任务栏和托盘订阅同一个 500ms `NativePlaybackProjection`，Windows 回调只发送 typed command；单元测试覆盖任务栏投影、生命周期持久化、活动转换协调和托盘菜单转义。
- `playDefaultItem` / `playUserPlaylistItem` 不再修改全局 `pending`，并增加最后一次请求胜出保护。浏览器以 800ms 人工延迟验证默认/用户列表双击：请求期间底栏按钮始终可用，底栏几何保持 `872×104`，无入场动画，曲名仅在完成后局部更新。

- Tauri bundle 已启用仅 NSIS/currentUser，使用 `%LOCALAPPDATA%\Programs\Resona`、自定义一键式模板和品牌侧栏/页眉，注册 MP3/WAV/FLAC 及格式图标，卸载精确清理 Resona 注册表和 AppData/LocalAppData。最终验收产物为 `Resona_0.0.19_windows_x64-setup.exe`，5,403,972 bytes，SHA-256 `3600976E20BCD347843C46AEDADE1F87FC425DF93C4B560672FB9A1A4DBAE98B`，明确为未签名内部测试包。
