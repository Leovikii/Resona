# 0.0.19 Windows 分发与应用身份

- 状态：Proposed
- 日期：2026-07-21
- 前置条件：0.0.18 完成；项目所有者确认图标、安装器、托盘和签名策略

## 目标

把已验证的便携 Release 转化为具有稳定 Windows Shell 身份、可安装、可卸载并能从资源管理器打开音频的发行候选版本。

## 开发前决策门槛

- 最终图标资产及其授权；生成 Windows 多尺寸 `.ico`、安装器和应用所需位图，不继续使用临时图标发布。
- 安装器默认建议只提供 Tauri NSIS；只有确认存在企业部署或 MSI 特有需求时才增加 MSI，避免维护两套安装路径。
- 0.1.0 托盘的最小功能范围，以及关闭按钮、最小化、后台播放、托盘退出和是否提供开机启动的明确语义。新 ADR 接受前继续保持“关闭主窗口即退出”，不得提前改变生命周期。
- 首版是否接受未签名安装包的 SmartScreen 提示，或提供可信 Windows 代码签名证书；不得把临时/不可信证书描述为正式签名。

## 范围

- 配置并验证 Windows NSIS 安装、开始菜单快捷方式、卸载入口、安装路径和用户数据保留边界。
- 注册 MP3/WAV/FLAC 文件关联与友好类型名称；双击、右键打开、首次实例和第二实例统一进入既有 `external-open` 服务。
- 建立稳定 AppUserModelID、快捷方式属性和应用 manifest，使 SMTC/系统媒体浮层显示 `Resona` 而非“未知应用”。
- 接入最终图标并检查任务栏、开始菜单、文件类型、安装器和 SMTC 显示。
- 按已接受的托盘/生命周期 ADR 实现最小托盘能力，不允许存在两套互相矛盾的退出语义或无法发现的后台驻留。
- 记录安装器依赖、构建命令、产物、许可证通知、版本和 SHA-256。

## 非范围

- 自动更新服务和更新签名密钥；转入 0.0.20。
- 商店发布、账户、遥测、联网激活、强制更新、Linux 包或企业集中部署。

## 验收

- 干净 Windows 用户环境完成安装、开始菜单启动、资源管理器文件关联打开、第二实例转发、升级覆盖和卸载。
- 安装版 SMTC 名称、图标和媒体键正常；便携/开发构建的 Shell 身份差异有明确记录。
- 关闭、托盘和桌面歌词生命周期符合接受后的单一规则，退出后无残留 Resona 播放核心。
- Release 不弹出终端窗口；安装/卸载不删除用户未明确纳入卸载范围的数据。

## 完成定义

- 形成可重复构建的 Windows 安装产物及校验值，应用身份、文件关联和生命周期通过实机验收。
- 分发决定写入新 ADR，`docs/DEVELOPMENT.md` 和发布文档包含离线可重复构建步骤。
