## 发现与取舍

本机 KIO-FUSE 父目录枚举返回空，并会使原可读子文件报 ENOTDIR。进一步只读 KIO 探针得到正常的 6 文件、4 子目录，但“.”类型为普通文件（32768）；KIO-FUSE `awaitChildrenComplete` 会用“.”更新节点，类型变化时替换目录节点，可解释失效链。尚未确认上游缺陷编号或服务端内部原因。本轮版本为 kio-extras 26.08.2、kio-fuse 5.1.1、kio 6.31.0。

原先“禁止网络目录发现”的临时保护已删除。GIO 识别 `fuse.kio-fuse` 后，通过官方 remoteUrl 获取来源，直接使用 KIO ListJob 列 NFS 目录并排除“.”/“..”；不调用故障 FUSE readdir。Rust 统一目录边界覆盖导入、同目录、CUE、歌词、封面与压缩扫描，导入复用 CUE 候选；文件仍走既有物理映射。内部工作模式复用同一可执行文件，在 GTK 之前拥有 QtCore 事件循环，以 quit lock 保持存活直到父进程 EOF，通过换行 JSON 串行复用 KIO 连接；没有独立 sidecar、网络播放引擎或系统配置改动。任务 15 秒、父进程 20 秒兜底，单目录最多 100000 项、响应最多 16 MiB。目录期限不约束任意 FUSE stat/read；临时路径持久化和真实断网边界保持开放。

锁定 Tauri dialog/rfd 包装会丢弃无法转换为本地路径的 URI、未设置 Linux parent，且某些服务错误与取消混淆。最终使用同一锁定 ashpd 直接调用标准 portal，保留 URI/错误及 parent，未引入自制 chooser、Dolphin 子进程或桌面配置改写。歌词伴随文件扫描也改走同一目录边界，避免前端刷新再次破坏映射；NFS 专项现包含元数据/歌词读取后继续解码播放。portal feature 激活 zbus Tokio 后曾导致 MPRIS 缺少 reactor，已在线程进入现有 Tauri runtime 上下文，保留 GLib executor，并重跑桌面集成。

## 所有者性能反馈与分段测量

验收结论：所有者于 2026-10-29 实测后确认性能达到可接受水平，性能优化完成。以下保留优化前后的测量和实际限制。

所有者确认网络位置可加入，但速度慢。使用真实目录、无音频写入、输出临时文件（与应用一致）的探针测得：

| 场景 | 耗时 |
| --- | --- |
| 当前逐目录进程，5 目录、24 子项、14 音频 | 5.12 秒，其中目录工作请求 5.08 秒 |
| 同场景 FUSE 属性查询 / 路径规范化 | 约 25 / 3 毫秒 |
| 临时探针，一个 KIO 进程顺序访问同样 5 个目录 | 1.27 秒；首个请求约 1.22 秒，其余约 0–1 毫秒 |

冷请求随 KIO 会话/缓存变化；有的首目录只需约 20 毫秒，不能用单次结果归因于服务器或程序体积。当前每目录 re-exec 丢失会话内的复用机会，递归串行放大此开销；元数据的外置封面 revision 在缓存检查前列目录，还可能追加扫描。临时 stdout 管道测量会被后代进程继承影响，曾误判为退出等待；该判断已撤回，不能拿它作为优化依据。

已改入生产实现：Rust 缓存一个串行 KIO 工作进程，每次以换行 JSON 发送 URI 并读取有界响应；错误时 kill/wait，下一请求重建。父进程读取保留 20 秒兜底，任务定时器 15 秒；即使 Qt/KIO 内部未及时处理定时器，父进程仍可终止。实际保留地址测试为 20.20 秒，未声称每种网络故障都在 15 秒返回。

所有者补充目录的根下无直属音频、有子目录；KIO-FUSE remoteUrl 返回空格、方括号与中文的可读 URI，旧 StrictMode 拒绝它。现在使用 Qt TolerantMode 并保留协议、主机、userinfo 校验；原始/编码 URI 列举一致。完整树为 25 目录、325 子项、19 个受支持音频，独立直接列举形成私有期望清单，应用递归结果逐项比对相对路径，根上下文与追加也一致，无 unreadable 分支。只读访问媒体，清单不提交。

| 本轮场景 | 耗时/结果 |
| --- | --- |
| 同一 25 目录旧工作模式，每目录新进程（完整编码地址以排除解析故障） | 31.29 秒；stdout 临时文件与旧应用一致，未计 PIPE EOF 等待 |
| 新工作进程复用，同树暖列举三次 | 56.80 / 40.98 / 41.06 毫秒 |
| 三个全新应用测试进程，完整创建并提交 19 项列表 | 322.34 / 1341.50 / 1263.79 毫秒 |
| 同进程暖递归解析 | 约 60–89 毫秒 |
| 临时本地目录，复刻同音频相对结构 | 约 0.96–1.24 毫秒；无内核 NFS 挂载，不冒充同服务器挂载对照 |
| 压缩输入真实扫描同一树 | 245.82 毫秒、326 扫描项（含根），0 WAV 候选；该目录确无 WAV，无读取警告 |

以上保留冷请求差异，不把暖缓存结果宣传成首次连接性能。仍未达到本地属性调用的绝对耗时，但主要累积冷启动已消除；因此加入 200 毫秒后显示的正文内扫描条，快操作不闪烁。没有新增目录全局缓存或改变封面缓存失效语义。

共享文件任务 gate 覆盖默认/用户列表、外部打开、压缩输入的解析/扫描/提交，忙时立即拒绝重复；压缩扫描/转换/安装也互斥。跨线程导入冲突、失败释放与活动压缩扫描拦截已通过。前端两个窗口共用 gate 与 Rust busy/scanning 快照，禁用添加和拖入，播放器控制可继续。工作进程专项验证同 PID 连续请求、非法协议失败后重建、超长请求拒绝、stdin EOF 退出。

本轮真实 NFS 专项 4 项（音频、原两目录、完整新树、压缩扫描）与工作进程复用/恢复 1 项通过；常规 Rust 136/20 条件忽略、Node 73/73、fmt/Clippy、许可证、前端与嵌入 Release 通过。最终 Release 桌面 MP3/WAV/FLAC 关联、单实例、冷打开、歌词 ready/重建、MPRIS 与启动更新单飞通过。

UI 已检查主窗口 1080×700、760×520、420×720、360×600 与压缩 720×500：扫描条在正文内，不覆盖标题；添加禁用，播放器控件保持可用，无横向溢出。通知移除自定义圆形图标，采用 Mantine 原生色条/细边框/关闭按钮、统一圆角与 380px 最大宽度，明暗主题长中英文换行可见；错误/警告手动关闭，普通/音量反馈沿用计时与进度条。参考 Mantine 与 WinUI 3 指导，不等于 Windows 原生字体/高对比实机验收。

代码验证基线 [635f2d9 CI](https://github.com/Leovikii/Resona/actions/runs/40870191090) 的 Windows/Arch/汇总全部通过，Arch 常规 135/17 条件忽略、真实 FFmpeg 2 项与包元数据 1 项通过。后续实现已变更，最新 SHA 的双平台 CI 仍是门禁，不复用该历史基线宣布新代码通过。
