## 复核命令

```bash
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked ffmpeg -- --ignored --test-threads=1
npm run build:linux
python3 scripts/test-linux-desktop.py
```

NFS actor 专项用 `RESONA_TEST_NFS_LOCATIONS` 设置 JSON URI 数组，运行 `selected_nfs_audio_decodes_seeks_and_plays -- --ignored --test-threads=1`。真实目录/文件名仅放本机临时环境，不提交仓库。桌面脚本可用 `RESONA_TEST_NFS_PATHS` JSON 物理路径数组追加低音量的第二实例、暂停/定位/继续和冷桌面打开验证；需要先用 KIO-FUSE 官方接口取得有效映射，勿从 busctl 的人类可读转义文本拼路径。

目录与离线专项另用 `RESONA_TEST_BINARY` 指向嵌入前端 Release：

```bash
cargo test --manifest-path src-tauri/Cargo.toml nfs_folders_create_append_and_default_import_without_invalidating_files -- --ignored --test-threads=1
cargo test --manifest-path src-tauri/Cargo.toml unreachable_network_directory_returns_within_the_worker_deadline -- --ignored --test-threads=1
```

前者复用上述 URI 数组，仅使用临时 SQLite，不修改远端音频；后者只请求保留测试地址。本机 KIO 冷请求开销随访问会话和缓存状态变化，不能将探针 stdout 管道造成的等待归因于应用退出；复用对照见下文。大目录性能未量化。测试包已覆盖原目录中的程序及许可证并重打包，保留 test-profile；压缩包排除测试数据。

原生 chooser 条件测试为 `native_portal_parent_exports_from_tauri_window`；单独运行并设置临时 XDG 数据/缓存。默认只检查 parent/服务，`RESONA_TEST_SELECT_NFS=1` 时需人工在第一窗选择 NFS 音频、第二窗取消，自动检查结果。测试必须串行且先退出其他应用实例。

## 发现与取舍

本机 KIO-FUSE 父目录枚举返回空，并会使原可读子文件报 ENOTDIR。进一步只读 KIO 探针得到正常的 6 文件、4 子目录，但“.”类型为普通文件（32768）；KIO-FUSE `awaitChildrenComplete` 会用“.”更新节点，类型变化时替换目录节点，可解释失效链。尚未确认上游缺陷编号或服务端内部原因。本轮版本为 kio-extras 26.08.2、kio-fuse 5.1.1、kio 6.31.0。

原先“禁止网络目录发现”的临时保护已删除。GIO 识别 `fuse.kio-fuse` 后，通过官方 remoteUrl 获取来源，直接使用 KIO ListJob 列 NFS 目录并排除“.”/“..”；不调用故障 FUSE readdir。Rust 统一目录边界覆盖导入、同目录、CUE、歌词、封面与压缩扫描，导入复用 CUE 候选；文件仍走既有物理映射。内部工作模式复用同一可执行文件，在 GTK 之前拥有 QtCore 事件循环；没有独立 sidecar、网络播放引擎或系统配置改动。任务 15 秒、父进程 20 秒兜底，单目录最多 100000 项、响应最多 16 MiB。目录期限不约束任意 FUSE stat/read；临时路径持久化和真实断网边界保持开放。

锁定 Tauri dialog/rfd 包装会丢弃无法转换为本地路径的 URI、未设置 Linux parent，且某些服务错误与取消混淆。最终使用同一锁定 ashpd 直接调用标准 portal，保留 URI/错误及 parent，未引入自制 chooser、Dolphin 子进程或桌面配置改写。歌词伴随文件扫描也改走同一目录边界，避免前端刷新再次破坏映射；NFS 专项现包含元数据/歌词读取后继续解码播放。portal feature 激活 zbus Tokio 后曾导致 MPRIS 缺少 reactor，已在线程进入现有 Tauri runtime 上下文，保留 GLib executor，并重跑桌面集成。

## 所有者性能反馈与分段测量

所有者确认网络位置可加入，但速度慢。使用真实目录、无音频写入、输出临时文件（与应用一致）的探针测得：

| 场景 | 耗时 |
| --- | --- |
| 当前逐目录进程，5 目录、24 子项、14 音频 | 5.12 秒，其中目录工作请求 5.08 秒 |
| 同场景 FUSE 属性查询 / 路径规范化 | 约 25 / 3 毫秒 |
| 临时探针，一个 KIO 进程顺序访问同样 5 个目录 | 1.27 秒；首个请求约 1.22 秒，其余约 0–1 毫秒 |

冷请求随 KIO 会话/缓存变化；有的首目录只需约 20 毫秒，不能用单次结果归因于服务器或程序体积。当前每目录 re-exec 丢失会话内的复用机会，递归串行放大此开销；元数据的外置封面 revision 在缓存检查前列目录，还可能追加扫描。临时 stdout 管道测量会被后代进程继承影响，曾误判为退出等待；该判断已撤回，不能拿它作为优化依据。

目前仅完成定位和临时复用探针，未改入生产实现。优先比较一次导入复用 KIO 会话与目录结果的最小方案，保留取消/期限和条目校验；尚未证明大目录或真实断网行为改善，不增加全局无限期缓存。

代码验证基线 [635f2d9 CI](https://github.com/Leovikii/Resona/actions/runs/40870191090) 的 Windows/Arch/汇总全部通过，Arch 常规 135/17 条件忽略、真实 FFmpeg 2 项与包元数据 1 项通过。之后纯文档更新不改变上述二进制。
