# 0.0.10 Windows 桌面歌词窗口技术原型

- 状态：Completed，技术可行性通过；产品化缺口转入 0.0.11
- 前置版本：0.0.9 本地多格式歌词解析与播放同步
- 架构决定：[ADR 0012](../decisions/0012-desktop-lyrics-window-and-unlock-helper.md)
- 所属阶段：P4 歌词
- 目标平台：Windows；不实现或验证 Linux
- 提案日期：2026-07-19
- 接受日期：2026-07-19
- 实现日期：2026-07-19

## 阶段目标

用最小实现证明 Windows 桌面歌词窗口方案可行，不提前完成产品化功能。原型必须验证：透明置顶歌词 WebView、权威歌词同步、解锁拖动、Tauri 官方整窗鼠标穿透，以及一个不含 WebView 的微型原生解锁辅助窗口。

原型成功后再规划窗口状态持久化、多显示器完整恢复、正式样式和入口位置。播放列表、受管理文件夹和一般主界面 UI 继续冻结。

## 原型范围

### 桌面歌词窗口

- 创建同进程、无边框、透明、置顶的第二个 Tauri WebView 窗口，不创建 sidecar 进程。
- 使用轻量窗口入口，只加载主题、本地化、歌词展示和必要窗口状态，不加载应用壳、媒体库或播放控制页面。
- 复用现有 Rust `PlaybackSnapshot`、`LyricsSnapshot` 和 750 ms 低频组合快照；不复制 `LyricsService`、歌词解析、播放时钟或队列状态。
- 原型显示当前歌词和下一行；无歌词、空歌词和加载失败使用已有可区分状态。视觉只需清晰、稳定并支持中英文，不作为最终样式。
- 主窗口设置页提供最小的显示/隐藏和锁定/解锁入口，入口位置不绑定未来正式播放器布局。
- 解锁时允许拖动桌面歌词窗口；原型不实现调整尺寸、位置持久化或启动自动恢复。

### 锁定与解锁辅助窗口

- 锁定时通过 Tauri 官方 `set_ignore_cursor_events(true)` 让整个歌词 WebView 穿透鼠标；不对 WebView2 HWND 实现局部命中测试。
- 同时显示一个不含 WebView 的微型 Windows 原生 owned tool window，作为唯一保留的可交互热点。它不出现在任务栏、不抢占当前程序焦点，并跟随歌词窗口置顶。
- 辅助窗口平时低干扰显示，鼠标进入后显示明确解锁状态；点击后由 Rust 窗口服务先恢复歌词窗口交互，再隐藏辅助窗口。
- 优先由 Tauri `WindowBuilder` 管理无 WebView 窗口生命周期；必要的 hover、点击和绘制消息只在 Windows platform adapter 内处理，不暴露 HWND 或 Win32 类型。
- 主窗口始终保留解锁和隐藏入口。辅助窗口创建、定位或显示失败时，锁定 command 必须拒绝或立即回滚，不能留下只有穿透歌词窗口而没有恢复入口的状态。
- 除桌面歌词自身外，不为解锁辅助窗口增加额外 WebView；不使用全局鼠标 hook、持续鼠标轮询、输入注入或向后方窗口转发鼠标消息。

## 代码边界

- 新增 `DesktopLyricsWindowService` 或等价应用服务，统一拥有可见性、锁定状态、歌词窗口和辅助窗口生命周期。
- Tauri commands 只做类型化输入验证与服务调用；React 不直接执行 Windows 平台判断或 Win32 调用。
- Windows 特定实现放入 `src-tauri/src/platform/desktop_lyrics/`；非 Windows capability 明确报告不支持，不增加 Linux 实现。
- 桌面歌词前端放入独立 `src/windows/` 入口或等价轻量边界；可共享歌词纯展示组件，但不复用会创建第二份播放控制状态的完整主窗口 hook。
- 原型优先复用现有 Tauri 和 `windows` crate，只按所需 Win32 API 增加 feature；不引入窗口状态插件或新的 UI 库。
- 所有失败返回稳定错误码并保留可诊断上下文；桌面歌词故障不得改变 Rodio 播放、队列或主窗口状态。

## 实施顺序

1. 建立 `DesktopLyricsWindowService`、窗口状态机、类型化 command 和最小 capability 权限。
2. 创建透明置顶歌词 WebView 和轻量 React 入口，验证歌词同步与解锁拖动。
3. 使用官方整窗穿透验证点击、滚轮和拖动能够作用于其他进程窗口。
4. 创建无 WebView 原生解锁辅助窗口，验证不抢焦点、hover、点击解锁和锁定失败回滚。
5. 接入主窗口最小显示/锁定控制，补齐中英文状态和可恢复错误。
6. 完成自动检查、Windows 实机矩阵、Release 构建与项目所有者验收包。

## 自动验证

- 纯状态机覆盖隐藏、显示、解锁、请求锁定、锁定成功、辅助窗口失败回滚和从主窗口解锁。
- command 测试确认非法状态不会静默成功，辅助窗口失败时不会保留穿透状态。
- 歌词回归覆盖 LRC/SRT/WebVTT、暂停、继续、seek、切歌、无歌词和坏歌词。
- 前端验证桌面歌词入口不会加载媒体库、创建第二播放控制器或形成高频 IPC。
- `npm run build`、`npm run licenses`、Rust format/test/Clippy、真实音频设备回归和 Windows Release 构建通过。
- 浏览器或静态预览只验证歌词布局；透明、置顶、焦点和穿透必须在真实 Tauri Windows 窗口验证。

## Windows 实机验证矩阵

1. 歌词窗口在普通桌面、浏览器和资源管理器上方保持透明置顶，文字无背景残留。
2. 解锁时窗口可拖动，拖动不改变播放或歌词同步。
3. 锁定后，歌词区域上的点击、双击、滚轮和拖动能够作用于后方的不同进程程序。
4. 原生辅助窗口不出现在任务栏，不激活或抢走后方程序焦点；hover 状态稳定，点击可立即解锁。
5. 主窗口可以在任何锁定状态下解锁或隐藏桌面歌词。
6. 至少验证 100% 与 150% 缩放、主屏和一个副屏位置；原型只要求辅助窗口位置正确，不承诺重启和显示器拓扑变化后的恢复。
7. 关闭、停止播放、无歌词和解析失败不会影响音频播放，退出应用后不残留辅助窗口或进程。

## 成功标准

- 上述窗口组合在 Release 构建和真实 Windows 桌面中稳定工作。
- 原生辅助窗口不包含 WebView，锁定状态没有全局输入监听或轮询。
- 任一窗口失败均可诊断且不会形成无法操作的置顶层。
- 既有播放、SMTC、歌词、播放列表和文件夹功能没有回归。

原型通过后，另行提出产品化版本，处理窗口位置/尺寸持久化、启动恢复、显示器拓扑修正、正式视觉、更多显示偏好和最终入口位置。

## 明确不包含

- 窗口位置或尺寸持久化、启动自动恢复和完整多显示器离屏修正。
- 最终字体、颜色、描边、动画、皮肤和任意样式编辑器。
- 桌面歌词内播放控制、歌词源选择、在线搜索、翻译、编辑和逐字歌词。
- 播放列表或受管理文件夹交互调整，以及一般主界面 UI 打磨。
- Windows 安装包、SMTC“未知应用”修复、转换、元数据写入和 Linux 验证。

## 停止条件

- 如果无 WebView 辅助窗口不能稳定接收 hover/点击、不能避免抢焦点，或不能与歌词窗口可靠保持相对位置，应停止并提交复现与测量结果。
- 如果整窗穿透不能把点击、滚轮或拖动可靠交给其他进程，应停止，不通过输入转发或注入模拟成功。
- 项目所有者已确认本计划；实现仍必须遵守上述停止条件，不以计划已接受为由绕过技术验证。

## 实现与自动验证结果

- 已实现同进程透明置顶歌词 WebView、独立轻量前端入口、主窗口显示/隐藏和锁定/解锁入口，以及 Tauri 官方整窗鼠标穿透。
- 已实现不含 WebView 的 Win32 owned tool window；使用 `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`，原生绘制 hover/解锁状态，点击经类型化窗口服务恢复交互。
- Tauri 2.11.5 稳定 API 的无 WebView `WindowBuilder` 仍要求 `unstable` feature。为避免把不稳定 API 引入产品，辅助窗口改为 Windows platform adapter 内的最小 raw Win32 实现；架构边界和禁止项不变。
- 锁定顺序为：定位并成功显示辅助窗口后，再启用歌词 WebView 穿透；辅助窗口失败时拒绝锁定。主窗口入口始终可恢复或隐藏。
- `npm run build`、`npm run licenses`、Rust format、26 个普通测试、8 个真实默认音频设备测试、Clippy `--all-targets --all-features -D warnings`、`git diff --check` 和 Tauri Release 构建通过。
- 浏览器视觉验证覆盖桌面歌词正常/空状态、680x440 和 360x640 设置页、中英文与暗色模式；无横向溢出或控制台 warning/error。独立歌词 chunk 为 2.32 kB，gzip 1.06 kB。
- 项目所有者已确认显示、歌词同步、拖动、整窗穿透和原生解锁按钮基本功能正常，桌面歌词双窗口方案的技术可行性通过。
- 实机同时发现主窗口关闭后应用与播放仍存活、运行时入口位于设置页、原生解锁按钮空闲时常驻三个产品化缺口。它们不否定窗口方案，但使当前版本不能作为最终交互使用，已转入 [0.0.11](0.0.11.md) 优先处理。
- 任务管理器中的 WebView2 renderer/GPU/utility 子进程不是第二套 Rust 播放核心；当前只有一份 `RodioPlaybackEngine`。0.0.11 仍将加入官方单实例能力并在隐藏/退出时释放歌词窗口资源。
