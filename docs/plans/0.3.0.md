# 0.3.0 正式版开发计划

更新：2026-11-04。目标是统一交互、修复正确性问题并减少维护负担，沿用现有产品范围、单一 Rust 权威状态和双平台发行流程。

## 阶段与边界

本轮已进入实施、全仓审查和验证；应用版本暂保留为 `0.3.0-rc.1`。以下发现不是全面逐行审查完成声明，也不代表原生验收通过。旧 RC 的合并/发布授权不作为正式版的发布授权。

初审基于本地 `main` 的 `8ebbe56`：清点 360 个跟踪文件、分析 68 个前端 TS/TSX 文件的入口引用图，并检查底栏、主题、主要 hooks、IPC、列表协调、持久化、转换、更新和窗口边界。未验证远端 Release/Actions 状态。

## 执行顺序与交付

### 1. 统一悬浮提示与底栏体验

- 优先复用锁定 Mantine 的主题扩展和浮层行为；实施前按本地参考或类型核对 API，不新增组件库、提示库或主题设置。
- 同步中英文短文案与无障碍名称；保留现有快捷键语义和音量键反馈。长帮助在帮助位置按需展示；必要错误仍在工作流正文中展示。
- 先完成底栏所有按钮，再覆盖标题栏、列表、设置、压缩和歌词工具栏；审计 `title` 时区分原生 DOM 提示与 Modal/窗口标题等组件参数。
- 跟随已有 `auto/light/dark`，不另建主题监听；预计是小范围主题/CSS 改动，需验证 Portal 浮层、透明歌词窗、solid/Mica/KDE 回退。具体默认值和验收见 ADR 草案。

### 2. 完成全仓审查并修复逻辑缺陷

逐模块记录“已审/待审、证据、修复或保留理由、验证结果”，维护在本计划，关闭项收为简短结果，不追加日记。当前 U/F/B/C 清单只是起点，未列模块不得视为无问题。

| 审查面 | 必查内容与完成证据 |
| --- | --- |
| 前端交互与设计 | 全部入口、shared/ui、hooks、i18n 和 CSS：主题/对比、图标与命中区、focus/disabled、弹层叠放、中英文溢出、长路径、空/忙/失败/终态；完成代表性视觉矩阵 |
| 播放与列表 | actor/输出设备、MediaImportService、playlists、persistence、CUE：命令顺序、旧快照、删除当前曲目、随机历史、预载失败、设备恢复、迁移和播放列表同步；服务/状态机回归 |
| 文件、元数据与歌词 | filesystem/media_source/metadata/lyrics、file access/dialog/drop、KIO：选中目标优先、链接限制、扫描边界、缓存上限、解析错误/取消、逻辑音轨和网络超时；本地 fixture 加 Linux 条件测试 |
| 转换与依赖 | compression、ffmpeg_dependency、file_commit：完整生命周期、文件归属、排他临时文件、验证/提交/源删除顺序、磁盘错误、取消、进程回收和互斥；真实 FFmpeg 矩阵 |

| 代码与文件引用 | Rust/TS 未用项、动态资源/CSS/i18n、脚本调用、打包内容、fixtures、文档链接；每项删除需给出引用与重建证据 |

先为 F1 和高风险 B 项建立有意义的失败回归，再修复。正确性修复与纯重构分开小批提交；不同时升级大版本依赖，不重写播放核心或增加新功能。

### 3. 清理代码、文件与文档

- 为候选逐项列“路径/符号、调用者、构建/测试/发行依赖、删除理由、验证”；静态检索未命中只能筛候选。先使用现有 TypeScript unused 检查、Clippy 和引用图，不为清理直接引入重型依赖。
- 清除已证实的死组件/样式、废弃接口和重复分支，保留有消费者的平台条件代码、开发预览、音频样本、测试、锁文件、生成器、安装器资源、schema 和许可证；缩小产物须有包内容或体积对比。
- 忽略的 `target/node_modules/dist/.local-docs` 不属于本次仓库删除清单，不清理用户数据或音频。删除跟踪文件后执行干净检出验证，不能依赖本机残留产物。
- 当前事实只在 STATUS、开放限制只在 KNOWN_ISSUES、实施任务只在本计划；长期约束在 ADR、用户变更在 releases。移除 rc.1 活动计划，其有效材质/生命周期边界已在 ADR 0033，验收历史由 Git 保留。
- 压缩重复验收流水和失效“本次授权”措辞；不删除仍有效或 Superseded 的 ADR，不手工压缩自动生成的许可证。执行相对链接检查。

### 4. 正式版验收与发行收口

- 自动检查：`npm test`、`npm run build`、TypeScript unused 检查、`cargo fmt --check`、Rust tests/Clippy、fixture 校验、许可证生成无意外差异、workflow 检查与受影响打包测试；具体命令沿用 [DEVELOPMENT](../DEVELOPMENT.md)。
- 共享视觉：代表性组合覆盖主窗口 `1080×700`、`760×520`、`420×720`、`360×600`，压缩 `720×500`，浅/深/系统主题、中英文、普通和 64px 歌词。检查提示边缘避让、长文换行、focus/Escape、点击/菜单/音量弹层互斥、缩放和高对比度，不跑全部排列。
- Windows Release：原生字体/主题/Mica、标题栏/Snap/DPI、托盘/SMTC/任务栏、歌词锁定与输入穿透、播放/设备恢复、压缩与取消、旧 RC 覆盖更新；可靠脚本覆盖已有项，其余桌面/硬件交互集中人工验收。
- Linux：按所有者 2026-11-04 的要求，仅进行代码审查、当前环境可行测试与既有 PR validation；不设计独立 Linux CI，不将 Linux 原生桌面/硬件专项列为本轮完成门禁，也不宣称未运行项目通过。
- 完成后才同步修改 `package.json`/lock、Cargo 清单/lock、Tauri 配置至 `0.3.0`，添加精简英文发布说明；覆盖 `rc.1 → stable` 的 SemVer、签名清单与 NSIS/Pacman 升级。保留预览更新偏好，不擅自改用户设置。
- 无未处置 P1；开放限制须有证据及明确的发布处置，不能因“历史存在”自动豁免。最新 `PR validation` Windows/Arch 双平台成功后才合并；main CD 构建、验签及双平台发布成功后才记录已发布。
