# 0.0.3 队列与连续播放

- 状态：Completed
- 日期：2026-07-17
- 前置版本：0.0.2 Completed
- 所属阶段：P1 播放技术验证

## 目标

把 0.0.2 的单曲播放扩展为可靠的本地顺序队列，验证同一个 Rodio 输出链可以连续播放不同格式、不同采样率和不同位深的曲目，并在提前预载的场景下实现可验证的 Gapless 行为。

## 推荐范围

### 1. 队列领域契约

- Rust 保存唯一权威队列：稳定 `QueueItemId`、路径、显示名、时长、状态和错误。
- 支持替换队列、追加多选文件、移除、清空、播放指定项、下一曲和停止。
- 支持按稳定项 ID 移动队列项；移动操作由 Rust 校正目标索引，前端拖放只提交源 ID 与目标位置，按钮追加始终使用队列末尾。
- 默认只实现顺序播放；不加入随机、循环、持久化播放列表或数据库。
- 队列项解码失败只标记该项并继续下一项；所有项失败时进入明确停止/失败状态。
- 继续使用 typed actor commands，前端只接收序列化队列快照和播放快照。
- 队列快照预留来源类型和修订号，至少区分显式文件导入与后续可接入的文件夹/播放列表来源；本版本不持久化这些来源。
- 路径规范化、稳定排序和重复项策略写成纯 Rust 契约测试，避免未来 UI 直接依赖文件系统扫描顺序。

### 2. Rodio actor 与预载策略

- 一个输出设备、一个 mixer、一个 `Player` 跨曲目复用，不在切歌时重建 WASAPI 流。
- 当前曲目开始后，提前打开并 append 下一曲；由于 Rodio 0.22.2 未公开 `Player::append_with_signal`，项目使用公开的 `source::Done` 和每曲独立原子标记通知 actor。
- 只预载一首下一曲，限制文件句柄、解码内存和失败影响；不把整条长队列一次性解码。
- 队列结束信号到达时推进当前索引、更新快照并准备下一项；不依赖 `Player.empty()` 单独判断曲目边界。
- 自动切歌复用已预载的 `Player` 队列；手动 `next`、移除或排序时重建当前 `Player`，但不重建输出设备。手动停止保留列表并恢复可诊断的停止状态。
- 保留 0.0.2 的暂停、继续、当前曲定位和音量行为。

Rodio 0.22.2 的公开 `Player::append`、`Player::len` 和 `source::Done` 可支撑该策略。`Done` 仅在 source 耗尽时递减原子计数，不在音频线程发送 channel。Rodio 自身仍有“队列为空后追加无延迟”ignored 测试，因此预载是本版本的必要前提，不把动态补队列当作 Gapless 保证场景。

### 3. 混合格式与 Gapless 验证

- 顺序 fixture：WAV 44.1/16 -> FLAC 48/24 -> MP3 48 kHz VBR；MP3 只使用 44.1/48 kHz CBR/VBR。
- 高解析度 fixture：WAV/FLAC 44.1、48、96、192 kHz 的已支持位深组合。
- 自动验证队列顺序、曲目结束信号、错误项跳过、暂停/继续、下一曲和停止。
- 使用同一 `Player` 预载两首 lossless fixture，验证边界没有人为插入的静音样本。
- Windows 实机抽检混合采样率与不同格式连续播放；不宣称 MP3 编码延迟已经达到 sample-perfect Gapless，除非 fixture 和解码器证据支持。

### 4. 最小界面

- 文件对话框支持多选并追加到队列。
- 显示当前曲目、队列项、播放失败项和基本队列操作。
- 保持现有进度、定位、音量与传输控制。
- 不建立媒体库、专辑视图、系统级文件拖放、播放模式设置或正式导航壳。
- 不实现三视图导航、文件夹树、用户播放列表或最近播放；只保证多选文件建立的队列契约可被这些来源复用。
- 本版本不接收系统级文件拖放；只验证队列项排序命令和最小列表内拖拽，外部文件/文件夹拖放留到正式 UI。

## 明确不包含

- 随机、单曲循环、列表循环和播放历史
- SQLite 队列持久化、媒体库扫描和元数据封面
- 输出设备选择、蓝牙断开、默认设备变化和休眠恢复
- Gapless 的 MP3 编码延迟补偿或自研解码器
- AAC/M4A、歌词、格式转换和 Linux 实现
- 虚拟化长列表；队列仅服务于技术验证规模

## 验收标准

1. 可通过多选对话框建立并修改顺序队列，Rust 快照与 UI 顺序一致。
2. WAV/FLAC/MP3 按队列顺序连续播放，单个坏文件不会终止后续有效项。
3. 混合采样率和位深切换不重建输出设备，不产生崩溃或永久静音。
4. 提前预载的两首 WAV/FLAC fixture 通过无插入静音的队列测试；队列空后再追加只验证功能正确，不宣称 Gapless。
5. 暂停、继续、当前曲定位、音量、下一曲和停止行为稳定。
6. `npm run build`、Rust format/test/Clippy、Tauri release build 和 Windows 实机抽检通过。
7. 队列契约、错误隔离、Rodio 约束和验证证据同步到文档。

## 实施顺序

1. 先写纯 Rust 队列模型与命令边界测试，不接 UI。
2. 将 actor 的单曲状态改为队列状态，加入预载与逐曲结束信号。
3. 增加混合格式 fixture、队列回归和默认设备 smoke test。
4. 接入多选文件和最小队列 UI，完成桌面/窄窗口验证。
5. 只有验收通过后才规划 0.0.4 设备管理；不在本版本扩展媒体库。

## 后续产品化顺序

0.0.3 完成后，正式 UI 不直接扩张当前 actor，而按以下顺序接入：

1. P2 建立左侧视图导航、中心内容、右侧详情和底部迷你播放器；先接入默认播放列表和现有队列。
2. P2 增加按需文件夹浏览。打开文件时生成直属文件夹音频队列；拖入文件或文件夹时生成用户播放列表草稿。
3. P3 引入 SQLite 持久化用户播放列表和最近播放历史，再接入媒体库增量扫描、元数据和搜索。
4. P4 在右侧详情和独立窗口接入歌词，不改变播放队列和播放状态的所有权。

## 完成记录

本计划已完成。随机/循环、持久队列、系统级文件拖放或 MP3 sample-perfect Gapless 仍需在后续版本单独扩大范围和验收标准。
