# 0.1.0-rc.4 窄屏交互与播放器分页收尾

- 状态：Completed；根据 Windows 实机反馈补齐拖放、排序、窄屏滚动、播放器间距与封面投影，自动回归、浏览器验收和 Windows Release 实机验收全部通过
- 日期：2026-07-25
- 前置：0.1.0-rc.3 已完成实现、自动回归与 Windows 实机功能验收

## 目标与约束

修复窄屏外部拖放，统一导航状态和应用内弹窗动效，收束完整播放器的宽/窄屏信息架构，并让音频压缩输入树默认展示首层内容。

本阶段只使用已锁定的 `@mantine/core`、`@mantine/hooks`、Lucide 和现有 Tauri 边界；不新增 Carousel、Embla、手势库、弹窗管理器或其他组件依赖，不实现拖曳/触摸滑页、自动轮播、循环翻页或新的后端状态。

## 范围

### 窄屏播放列表拖放与导航状态

- 默认列表和用户播放列表的顶部 Tabs 暴露与宽屏相同的外部文件/文件夹拖放目标；复用现有 Tauri drag/drop 坐标命中、列表添加和选中逻辑，不复制播放列表领域状态。
- 拖入可见标签时显示明确的主题色反馈，释放后添加到目标列表并切换到该列表；拖入标签间隙时复用宽屏 `playlist-gap` 语义，按命中位置新建播放列表、导入项目并切换到新列表。
- 宽/窄屏共享播放列表拖曳排序：默认列表固定首位，用户列表按持久化位置重排，并提供右键“上移/下移”作为等价操作。外部文件拖放和内部排序使用独立状态，不得互相误触。播放列表导航和曲目列表在拖曳靠近可滚动边缘时持续自动滚动，并在滚动后重新计算插入位置，以便抵达首项、末项或当前不可见的位置。
- 播放列表导航与曲目列表统一使用不补零的普通序号 `1、2、3`；当前播放列表在同一固定槽位显示播放动画。窄屏标签区域将鼠标纵向滚轮转换为横向滚动，不增加拖曳平移，以免与排序冲突。
- 右上角工具/设置按钮与播放列表使用相同层级：默认透明，hover/focus 使用普通浅表面，激活使用主题色浅背景和主题色图标；不使用阴影或更重的填充状态。
- 导入拒绝提示使用 Mantine Notification/Transition，在 4 秒后自动退出并允许手动关闭；通过组件原生 `icon` 插槽显示 Lucide 提示图标，避免无图标时的左侧强调线。通知按后端返回的拒绝枚举简短列出实际原因，不使用泛化或猜测文案。真正错误继续常驻，完整播放器展开时提示上移以避开分页控件。
- 窄屏播放列表使用 Mantine ScrollArea 的 `offsetScrollbars="x"` 为横向滚动条保留稳定空间，激活标签不使用阴影且不得遮挡滚动条。

### 应用内弹窗动效

- 在 Mantine theme 统一 `Modal` 的内置 `pop` 过渡，时长约 180 ms；所有现有和未来应用内 Modal 继承同一默认值，并遵守 `prefers-reduced-motion`。
- 更新弹窗首次需要时仍懒加载，但关闭时保留挂载直到 Mantine 退出动画完成，避免立即卸载造成突兀消失。
- 播放列表清空确认和重命名输入不再使用 `window.confirm`/`window.prompt`，收口到已有 Mantine Modal 交互；文件选择器和 Windows 系统对话框不属于应用内动效范围。
- 不编写自有动画引擎，不引入 `@mantine/modals`；只有重复的确认/输入行为形成最小共享边界。

### 完整播放器分页与布局

- 删除“歌词/播放信息”文字分段开关及其为关闭按钮预留的 margin 特例。
- 使用现有 Mantine `Tabs` 管理语义页面，底部 `Tabs.List` 只显示可点击圆点；圆点没有可见标题或 Tooltip，仅以本地化 `aria-label` 表达封面、歌词和播放信息页面。
- 使用 Lucide 左右箭头的 Mantine `ActionIcon` 提供上一页/下一页；按钮只有本地化无障碍名称。圆点与箭头通过 CSS 在播放器 hover 或 `focus-within` 时淡入、离开时淡出，关闭按钮始终可见；禁用方向在边界处隐藏。
- 不处理鼠标拖曳、触摸滑动、滚轮翻页或惯性吸附。页面变化只来自圆点、左右按钮和 Tabs 原生键盘导航，避免为两三个固定页面自造手势系统。
- 宽屏左侧封面、标题和歌手保持固定，右侧只在歌词与播放信息两页之间切换；页码与箭头位于右侧面板底部的独立安全区，不遮挡歌词或信息末行。
- 窄屏顶部标题/歌手与关闭按钮使用稳定 header 网格，header 与正文保留至少 16 px 安全距离；正文在封面、歌词、播放信息三页之间切换。封面页使用等比方形封面或统一占位图，并同时受可用宽高约束，不能挤压标题、分页控件或底栏。
- 当前曲目有有效歌词时默认歌词页；无歌词、空歌词或读取失败时，窄屏默认封面页，宽屏默认播放信息页。默认值只在曲目变化或歌词首次完成解析时应用；用户在同一曲目内主动翻页后不得被异步结果抢切。
- 页面内容保持挂载或恢复既有滚动位置；切页不重建播放 controller、歌词文档、元数据请求或底部播放器。

### 音频压缩输入树

- 扫描返回顶层目录后自动展开该层，子目录继续由用户手动展开；不默认递归展开全部目录。
- 自动展开按 scan 和首次出现的根路径执行。用户手动收起后，后续轮询不得再次强制展开；追加新根目录时只展开新增根。
- 展开状态仍是窗口本地 UI 状态，不进入 Rust 快照或持久化，不改变递归扫描和每层分批渲染策略。

## 明确不做

- 不增加新的媒体格式、播放状态、数据库表、窗口类型或后端 command。
- 不加入 Carousel/Embla、第二套组件库、拖曳翻页或复杂自动隐藏计时器。
- 不改变宽屏左侧封面常驻、底部播放器稳定挂载、歌词点击定位和播放信息数据来源。

## 实现顺序

1. 补齐窄屏 Tabs 拖放标记和反馈，统一顶部导航按钮状态。
2. 统一 Mantine Modal 默认动效并修正更新弹窗卸载时机，收口应用内确认/输入弹窗。
3. 将完整播放器改为宽屏两页、窄屏三页的无文字分页，并完成默认页面与布局收束。
4. 修正压缩树顶层自动展开时机和手动收起保持。
5. 统一版本到 `0.1.0-rc.4`，更新状态和受影响 ADR，执行完整门禁与 Windows 实机验收。

## 验收

- 自动验证覆盖分页默认值和用户选择优先级、上一页/下一页边界、播放列表位置移动与边界、窄屏拖放目标映射、更新弹窗退出生命周期及压缩根目录只自动展开一次。
- `npm test`、`npm run verify:fixtures`、`npm run build`、许可证生成、工作流 lint、Rust test/format/Clippy 和 `git diff --check` 全部通过；依赖清单不得出现 Carousel、Embla 或其他新增 UI 包。
- 浏览器覆盖 `1080x700`、`760x520`、`420x720`、`360x600` 的明暗主题、长标题、有/无歌词、有/无封面、页面边界、控件显隐、键盘焦点、Modal 开关动画和 `720x500` 压缩窗口。
- Windows Release 验证高 DPI 下将文件和文件夹拖入宽/窄屏默认列表、用户列表标签及标签间隙，确认添加/新建/选中和插入位置一致；验证外部拖放与内部排序靠近宽/窄屏导航和曲目列表边缘时均能持续滚动到首尾，滚动后的插入位置正确；验证重启后顺序持久化、窄屏滚轮横移、激活标签不遮挡滚动条，以及导入提示包含图标和实际原因、4 秒退出且无左侧强调线；同时验证应用内 Modal 进入/退出、完整播放器圆点/箭头与封面安全距离、压缩目录异步返回后的首层展开及用户手动收起保持。

## 实机回归修复

- 测试 EXE 必须经 `npm run build:exe` 生成；裸 `cargo build --release` 未启用 Tauri `custom-protocol`，会在运行时访问 `devUrl` 并显示 `ERR_CONNECTION_REFUSED`，不得交付。
- DWM thumbnail/live-preview 改为任务栏工作线程预生成固定尺寸位图组，新组完整后才替换旧组；窗口回调始终即时提交不超过请求尺寸的最近缓存，不再等待补偿渲染。共享封面归一化为最大 512 px PNG/BGRA；源封面以 8 项 LRU 复用，任务栏按稳定指纹跳过相同封面的重复位图生成。SMTC 工作线程显式初始化 Windows Runtime，同曲位置更新按 5 秒节流，按指纹复用并保留最近 16 个不同 PNG。
- 窄屏默认列表与用户列表标题统一为两列网格，添加按钮固定在右上；360x600、420x720 和 1080x700 浏览器回归无重叠或横向溢出。
- 自动门禁与浏览器宽/窄屏冒烟由开发侧完成；项目所有者已使用最终 Windows Release EXE 确认全部功能正常，包括 SMTC/任务栏封面、连续同专辑切歌和 Explorer 响应。
