# 0.0.4 输出设备生命周期

- 状态：Accepted
- 日期：2026-07-17
- 前置版本：0.0.3 Completed
- 所属阶段：P1 播放技术验证

## 目标

在不引入 WASAPI Exclusive 或平台专用自研音频后端的前提下，使用 Rodio 0.22.2 公开的 CPAL 0.17.3 接口完成 Windows 输出设备枚举、默认/指定设备选择、流错误检测和可诊断恢复。

## 范围

### 设备契约

- Rust 提供稳定设备 ID、显示名、是否系统默认、连接类型和当前选择状态。
- 选择策略区分“跟随系统默认”与“固定设备 ID”，UI 不保存 CPAL `Device`。
- 设备枚举按需执行并在 actor 内节流，不加入 750 ms 播放快照轮询。
- 使用 CPAL `DeviceId` 字符串作为当前版本持久标识；0.0.4 不建立设置数据库。

### 输出重建与恢复

- `DeviceSinkBuilder::from_device` 打开指定设备，继续使用共享模式默认配置。
- 使用 `with_error_callback` 把 CPAL stream error 送回 audio actor；回调不执行恢复、文件 IO 或 WebView IPC。
- 跟随系统默认时，默认端点变化后重建输出并从当前曲目的近似位置恢复。
- 固定设备断开时不静默改播其他设备，进入明确不可用状态；同一设备 ID 恢复后自动重新打开。
- 恢复保留队列、音量、暂停状态和尽可能接近的当前曲位置；不承诺设备断开期间的无缝播放。

### 最小界面

- 提供输出设备菜单、跟随系统默认选项、刷新和当前状态。
- 不建立正式设置页，不暴露缓冲区、采样格式或 Exclusive 模式设置。

## 验收

1. 能列出 Windows 输出端点并识别系统默认设备。
2. 能在系统默认与指定端点之间切换，播放 actor 和 UI 状态一致。
3. 默认端点变化可重建输出；固定设备断开进入明确错误并在重新出现后恢复。
4. 输出回调只发送轻量错误信号，恢复逻辑全部在 audio actor 中串行执行。
5. 现有队列、预载、暂停、定位、音量和格式矩阵回归通过。
6. 前端 build、Rust format/test/Clippy、默认设备 smoke test 和 Tauri release build 通过。

## 不包含

- WASAPI Exclusive、ASIO、bit-perfect 或手动音频格式协商
- Bluetooth 配对、Windows 设置控制或厂商驱动管理
- 睡眠/唤醒专用 Windows API；本版本通过流错误和设备重枚举覆盖基础恢复
- Linux/PipeWire 实现和验证
