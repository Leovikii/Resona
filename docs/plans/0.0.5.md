# 0.0.5 应用壳与文件夹播放闭环

- 状态：Completed
- 前置版本：0.0.4 输出设备生命周期（已验收）
- 所属阶段：P2 应用壳与播放体验
- 计划日期：2026-07-18

## 阶段目标

围绕 Rust 权威播放队列完成第一个可长期演进的桌面应用壳，并打通“打开文件、同目录组队、文件夹浏览、按位置插入队列”的常用流程。本阶段不建立 SQLite、媒体库索引或持久化用户播放列表。

## 已有基础

- Queue、Folder、Recent 导航骨架；正式侧栏将在本阶段按最终信息架构重组。
- Rust `list_folder_entries` 命令，只读取直接子目录并过滤 MP3、WAV、FLAC。
- 当前队列的播放、追加、删除、下一曲和内部拖曳排序。
- Folder 视图的上下级浏览，以及双击/键盘激活音频。
- 底部播放控制和输出设备最小控件。

## 实施范围

### 1. 文件上下文与默认队列

- 新增单个原子命令：输入选中的音频路径，由 Rust 枚举同目录直接子文件、生成稳定顺序、替换当前队列并从选中项开始播放。
- 文件夹不递归；忽略不支持格式、不可读文件和子目录中的音频。
- UI 不执行“先枚举、再替换、再播放”的多次 IPC 组合，避免竞态和半完成状态。
- 文件夹视图和系统文件选择器复用同一 Rust 用例，保证行为一致。

### 2. 队列插入契约

- 增加 `insert_queue(paths, index)`，由 Rust 校验边界、分配稳定 ID 并返回完整快照。
- 拖入队列项目上方或下方时显示明确插入线；释放位置决定插入索引。
- 按钮添加继续追加到末尾；队列内部重排继续使用现有稳定 ID。
- 当前播放项前后插入不得重建输出设备，不得改变正在播放的曲目和位置。

### 3. 外部文件拖放

- 使用 Tauri 2 官方 WebView 拖放事件，不自行解析浏览器伪路径。
- 支持拖入一个或多个音频文件；文件夹只读取直接子音频，不递归。
- 对重复路径的首版策略为“允许重复”，因为播放队列表达播放顺序而不是媒体库唯一集合。
- 不支持格式、空文件夹和不可读路径返回结构化结果；有效文件仍可加入，不因单项失败污染整批。
- 本阶段拖放目标是当前播放队列。拖放自动创建“用户播放列表”推迟到持久化播放列表领域建立后，避免把队列误当播放列表。

### 4. 应用壳布局

- 沿用草图中的常见桌面音乐播放器结构：左侧导航栏、顶部工具栏、右侧主信息区和底部固定迷你播放器，不建立永久第三列详情。
- 左侧导航栏贯穿窗口高度；底部播放器位于右侧主信息区下方，不覆盖导航栏。
- 侧栏按使用频率分组和排序：顶部“正在播放”；内容组依次为“播放列表、文件夹、最近播放”；底部工具组依次为“工具、设置”。
- “播放列表”首版显示当前/默认列表入口和后续用户列表区域；未建立 SQLite 前不伪造可持久化用户列表。
- “文件夹、最近播放、工具、设置”分别在右侧显示对应列表或页面；工具页首版提供稳定入口和 WAV → FLAC 转换说明空状态，不提前接入 FFmpeg。
- 右侧主信息区以本地文件、队列和设置为主，不照搬在线音乐播放器的推荐信息流。
- 窄窗口下左侧导航折叠为紧凑导航或抽屉，底部控制始终保持可操作。
- 输出设备选择移入详情或设置入口，不长期占据主内容流。
- 0.0.5 保留 Windows 原生标题栏；自定义标题栏和窗口控制会增加拖动区域、DPI 与可访问性成本，后续有明确设计再评估。

### 5. 正在播放视图

- 只有存在当前播放文件时，“正在播放”侧栏项才可用；没有当前曲目时保持禁用，不能进入空的正在播放页。
- 进入方式有三种：点击侧栏“正在播放”、点击底部播放器的封面/曲目信息、点击底部播放器右侧上拉按钮。
- 进入后，右侧上部信息区与底部播放器视觉融合，但底部播放器的高度、布局和控制位置保持不变。
- 上部信息区采用“左侧大方形封面、右侧歌词”结构，并保留曲名、路径和时长等必要信息。
- 再次点击上拉按钮或切换其他侧栏项退出正在播放视图；退出不影响播放状态。
- 0.0.5 建立封面和歌词区域、加载态与缺失态；真实封面读取、LRC 解析和逐行同步仍由元数据/歌词阶段实现。
- 当前播放曲目变化时视图原地更新，不重新挂载底部播放器，也不创建第二份播放状态。

### 6. 主题与显示偏好

- 使用 Mantine 的动态主题能力，提供“跟随系统、浅色、深色”三种模式，默认跟随系统。
- 跟随系统通过 `prefers-color-scheme` 响应运行时变化，不要求重启应用。
- 提供经过对比度验证的有限主题色集合，不开放任意颜色输入，避免不可读组合。
- 主题色只改变强调色和交互状态，不把整个界面染成单一色系。
- 首版以 `localStorage` 保存纯 UI 偏好；数据模型固定为 `colorScheme`、`accentColor` 和 `locale`，以后可无损迁移到统一设置服务。
- 移除当前 CSS 中固定深色背景和硬编码边框色，改用 Mantine CSS variables 和语义 token。

### 7. 中文与英文

- 接入 `i18next` + `react-i18next`，只启用中文简体 `zh-CN` 和英文 `en`。
- 语言提供“跟随系统、中文、English”三种选择并持久化，默认跟随系统。
- 组件只引用稳定翻译 key；不在 JSX、命令处理函数或 CSS 中散落双语字符串。
- Rust 返回稳定错误码和参数，前端负责本地化；未知错误保留可诊断的原始 fallback。
- 文件名、路径和标签原文不翻译；时间、数量和排序使用 `Intl` 与当前 locale。
- 翻译资源按功能域拆分，首版不引入在线翻译平台或运行时语言包下载。

### 8. 状态、错误与可访问性

- Rust 继续作为队列、当前项和播放状态的唯一权威来源。
- 文件夹加载、拖放和命令失败使用各自局部状态，不覆盖有效播放快照。
- 队列插入、重排、删除和文件夹项目均支持键盘操作及明确的可访问名称。
- Recent 视图保留明确空状态，不在没有持久化事件模型时伪造最近播放。

## 明确不包含

- SQLite、用户播放列表持久化、最近播放持久化和媒体库扫描。
- 递归目录导入、文件监控、封面和完整元数据读取。
- 歌词、桌面歌词、格式转换、AAC/M4A 和 Linux 验证。
- 工具页中的真实 WAV → FLAC 转换；0.0.5 只保留入口和空状态。
- 长列表虚拟化；先用固定规模测试确定瓶颈，确有需要时再采用成熟库。
- Windows 原生文件选择窗口偶发阻塞的进一步修复；见 `docs/KNOWN_ISSUES.md`。
- Windows SMTC 媒体会话；该能力在 0.0.6 单独实现，避免与 UI 重构同时扩大诊断面。

## 验收标准

1. 从系统选择器或 Folder 视图打开任意支持音频，会载入同目录全部支持音频并从选中项播放。
2. 多文件或文件夹拖入队列时，可按释放位置插入；按钮添加始终追加到末尾。
3. 插入、删除和排序不重建输出设备，当前播放项身份和播放位置保持正确。
4. 目录不可读、部分文件无效或格式不支持时有结构化结果，播放器 actor 不退出。
5. 680x440、推荐桌面尺寸和 360x640 下无横向溢出、控件重叠或不可达操作。
6. 无当前曲目时不能进入“正在播放”；有当前曲目时三个入口均可进入，且底部播放器布局不发生跳动。
7. 正在播放上部区域稳定显示方形封面和歌词区域；缺少封面或歌词时显示明确空状态。
8. 工具页入口稳定存在，但不会误导用户认为转换功能已经可用。
9. 系统/浅色/深色模式和每个主题色均保持可读，系统模式可在运行时跟随 Windows 切换。
10. 中文和英文界面没有缺失 key、硬编码残留或导致布局溢出的文本。
11. 前端 build、Rust format/test/Clippy、设备 smoke test、许可证报告和 Tauri release build 通过。

## 已确认的决策

1. 本阶段把拖放限定为“当前播放队列”，用户播放列表创建与持久化放到后续阶段。
2. 同目录音频采用稳定的不区分大小写文件名排序，不额外实现自然数字排序。
3. 重复文件允许多次进入队列。
4. Recent 仅保留空状态，不在 0.0.5 引入临时内存历史。
5. 采用经典“侧栏 + 右侧主信息区 + 底部播放器”结构，不建立永久第三列详情。
6. 主题模式和语言都默认跟随系统，并允许手动覆盖。
7. 侧栏顺序为：正在播放；播放列表、文件夹、最近播放；工具、设置，其中工具和设置固定在底部组。
8. 正在播放视图只在有当前曲目时可进入，展开后底部播放器保持原布局不变。
