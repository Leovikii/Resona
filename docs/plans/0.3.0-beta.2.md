# 0.3.0-beta.2 开发与验证

范围：修复 Linux 更新后需手动重启，以及 KDE Wayland 歌词启动选屏、跨屏与位置记忆；检查 Windows 对应实现。beta.1 已发布；所有者于 2026-10-30 授权双平台 PR CI 通过后合并 main、发布 beta.2 并同步 dev。

## 根因与改动

- Linux 安装成功原本只设置 complete，没有重启调用。现复核数据库成功后先复用退出前保存，再调用 Tauri request_restart；Exit 事件先释放 single-instance D-Bus 名称。下载/事务预览/Polkit 仍由用户触发，取消或安装失败不走重启分支。
- Wayland 旧几何只有 x/y/width，输出来自创建时主窗口；隐藏主窗口可被 GTK 按 (0,0) 误判至副屏。GTK 3 Wayland 后端未实现 primary monitor 查询，is_primary 全为 false 是该接口限制；KDE 的输出优先级仍存在。layer-shell 使用专用输出和边距，KWin 普通窗口记忆不接管。
- 新几何增加可选 output（厂商、型号、布局原点），先精确匹配，再匹配唯一同型号；无旧记录/原屏缺失时回退到已映射主窗口或可用屏。旧 x/y/width 可以读取，不迁移其他用户数据。拖动以 surface-local 指针推导布局位置，指针进入另一输出后重绑定歌词/helper 并约束尺寸。跨屏 remap 结束本次拖动，松手后继续调整；不新增全局鼠标能力，不实现运行中的热拔插恢复。
- Windows 原有系统拖动不钳制单屏，物理位置/宽度恢复按最大交集或最近工作区选屏，使用目标 DPI 后再恢复原点；没有发现 Linux 的同类算法问题。检查另发现持有服务锁调用 Tauri 拖动/几何查询可能与 DPI/resize 回调互等，现复制句柄后释放锁，锁定前定位后复核资源代次；字号更新仅保留已有无锁置顶/helper 同步。
- Windows 原生生命周期测试另发现 WinEvent hook 在事件线程安装、却在隐藏歌词的工作线程卸载，产生“句柄无效”。卸载现派发回事件线程，不同步等待、不持有服务锁；原生重复关闭重建检查同时拒绝 hook 卸载错误日志。

## 自动结果（2026-10-29）

- Node 75/75；TypeScript 与 Vite 通过。
- Rust 常规 137 通过、21 条件忽略；fmt/Clippy all-targets 通过。新增输出重排、唯一型号移位、重复型号歧义、旧格式与负原点边界测试。
- 真实 KDE Wayland：native_layer_surface_lifecycle 通过。协议日志出现两个 wl_output 上的歌词 layer surface，断言实际输出、helper 绑定、固定字号高度、保存/关闭重建、输入穿透和解锁。未模拟鼠标。
- 真实进程：native_update_restart_releases_single_instance 通过。测试启动隔离 Tauri 子进程，request_restart 后新进程成功取得同一个 D-Bus 单实例名并执行 setup；不安装系统包，不复用用户应用数据。
- Windows 对应变更已在 2026-10-30 完成下述本机编译、回归和所有者验收。
- 嵌入前端 Release 构建及现有 test-linux-desktop.py 通过（MP3/WAV/FLAC 桌面打开、单实例、每进程一次启动更新、歌词真实前端 ready/重建、MPRIS 与退出）。本机测试目录为 `src-tauri/target/test-build/Resona-0.3.0-beta.2-arch-wayland-x86_64/`，复制 beta.1 test-profile，原目录保留；文件 SHA256 校验通过。临时日志保留在 /tmp/resona-beta2-*.log，不提交。

## Windows 本机结果（2026-10-30）

- 基线 `3b98813`，本轮补修 hook 卸载。Windows 11 x64，Rust 1.98.1 / MSVC 2022；本轮 Node 24.22.1，远端 CI 仍按工作流使用 Node 26。
- Node 71 通过/4 平台跳过；Rust 145 通过/12 条件忽略；fmt、Clippy（含 custom-protocol 原生测试）、TypeScript/Vite、许可证无差异与隔离标识的嵌入前端 Release 构建通过。首次沙箱执行有 5 项文件移动/激活被系统拒绝，正常本机权限下重跑全部通过，没有修改生产文件安全逻辑。
- 新增 `native_lyrics_geometry_and_lock_lifecycle`，真实 Tauri/WebView2 与原生 helper 回归 1 项通过。实际工作区 `3072×1920`、200% 缩放；两次定位/关闭重建往返、16/64px 固定高度、锁定/解锁、helper 实际 HWND 边界、保存和恢复、迟到 ready、WinEvent hook 释放均通过。没有模拟鼠标，也不将 API 定位等同于实际鼠标跨屏。
- Cargo 库测试默认没有 Tauri 应用的 Common Controls v6 清单，直接启动该原生测试会报 `STATUS_ENTRYPOINT_NOT_FOUND`。原生用例仅在嵌入前端模式编译，由脚本从 Release 提取同一清单再嵌入测试 EXE；普通 `cargo test` 不依赖该步骤。脚本有 30 秒进程期限，进程退出后再清理 WebView2 隔离数据，避免仍占用的配置目录造成假失败。
- 测试程序为 `src-tauri/target/test-build/Resona-0.3.0-beta.2-windows-x86_64/Resona.exe`，附样本、许可证和 SHA256；独立标识 `io.github.vki.resona.windows-validation` 保留此前测试偏好，与安装版隔离。所有者确认本机可测项目均通过：拖动、锁定/解锁及穿透、16/64px 字号、关闭重开和应用重启后的恢复。本机只枚举到单屏，负坐标及不同 DPI 双屏未测。

在 MSVC 开发终端执行（先按开发规范构建嵌入前端 EXE）：

```powershell
npm run build:exe -- --config src-tauri/target/windows-validation.config.json
./scripts/test-windows-lyrics.ps1
```

其中忽略配置 `windows-validation.config.json` 内容为 `{"identifier":"io.github.vki.resona.windows-validation"}`；本机日志与产物留在忽略的 target，不提交。
