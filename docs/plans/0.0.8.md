# 0.0.8 受管理文件夹与元数据索引

- 状态：Completed
- 前置版本：0.0.7 持久化播放列表与媒体库基础
- 所属阶段：P3 本地媒体库
- 目标平台：Windows；Linux 仅保留结构，不在本阶段验证
- 开始日期：2026-07-18
- 实现完成日期：2026-07-18
- 验收日期：2026-07-18

## 阶段目标

把 0.0.7 已建立的 SQLite 基础扩展为可用的本地媒体库索引：用户可添加和移除受管理文件夹，执行可重试的直属目录增量扫描，并使用 `lofty-rs` 读取 MP3/WAV/FLAC 的标题、艺术家、专辑、时长和封面引用。


## 实施范围

- Rust `managed_folders` service：添加、移除、列出、手动重新扫描。
- 只扫描受管理文件夹的直接内容；递归扫描作为独立决策，不默认开启。
- 根据路径、文件大小和修改时间进行增量判断；删除或移动的文件保留可诊断的 missing 状态。
- 批量事务写入 `media_records`，单文件解析失败不阻塞其他文件。
- `lofty-rs` adapter 只返回 Resona DTO，不把第三方类型暴露到 command 或 UI。
- 前端文件夹/媒体库视图增加最小的添加、扫描状态、错误和重试入口；扫描取消后置。
- 自动化 fixture 覆盖 MP3/WAV/FLAC、无标签文件、损坏标签和缺失文件。

## 当前实现进度

- 已完成 schema version 2 migration，新增 `has_artwork` 字段并兼容 0.0.7 数据库。
- 已完成受管理文件夹添加、移除、列出和手动扫描 commands。
- 已完成直属目录扫描：忽略子目录和不支持格式，单文件失败只进入错误摘要。
- 已完成基于修改时间复用旧媒体记录的增量基础；重复扫描不会重复插入记录。
- 已完成 `lofty 0.24.0` 只读 metadata adapter，返回标题、艺术家、专辑、时长和封面存在性 DTO。
- 已完成文件夹页面最小添加/扫描/移除入口，并覆盖加载、空、错误和扫描状态。
- 自动验证已通过：17 个普通 Rust tests、8 个真实音频设备 tests、Clippy、格式检查、前端 build、许可证检查、Release build 和 1280×800/窄屏预览。

## 不包含

- 元数据写入、封面编辑、LRC 歌词、WAV 转 FLAC、AAC/M4A 扩展、Linux 实现和视觉重构。

## 验收标准

1. 新安装、重复启动和 schema migration 均保持数据库可用且失败可诊断。
2. 扫描可重试；单文件失败不会丢失其他成功记录。取消操作后置，不阻塞本阶段。
3. 重复扫描不会重复插入记录，文件变化会更新对应媒体记录。
4. MP3/WAV/FLAC 的只读元数据和封面引用在 fixture 上稳定返回。
5. Rust 单元/集成测试、前端 build、Clippy、许可证检查和 Windows smoke test 通过。
