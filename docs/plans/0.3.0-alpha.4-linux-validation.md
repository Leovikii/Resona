## 构建与隔离运行

先正常退出其他 Resona 实例，避免单实例机制把测试转交到用户会话。依赖和基础构建方法见 [Linux 指南](../LINUX.md)。保留桌面的配置和字体，只隔离应用数据/缓存；不要修改用户现有列表、音频或 GTK 配置。

```bash
npm ci
npm run test:linux
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked ffmpeg -- --ignored --test-threads=1
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings
npm run build:linux
resona_alpha4_root=$(mktemp -d)
XDG_DATA_HOME="$resona_alpha4_root/data" XDG_CACHE_HOME="$resona_alpha4_root/cache" \
GDK_BACKEND=wayland WAYLAND_DEBUG=client ./src-tauri/target/release/resona \
  2>"$resona_alpha4_root/wayland.log"
```

日志通常位于 `$resona_alpha4_root/data/io.github.vki.resona/logs/resona.log`；`WAYLAND_DEBUG` 只用于诊断，不用于性能测量。分享前筛选必要片段，协议日志可能包含本地路径/窗口信息。不要在日常运行中长期启用。

## 材质与窗口验收顺序

1. 记录 commit、`plasmashell --version`、`kwin_wayland --version`、`pacman -Q gtk3 webkit2gtk-4.1 mesa`、显卡/驱动、屏幕缩放和桌面效果设置。必须是原生 Wayland；WSLg 不提供目标 KWin 合成环境。
2. 主窗口与压缩窗口各检查冷启动、关闭重开、失焦、深浅主题。外壳应连续，正文保持不透明，弹层可读，无黑窗、闪透明或 GTK 装饰残留。日志 `KDE shell material` 和协议日志只能说明请求/能力，不证明模糊实际生效。
3. 能力优先 `ext_background_effect_manager_v1` 的 Blur，缺失时兼容 `org_kde_kwin_blur_manager`；两者都没有、能力撤回或初始化失败时完整实色回退。分别记录实际可测协议，不为测试强行卸载桌面或伪称旧协议也通过。关闭模糊效果后观察 compositor 是否撤回 capability；没有撤回时不能期待客户端推知内部效果开关。
4. 在有纹理/窗口的桌面背景上肉眼核对模糊范围：标题栏、侧栏/标签和底栏；正文矩形应被排除。移动、缩放、宽窄切换、最大化/还原、重建压缩窗口后范围不得滞留或偏移。检查圆角、阴影、边缘缩放和吸附；仅无边框不保证 compositor 自动提供装饰阴影。
5. 逐一实际点击标题按钮和边缘，拖动空白区、双击最大化/还原、右键标题区打开 KWin 窗口菜单；按钮不能触发拖动。工具/设置在窄屏显示、宽屏位于侧栏底部。测试键盘 Tab、Enter、Escape、Tooltip、焦点恢复，以及 125%/150%/200% 缩放和文字放大。
6. 覆盖 1080×700、760×520、420×720、360×600 和压缩 720×500；长列表名、多列表横向滚动、排序、拖放与添加菜单不受标题栏影响。最窄五按钮各 44×48 逻辑像素；最大化后不保留拦截点击的 resize 边缘。
7. 在隔离数据中检查关闭到托盘、直接退出、压缩活动关闭确认和安装退出保护。关闭按钮必须进入原有 CloseRequested 路径。桌面歌词继续专用 layer-shell，不套用普通窗口材质。

## 性能记录

使用同一 Release、同一机器/驱动/窗口尺寸，分别以正常模糊与关闭 KWin 模糊效果对比，退出 Wayland 调试日志。每个场景预热后重复三次：静置、长列表滚动、拖动/连续缩放、窗口背后播放视频。记录帧时间/掉帧、KWin 与 WebKit GPU 负载、显存和功耗，注明工具与采样时长。没有可靠工具的数据留空，不能以 React CPU 低推断总 GPU 成本。

当前 adapter 每 200ms drain 自己的 pending 队列，GTK 负责读取同一 socket；前端只在内容区域几何变化时提交矩形，不运行 CSS blur。若出现静置唤醒/功耗问题，附测量再决定是否将队列调度改为专用 GLib source。

结果回填本文件与 STATUS：每项标注通过/失败/未测，附 SHA、环境、最短复现、必要日志和截图。失败项先判定前端、GTK surface 生命周期、协议能力还是 KWin 效果，再修对应 adapter；不通过禁用安全检查或添加强制模糊插件掩盖问题。
