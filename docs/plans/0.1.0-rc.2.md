# 0.1.0-rc.2 播放呈现、更新体验与音频压缩优化

- 状态：Implemented，自动门禁与浏览器回归完成，待原生验收
- 日期：2026-07-24
- 前置：rc.1 功能与自动门禁完成；真实覆盖更新和遗留 Windows 矩阵并入本版本

## 目标与边界

删除低价值的最近播放能力，统一当前歌曲封面在 React 与 Windows Shell 的呈现，简化关于/更新体验，提高多文件 WAV 到 FLAC 吞吐并让逐项进度和压缩效果可见。

性能优先、依赖体积次要。除非替代组件完整覆盖 16/24/32-bit integer、32-bit float、采样率/声道、元数据、取消与文件安全矩阵且吞吐更优，否则保留 FFmpeg。不得扩大为媒体库、标签编辑、更多格式、有损转码、DSP 或第二播放引擎。

## 已接受范围

### 删除最近播放

- 删除宽/窄屏入口、页面、前端状态/翻译/预览、DTO、Tauri command、播放后写入和持久化方法。
- 冷启动显示会话内“默认”列表，不留空白分隔或隐藏兼容入口。
- schema v5 对新数据库不创建 `recent_plays`，旧数据库迁移时只删除该表；保留用户播放列表、项目顺序和应用状态。
- 最近播放数据明确放弃，不提供导出、恢复或隐藏 API。

### 共享封面

- `MetadataService` 以路径、文件大小和修改时间为键缓存最多 4 首；限制源封面 16 MiB、源尺寸 8192、解码内存 64 MiB、缓存尺寸 1024。
- 一次解析生成 `TrackDetails`、编码封面、data URL 与 BGRA；底栏、完整播放器、SMTC、托盘投影和任务栏共用结果，不随播放位置 tick 重读文件。
- 底栏宽屏封面 52 px、窄屏 44 px，固定比例，不挤压曲名/时间/控制区；hover/focus 仍显示展开/收起动作。
- 无封面、损坏或超限统一使用项目占位图。

### SMTC 与任务栏

- SMTC 使用真实歌曲封面；提交失败时重试无封面元数据，不能连带丢失标题。
- 主窗口处理 `WM_DWMSENDICONICTHUMBNAIL` 与 `WM_DWMSENDICONICLIVEPREVIEWBITMAP`，通过 DWM API 提交只含封面/占位图的位图。
- 画布遵守系统请求/客户区协调尺寸并设合理上限；封面等比完整显示、居中、不裁切，不泄露 WebView 截图。
- 窗口消息回调只读缓存像素并管理 GDI 对象，不做文件 I/O、标签解析或解码。保留任务栏三个媒体按钮与进度。

### 关于与更新

- “关于”置顶。版本与检查更新合并为一个动态按钮：检查中、最新和发现版本都用短文本。
- 版权/许可证与 GitHub 按钮同一行；GitHub 使用官方矢量 mark，按钮风格、tooltip 和无障碍名称与其他 ActionIcon 一致。
- 更新状态由 App 持有；首个可交互帧后延迟一次静默检查，每进程最多一次。Rust 检查 single-flight，连接超时 5 秒、总超时 15 秒。
- 无更新或离线不弹窗。发现更新时懒加载弹窗，展示版本、日期、大小与 Markdown/GFM 日志；跳过原始 HTML，HTTP(S) 外链经 Rust opener。
- 弹窗内直接下载、验签、取消、失败重试和安装。禁止强制更新、静默下载、遥测或远程配置。

### 音频压缩

- 保留 FFmpeg 编码器；输入用 `hound`，临时 FLAC 用 `lofty` 验证，转换热路径不启动 ffprobe。
- worker 数按可用并行度保留一个响应核心并限制为 1–4。每个文件使用独立 FFmpeg 和唯一临时路径。
- `CompressionItem` 维护单调 `progress`、`sourceBytes`、`outputBytes`、状态、错误和删除结果；删除全局 `currentProgress`。
- 取消终止所有活动 FFmpeg 并清理未提交临时文件。已有输出永不覆盖；验证后原子提交，源 WAV 只在明确确认且提交成功后删除。部分失败不回滚成功项。
- 文件行本体使用低对比度进度覆盖层，内容位于其上；目录行不伪造进度。移除独立总进度/结果面板。
- 转换前汇总“数量 · 输入体积”；运行中显示完成数；终态只按成功项显示“输入 → 输出 · 节省体积/比例”，失败和取消追加简短计数。

- `STATUS` 只保留当前版本、开放门禁和风险；产品、架构、结构、开发规范只描述当前事实。
