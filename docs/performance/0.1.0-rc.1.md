# 0.1.0-rc.1 性能与音频审计

日期：2026-07-23

## 环境与方法

- Windows NT `10.0.26200.0`，x64 AMD 平台
- WebView2 `150.0.4078.83`
- Node.js `26.1.0`、npm `11.13.0`
- rustc `1.97.1`
- 前端使用 Vite production build 的输出统计；轮询成本按源码定时周期换算，并以浏览器实渲染确认隐藏/恢复行为。
- 后端通过代码路径审查、普通测试、显式真实音频设备测试和真实 FFmpeg 转换矩阵验证。
- release 主窗口启动计时在同一次已编译二进制上连续运行 10 次；每次等待最大可见窗口达到至少 `320×320`，随后正常关闭，超时才强制结束。
- 空闲资源在 release 主窗口稳定后采样 60 秒。CPU/Working Set/Private Bytes 只统计 Resona 父进程，不把系统内其他 WebView2 进程混入结果。

浏览器实渲染覆盖 `1080×700`、`800×600`、浅色、深色、更新卡片和安装确认弹窗；控制台无 warning/error。没有发现需要在 RC 阶段拆分 `App.tsx`、引入列表虚拟化或复制 Rust 状态到前端的证据。

## 原生启动与空闲基线

- 10 次可见主窗口就绪时间：`256.9, 262.0, 259.8, 266.5, 268.5, 264.2, 258.1, 249.6, 254.4, 254.5 ms`
- 中位数：`259.0 ms`
- 最小/最大：`249.6 / 268.5 ms`
- 60 秒空闲父进程 CPU 时间：`0.016 s`，折合单核心 `0.026%`
- Working Set：平均 `30.26 MiB`，峰值 `30.27 MiB`
- Private Bytes：平均 `5.94 MiB`，峰值 `5.96 MiB`

这是一份当前 rc.1 release 基线，不是与旧版严格同机 A/B 的“改善百分比”。WebView2 子进程、播放、托盘隐藏和桌面歌词场景仍需单独采集，不能从父进程空闲数据外推。

## 后端与音频结果

- 播放 actor 的 `150ms` tick 负责生命周期、进度和设备恢复；当前测试没有证明降低频率或改为另一套调度器会带来净收益，保持不变。
- SMTC、任务栏和托盘共享 `500ms` Rust 原生播放投影。它在主 WebView 隐藏时仍需工作，因此不能随前端可见性暂停。
- 音频输出由 Rodio/CPAL 的 `MixerDeviceSink` 管理。Resona 注入的输出错误回调只向无界标准通道发送错误文本，不执行文件、数据库或网络 I/O。
- 解码文件在 actor 命令路径打开并交给 Rodio；SQLite 状态恢复、媒体元数据、歌词、GitHub 更新和 FFmpeg 均不在音频输出回调中执行。
- 音量继续限制为 `0.0..=1.0`。没有加入软件增益、响度标准化、EQ、DSP 或额外重采样，也没有把 WASAPI Shared 描述为 bit-perfect。
- 未升级 Rodio、CPAL 或 Symphonia；避免在发布候选阶段改变输出行为和许可证矩阵。

自动矩阵覆盖 MP3、FLAC、PCM WAV、192 kHz/32-bit WAV、默认输出设备、无损队列预加载/切换、播放模式连续性、SMTC 控制和真实 FFmpeg 转换。普通测试与 9 个显式真实设备/转换测试均通过。

## 诊断开销与隐私

- 使用 Tauri 官方 Rust 日志插件写入平台规范的应用日志目录。
- 只接受 `resona`/`resona_lib` 模块 target 的 `Info` 及以上事件，不转发 WebView 控制台或第三方依赖日志。
- 单文件上限 `256 KiB`，`KeepOne` 轮转；日志不上传。
- 记录版本、生命周期、原生集成状态和更新结果码，不记录媒体完整路径或签名材料。
- NSIS 非更新卸载会删除 `%LOCALAPPDATA%\io.github.vki.resona`，因此日志与其他应用缓存一并清理；更新安装保留诊断和用户状态。
