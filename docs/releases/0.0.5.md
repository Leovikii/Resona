# Resona 0.0.5

Date: 2026-07-18
Status: Completed

## Delivered

- Replaced the technical-validation screen with the stable application shell: grouped left navigation, right content area, and a permanently mounted bottom player.
- Added the Now Playing view with a large square artwork placeholder and lyrics empty state. It is disabled without a current track and opens from the sidebar or bottom player without remounting the player controls.
- Added system, light, and dark color schemes; curated accent colors; and persisted UI preferences.
- Added Simplified Chinese and English through `i18next` and `react-i18next`, including system-locale selection.
- Added atomic file-context playback: opening a supported file loads its supported direct siblings in stable order and starts the selected item.
- Added folder browsing, positioned batch queue insertion, internal queue reordering, and Tauri WebView file/folder drop handling with structured rejection reasons.
- Kept the Rust playback service as the queue and playback authority. Frontend views consume typed snapshots and do not duplicate audio-domain state.

- The project owner confirmed playback controls and queue behavior on Windows.

## Limits

- Playlists and recent playback are not persisted; SQLite-backed library work remains in P3.
- Artwork and lyrics are placeholders; metadata extraction and synchronized lyrics remain later stages.
- The Tools page is only a stable entry point; WAV-to-FLAC conversion is not implemented.
- SMTC, media keys, and Windows system media information are proposed for 0.0.6 and are not included here.
- The native Windows file dialog can still block intermittently; application-side duplicate-dialog and parent-window boundaries are implemented, and further investigation remains deferred in `docs/KNOWN_ISSUES.md`.
- No Linux implementation or validation is included.
