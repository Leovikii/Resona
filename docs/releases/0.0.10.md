# Resona 0.0.10

状态：Completed，桌面歌词技术原型通过（2026-07-19）

## 交付内容

- 第二个同进程 Tauri WebView 窗口：透明、置顶、无边框、跳过任务栏，显示当前歌词和下一行。
- 桌面歌词前端按窗口标签独立懒加载，只消费 Rust 权威播放与歌词组合快照，不加载主应用壳、媒体库或第二播放控制器。
- 解锁状态支持拖动；锁定状态使用 Tauri 官方 `set_ignore_cursor_events(true)` 实现整窗鼠标穿透。
- 锁定后显示不含 WebView 的 Win32 owned tool window，提供 hover 与点击解锁；使用 `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE`，不使用全局 hook、轮询、输入注入或输入转发。
- 主窗口设置页提供显示/隐藏和锁定/解锁兜底入口；辅助窗口创建、定位或显示失败时不会进入锁定状态。
- 版本号统一更新到 `0.0.10`，新增桌面歌词窗口最小 Tauri capability。

## 架构实现说明

计划曾优先考虑 Tauri 无 WebView `WindowBuilder`。Tauri 2.11.5 的该能力在稳定 API 中仍不可用，需要启用 `unstable` feature。当前为避免引入不稳定 API，辅助窗口由 Windows platform adapter 在 Tauri 主事件线程通过 raw Win32 创建；HWND、窗口消息和 GDI 绘制均不离开该 adapter。

歌词 WebView 继续使用稳定 Tauri API。锁定顺序固定为先定位并显示辅助窗口，再启用歌词窗口穿透；解锁顺序固定为先恢复歌词窗口交互，再隐藏辅助窗口。

## 项目所有者验收

项目所有者已确认桌面歌词显示、同步、拖动、锁定穿透和原生解锁按钮基本功能正常，技术原型目标成立。同时确认以下问题：

1. 关闭主窗口后，桌面歌词窗口和播放仍继续运行，应用无法按预期退出。
2. 桌面歌词运行时开关目前位于设置页，正式入口必须移动到底部播放控制区；歌词窗口内还缺少最小锁定/隐藏控件。
3. 锁定后的原生解锁按钮可交互，但空闲时不会隐藏或淡出；正式行为应为鼠标进入热点后才显示。

这些问题记录为产品化阻塞项并转入 [0.0.11](../plans/0.0.11.md)，不回滚 0.0.10 已验证的双窗口技术方案。
