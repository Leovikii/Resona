# ADR 0015：播放列表激活、队列入口与单一状态展示

- 状态：Accepted；独立队列入口由 [ADR 0018](0018-playlist-as-playback-sequence.md) 替代，最近播放激活路径由 rc.2 撤销
- 日期：2026-07-20
- 补充：[ADR 0014](0014-player-only-scope-and-transient-default-playlist.md)

> 当前约束：标题唯一性、状态只在底栏表达、激活态优先和渲染隔离继续有效；列表与队列是不同产品对象、底栏打开独立队列抽屉的决定已经废止。底栏列表按钮现在定位并编辑当前播放列表。

## 背景

0.0.13 同时显示应用壳标题与页面标题，并在壳标题、徽章和播放控件重复展示播放状态。用户播放列表还提供“载入队列”“追加队列”“把当前队列复制到列表”按钮，要求用户理解三个内部集合，且容易制造重复项目。750 ms 播放快照轮询因此会更新与播放进度无关的页面区域。

## 决定

- 点击侧栏播放列表只选择详情；显式点击列表内任一曲目时，以该列表完整顺序替换 `PlaybackQueue` 并从目标曲目播放。
- 默认列表和最近播放的曲目激活沿用统一 external-open 服务；用户列表曲目激活使用原子 `replace_queue_and_play`。
- 删除列表页“载入队列”“追加队列”和“复制当前队列”入口。当前播放队列只从底部播放器的队列按钮进入，提供播放、移除和排序。
- 每个主内容视图只显示一个标题。播放/暂停状态只由底部主播放按钮表达；页面、标题栏和徽章不重复显示 idle/playing/paused/stopped。
- 激活导航项的颜色优先于 hover；hover 只作用于非激活项。
- 高频进度快照只驱动播放器和完整播放页。队列、输出设备和错误未变化时保持引用稳定，侧栏和普通页面通过 memo/低频 props 隔离。

## 后果

- 播放列表与队列仍是不同领域对象，但用户不需要通过管理按钮手工同步它们。
- “追加到队列”不作为 0.1.0 主工作流；未来如出现明确场景，必须以单曲上下文菜单等局部命令重新提案。
- UI 测试必须检查标题唯一性、状态文案唯一性、激活态 hover 和播放进度期间非播放器区域的渲染稳定性。
