# ADR 0019：临时默认列表退出语义与桌面歌词三分区工具栏

- 状态：Accepted
- 日期：2026-07-21
- 修订：[ADR 0013](0013-windows-lifetime-and-desktop-lyrics-controls.md) 的歌词工具栏布局
- 修订：[ADR 0018](0018-playlist-as-playback-sequence.md) 的默认列表会话恢复语义

## 背景

默认列表用于承载从资源管理器直接打开或临时导入的音频。它是用户可编辑的播放列表，不是持久化歌单；若重启后仍隐式恢复其内容，会和“临时默认列表”的产品语义冲突。

桌面歌词已经验证透明 WebView 加 Win32 owned-tool helper 的锁定穿透方案。原工具栏没有媒体信息区，且锁定 helper 位于右侧，与播放控制的视觉重心不一致。

## 决定

- 默认列表在正常退出时清空，下一次启动不恢复上次路径、当前曲目或播放进度。仅恢复音量、播放模式与输出设备选择等不属于播放列表内容的偏好。
- 默认列表拥有稳定的会话项目 ID，因此与用户列表共享选择、批量删除、清空和排序能力；它仍不写入 SQLite，且不可重命名或删除。
- 桌面歌词顶部使用三列固定网格：左侧为单行可省略的媒体名称，中间为上一曲、播放/暂停、下一曲，右侧为设置、锁定/解锁、关闭。
- 锁定后保持既有整窗穿透；唯一原生解锁 helper 移至相对窗口中央播放控制区。该 helper 仍使用 near-transparent alpha 命中策略，只在局部 hover 后绘制解锁图标。

## 后果

- 应用启动不再把 `PlaybackSessionRecord` 的路径序列交给 Rodio 或 `MediaImportService` 恢复；退出持久化记录中路径、当前路径和进度均为空值。
- 用户列表继续使用 SQLite 事务；默认列表批量操作通过 Rust 会话状态和 Rodio 内部执行序列同步，React 只维护视觉选择状态。
- 不引入第二个 WebView、全局鼠标 hook、轮询或输入注入。Windows 原生 helper 的移动必须更新现有单元测试和实机锁定验收。
