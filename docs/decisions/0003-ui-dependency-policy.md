# ADR 0003：UI 依赖与解耦策略

- 状态：Accepted
- 日期：2026-07-17

## 背景

Resona 允许依赖存在商业生态，但不接受免费核心要求许可证申请、密钥注入、联网激活、授权遮罩或运行时校验。完全包装第三方组件会增加代码和组件层级，却未必带来真实可替换性。

## 决定

使用 Mantine 作为主要组件库，并采用选择性隔离：

- 设计令牌由 Resona 持有。
- Mantine provider 和直接导入集中在 `app` 与 `shared/ui`。
- 领域组件隐藏第三方类型和默认行为。
- 不包装无状态、一次性、没有策略差异的基础控件。
- 不混入第二套完整组件库。

依赖准入与升级必须检查实际运行时行为，不能只检查 SPDX 标识。

## 理由

该策略把切换成本集中在主题和共享 UI 边界，又避免全量 facade 带来的重复 API、渲染层级和维护负担。组件函数本身不是音频性能路径，真正需要控制的是全局重渲染、长列表和高频事件。

## 后果

- feature 不保存 Mantine 类型，不把它们放入 command/event 契约。
- 发现第三方 bug 时优先在单个共享组件或 adapter 中修复，防止 workaround 扩散。
- 替换组件库仍需要重写 UI 实现，但不会影响领域状态、后端契约和业务服务。
