# ADR 0037：悬浮提示统一规范

- 状态：Proposed；正式版开发方案，本轮尚未实施。
- 日期：2026-11-04。
- 补充 ADR 0003、0006、0022、0033；保留 ADR 0036 的窗口内快捷键和音量反馈语义。

## 背景

底栏播放模式使用原生 `title`，其他按钮使用 Mantine Tooltip，音量提示还包含整段快捷键说明。原生提示无法共享应用字号、延迟和明暗表面，长说明在窄窗口中妨碍阅读。现有 Mantine provider 已管理主题，无需新增提示库或主题设置。

## 拟定规则

- 应用内控件提示统一使用 Mantine Tooltip，通过 `app` 的主题默认值与 `shared/ui` 的必要行为适配集中维护。不得逐控件复制样式，也不为每个控件新增包装组件。
- 普通提示只描述动作或当前状态，例如“上一首”“顺序播放”“音量 72%”；快捷键确有帮助时最多附当前动作的简短键名。完整键表放在设置中的按需帮助位置。错误、警告和必须阅读的说明在对应正文/弹层中展示，提示不承担唯一的信息入口。
- 初始默认值拟为：Mantine `xs` 字号、常规字重、约 1.4 行高，纵/横内边距 6/8px，圆角使用现有 `sm` token；最大宽度 240px 且受窗口可用宽度约束。长文本可换行，默认无箭头、无交互内容；具体值在代表性视口验收时收敛并集中修改。
- 使用已有主题的实体浮层表面、文本和边界 token，浅色/深色跟随 `auto/light/dark`；不跟随强调色填充，不另建系统主题订阅，不用 CSS blur。菜单、Popover 与提示保持一致的可读性和层级；透明桌面歌词中的提示仍须有实体背景，不能把歌词正文颜色直接当成提示颜色。
- hover 打开延迟初值 400ms、关闭延迟 80ms；键盘 focus 可发现同样说明，Escape 可关闭，不夺取焦点，不拦截底层点击。不为触摸自动弹出 hover 提示。显示期间指针移入提示应可保持阅读；离开触发范围/关闭后解除，不做永久常驻。
- 菜单、音量 Popover 或其他主交互弹层打开时关闭该触发器的提示；保持键盘调音量时已有百分比反馈。位置由浮层库处理边缘翻转/避让，不能用固定坐标或额外透明窗口实现。
- Tooltip 不能替代 `aria-label`、可见标签、disabled 原因或 focus 样式。禁用控件仅在需要解释原因时提供可达提示，不以全局包装改变命中、菜单锚点和原生 disabled 语义。
- 原生 DOM `title` 不再作为应用控件的提示实现；截断的文件名、路径、元数据也按需迁移到有界统一提示，完整内容仍可在原有详情中读取。审计时保留窗口/Modal 的 `title` 参数、SVG 文档标题等非 DOM 提示用途。

## 实施与验收

先底栏，后标题栏、列表、设置、压缩与歌词工具栏；按锁定 Mantine 参考/类型核对 defaults、Portal 和事件 API。共享外观尽量由主题实现，仅在多个真实调用点共享弹层互斥等行为时引入适配。

按 [正式版计划](../plans/0.3.0.md) 覆盖规定视口、主题、中英文、focus/Escape、缩放、长文本和弹层互斥。浏览器结果只证明布局；两端 WebView 的字体、原生主题和歌词透明窗仍需各自验证。纯样式改动不新增镜像实现的测试，有状态行为和失败路径才增加必要回归。
