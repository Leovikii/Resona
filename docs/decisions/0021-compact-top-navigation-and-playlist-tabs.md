# ADR 0021：窄屏顶部导航、播放列表标签与两行底栏

- 状态：Accepted
- 日期：2026-07-22
- 替代：[ADR 0020](0020-main-window-layout-modes-and-geometry.md) 中窄屏固定左侧 rail 与两行底栏的具体实现描述

## 背景

窄屏窗口的固定左侧导航栏会占用本就有限的横向空间，播放列表也需要在窄窗口中保持可见和可切换。此前曾尝试常驻左侧图标栏、完整侧栏 Drawer 和单行播放器：Drawer 与顶部导航、播放列表 Tabs 重复，单行播放器则让曲目信息、进度和七个固定控件争抢宽度。

## 决定

- 窄屏应用壳采用两层顶部导航：第一层提供 Resona 品牌、最近播放、工具和设置；第二层使用横向可滚动 Tabs 展示默认列表及用户播放列表，新增按钮固定在右侧。
- 删除左上角折叠/导航按钮、Drawer 和第二份 Sidebar。顶部已有入口覆盖全部当前页面，播放列表 Tabs 覆盖默认及用户列表，无需维护重复交互状态。
- 窄屏底栏使用 `120px` 两行稳定网格：第一行独占封面、曲目信息、进度和时间；第二行左侧为音质，中间为上一曲/播放暂停/下一曲，右侧为播放模式/桌面歌词/音量。播放按钮使用 Mantine `xl`，曲名继续使用 `OverflowMarquee`，不会穿透窗口或推动控制组换行。
- 窄屏设置页的歌词字号和歌词颜色均使用“标签 + 控件”两列单行布局；其他需要更多宽度的设置项仍可按既有规则纵向排列。
- 播放列表标签使用 Mantine `pills` 激活态并保留播放中 CSS 指示；标签文本严格限制在组件内部并省略溢出，标签菜单继续通过页面 Portal 按视口坐标定位。

## 理由

顶部 Tabs 更适合窄屏的高度富余场景，可直接切换全部列表；删掉 Drawer 减少一份组件树、开关状态和不可达交互。两行底栏以少量纵向空间换取稳定宽度，避免标题、进度和控制互相挤压。

## 后果

- `CompactTopNavigation` 成为窄屏导航的共享 UI 组件，Mantine 依赖仍集中在 `src/shared/ui`。
- 窄屏底栏从旧两行方案的 `132px` 收敛为 `120px`；播放控制槽位固定，不因歌词开关或音质标识变化而重排。
- 浏览器验证覆盖 360×600、420×720、中英文及明暗主题；Windows 原生窗口几何与 DPI 验收仍由主窗口原生测试负责。
