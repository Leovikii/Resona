# ADR 0021：窄屏顶部导航与播放列表 Tabs

- 状态：Accepted；0.1.0 修订
- 日期：2026-07-22，修订于 2026-07-26
- 替代：[ADR 0020](0020-main-window-layout-modes-and-geometry.md) 的窄屏固定 rail

## 决定

- 窄屏使用两层顶部区域：第一层提供品牌、工具和设置；第二层横向滚动展示默认/用户播放列表，新增按钮固定在右侧。
- 不保留 Drawer、第二份 Sidebar 或最近播放入口。宽/窄屏共享同一选择和播放状态。
- 窄屏底栏使用稳定两行网格，封面为 44 px；曲目信息、进度、时间和固定控制槽不能因动态内容重排。
- 播放列表 Tabs 文本省略溢出并保留播放中指示；导航与曲目列表统一使用不补零的普通序号，当前播放列表在相同固定槽位显示播放动画。菜单通过 Portal 按视口定位。
- 默认列表和用户列表 Tabs 是外部文件/文件夹拖放目标，复用主窗口的坐标命中与列表添加逻辑；拖到标签会添加项目并切换到目标列表，拖到标签间隙会复用宽屏 `playlist-gap` 路径，按位置创建并切换到新列表。
- 宽/窄屏共享用户播放列表拖曳排序和右键上移/下移；默认列表固定首位，排序结果由既有 Rust/SQLite 列表位置持久化。内部排序与外部文件拖放使用独立状态。播放列表导航和曲目列表靠近滚动边缘时持续自动滚动，滚动后重新计算插入位置；到达边界、拖放结束或组件卸载时停止。
- 窄屏标签区域将鼠标纵向滚轮转换为横向滚动；不使用鼠标拖曳平移，避免与标签排序竞争同一手势。
- 工具、设置和播放列表使用同一状态层级：默认透明，hover/focus 使用普通浅表面，激活使用主题色浅背景和主题色图标，不使用阴影。窄屏横向 ScrollArea 使用组件原生 scrollbar offset，标签不得覆盖滚动条。
- 宽屏播放列表、窄屏 Tabs 和曲目列表右键菜单共用 Mantine `Menu.ContextMenu` 适配器；每个命令统一为同尺寸 Lucide 图标和简短文本，危险命令使用组件原生红色语义。播放列表菜单同时提供事务化“关闭其他列表”，宽/窄屏动作与禁用条件一致。

## 后果

浏览器至少覆盖 360x600、420x720、中英文和明暗主题，并验证标签与 `0..N` 间隙的拖放标记、滚轮横移和宽/窄排序；Windows Release 验证文件/文件夹在宽/窄屏中的添加、新建、选中与插入位置一致，以及排序持久化、DPI 与几何恢复。
