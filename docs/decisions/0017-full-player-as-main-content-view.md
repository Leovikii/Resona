# ADR 0017：完整播放器作为右侧主内容视图

- 状态：Accepted
- 日期：2026-07-20
- 部分替代：[ADR 0014](0014-player-only-scope-and-transient-default-playlist.md) 的完整播放器覆盖层决定
- 补充：[ADR 0015](0015-playlist-activation-and-single-state-presentation.md) 的单一状态展示决定
- 补充：[ADR 0022](0022-native-window-materials-and-surface-hierarchy.md) 的普通窗口材质

## 背景

0.0.14 使用绝对定位层把完整播放器覆盖在已有右侧内容之上。底层列表仍保持渲染和可选择状态，侧栏点击只改变被遮住的内容，产生双层界面、无效交互、焦点层级和背景接缝问题。完整播放器与底部控件还使用不同表面颜色和边框，浅色主题下尤其容易出现透明感和白边。

## 决定

- 完整播放器是右侧主内容区的一种互斥视图，不是绝对定位覆盖层、模态框或侧栏路由。
- `selection` 继续保存最近播放、默认/用户列表、工具或设置上下文；`playerExpanded` 只决定右侧当前渲染完整播放器还是所选内容。
- 只通过底部左侧封面按钮进入或退出完整播放器；封面 hover/focus 显示展开或收起图标。右侧工具栏不提供重复的展开按钮，当前播放列表入口固定为最右控件。完整播放器内点击关闭恢复原选择；展开时点击任意侧栏项，先退出播放器再直接显示目标内容。
- 外部打开新媒体可以更新当前曲目和底层默认列表选择，但不创建第二份播放状态；完整播放器只消费既有权威快照。
- 底部播放器稳定挂载，展开/退出不会重建播放控制器、队列、歌词或元数据服务。
- 完整播放器和底栏使用同一 content surface；实色回退保持不透明，Windows 11 Mica 路径使用 ADR 0022 的受控透明度。展开状态取消两者之间的分割边框。界面标签使用“歌词”/“Lyrics”，不向用户展示“同步”实现术语。
- 不为该二态交互引入前端路由库、全局状态库或遮罩/焦点管理层。
- 歌词与播放信息共享固定高度面板和固定高度切换栏；当前歌词变化时在容器内平滑居中，禁止高亮位移产生横向滚动条。关闭按钮必须占用独立安全区，不得覆盖切换控件。
- 播放信息把源文件格式、采样率、位深、声道和码率合并为一行“输入音频”；另一行“系统输出”读取 `MixerDeviceSink::config()` 的实际 CPAL 输出采样率、样本格式和声道，便于判断共享模式下是否发生重采样。UI 不推测设备配置。

## 理由

- 互斥渲染从结构上消除双层内容、无效点击和层级竞争，比继续修补 z-index、pointer-events 或透明背景更稳定。
- 保留原选择即可低成本恢复上下文，不需要把完整播放器伪装成永久导航页。
- 底栏独立挂载符合播放器连续控制和高频快照隔离要求。

## 后果

- `FullPlayerView` 在 `.main-region` 正常文档流中占满可用区域，普通 `.content-viewport` 同时不渲染。
- UI 回归必须检查展开时普通页面内容不存在、侧栏切换会退出播放器、明暗主题背景连续、底栏无白边以及最小窗口无溢出。
