# ADR 0016：音频压缩独立工作窗口

- 状态：Accepted；rc.3 修订
- 日期：2026-07-20，修订于 2026-07-25
- 补充：[ADR 0022](0022-native-window-materials-and-surface-hierarchy.md)

## 决定

- WAV 到 FLAC 压缩使用按需创建、单实例、可关闭的普通 WebView 窗口；主窗口工具页只负责打开/聚焦。
- Rust 权威管理扫描、依赖与批次快照。窗口接受文件/文件夹/拖入，递归扫描不跟随链接类路径，单项错误不阻断其他文件。
- 扫描和参数校验使用进程内 `hound`；临时 FLAC 用 `lofty` 验证。FFmpeg 只承担实际编码，转换热路径不启动 ffprobe。
- 文件级 worker 按可用并行度取 1–4。每项有独立进度、源/输出体积、状态与错误；取消终止全部活动 FFmpeg 并清理临时文件。
- 文件行本体显示进度覆盖层，不维护重复结果面板。汇总只使用成功项计算输入、输出和节省空间。
- 关闭窗口即取消扫描并丢弃输入工作区；旧扫描结果不能写回。已启动转换独立于窗口生命周期并继续执行。
- 子窗口能力只开放对自身的显示、标题更新和文件选择；主窗口仍经 Rust adapter 创建或聚焦窗口。
- 已有输出不覆盖；验证后原子提交，源 WAV 只在用户明确确认且提交成功后删除。部分失败保留已成功结果。

## 理由与后果

独立窗口隔离长任务和复杂目录树；进程内校验减少子进程启动，有界并行提高多文件吞吐且避免无界争抢。真实 FFmpeg 格式矩阵、取消、冲突、删除顺序和部分失败必须自动覆盖；Windows 视觉与拖入仍需 Release 验收。
