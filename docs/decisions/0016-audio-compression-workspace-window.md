# ADR 0016：音频压缩独立工作窗口

- 状态：Accepted
- 日期：2026-07-20
- 补充：[ADR 0014](0014-player-only-scope-and-transient-default-playlist.md) 的工具入口决定
- 部分替代：[ADR 0014](0014-player-only-scope-and-transient-default-playlist.md) 中“0.1.0 不提供递归扫描”的笼统表述；只允许压缩工作流的一次性递归发现

## 背景

0.0.16 在主窗口工具页内完成了 WAV 到 FLAC 的最小任务闭环，证明固定 FFmpeg sidecar、参数保持、进度、取消、验证和安全删除方案可行。正式工作流还需要同时容纳文件/文件夹拖入、递归发现、按目录结构展示的大批待转换文件、扫描警告和任务结果。继续把这些控件直接铺在主窗口工具页会挤占播放器信息区，也会让工具入口、文件浏览和长任务状态混在同一 React 页面中。

该递归目录处理只服务于一次明确发起的压缩任务，不建立媒体库、不持久管理外部文件夹，也不改变 0.1.0 的纯播放器范围。

## 决定

### 窗口与入口

- 主窗口“工具”页只展示工具入口和必要的当前任务摘要，不直接承载压缩参数、待转换树或结果列表。
- 点击“音频压缩”打开或聚焦单实例普通 Tauri WebView 窗口 `audio-compression`。它不是透明、置顶或鼠标穿透窗口，不复用桌面歌词的 Win32 helper。
- 压缩窗口使用与主窗口相同的主题、主题色和中英文偏好，允许调整尺寸并记忆最后的有效尺寸和位置。
- 压缩窗口默认尺寸为 `800×560`、最小尺寸为 `700×500`；顶部使用与播放列表一致的单一添加菜单提供文件/文件夹入口，避免重复按钮和重复计数。
- 关闭压缩窗口只释放该 WebView，不销毁 Rust `CompressionService` 的权威任务状态；重新打开时从类型化快照恢复。关闭主应用仍由统一应用生命周期安全取消活动任务、终止 sidecar 并清理临时文件。
- 压缩窗口使用独立的最小 Tauri capability，只获得扫描和压缩工作流需要的 commands、dialog 和窗口权限。

### 导入与递归扫描

- 压缩窗口接受文件选择、文件夹选择以及外部文件/文件夹拖入。一次可以加入多个根路径。
- 文件夹导入在 Rust 后台递归遍历所有普通子目录；不得在 React 中递归文件系统或逐项拼装权威队列。
- Windows junction、符号链接和其他 reparse point 默认不跟随，避免目录循环、重复扫描和意外越出用户选择的根目录。重叠根路径和重复文件按规范化路径去重。
- 无权限、消失或无法读取的目录/文件形成结构化扫描警告，不因单项错误放弃其余根路径。
- 0.1.0 只把通过格式验证的 PCM 或 32-bit float WAV 纳入待转换集合。扩展名用于低成本候选筛选，扫描合法性由 Rust 内的 `hound` 读取 RIFF/WAVE 头确认；扫描阶段不得按文件启动 ffprobe 或建立外部进程池。损坏 WAV、已有冲突输出和不支持的样本格式以可诊断原因排除或标记。
- 扫描可取消，进度以批量快照或节流事件提供，不为每个目录项发送高频 WebView IPC。

### 目录树与任务

- UI 按每个导入根路径保留相对文件夹结构，显示可折叠目录和合法待转换文件；重叠导入后的同一文件只出现一次。
- 大目录使用扁平化可见节点模型，并在数据量达到性能阈值时虚拟化；折叠、选择和滚动状态属于压缩窗口临时 UI 状态，不进入转换领域模型。
- 用户可以在开始前移除根路径、目录或单个文件，并选择压缩档位和“成功后删除源 WAV”。真正提交给 `CompressionService` 的仍是稳定、去重、已验证的文件路径快照。
- 删除源文件继续默认开启，每次实际启动批次都必须根据最终文件数量明确确认。扫描或预览不能触发删除。
- 输出仍写入源 WAV 同目录；保持采样率和声道，16/24-bit 保持位深，32-bit integer/float 输出 24-bit FLAC，不覆盖已有 FLAC。

## 理由

- 普通独立窗口为树形浏览、拖放和长任务提供足够空间，同时保持主窗口播放器布局稳定。
- `CompressionService` 继续作为唯一权威来源，避免关闭窗口、重新打开或未来增加第二个入口时复制任务状态。
- 后台递归、去重、链接边界和结构化警告属于文件系统领域问题，放在 Rust 中更易测试，也不会阻塞 WebView。
- 单实例窗口和按需创建减少空闲 WebView 开销；它不会创建第二套 Rust 应用、播放核心或 FFmpeg 服务。
- 进程内头解析把扫描成本限制为顺序的小文件头读取，避免数十个进程启动、Windows 控制台闪烁和 CPU 峰值；真正转换仍由成熟 FFmpeg 完成，临时 FLAC 仍由 ffprobe 验证。

## 后果

- 0.0.16 的内嵌压缩面板作为技术验证保留在历史记录中，发行前要替换为工具入口和独立工作窗口。
- 需要增加压缩窗口前端入口、专用 capability、窗口生命周期服务、递归扫描 DTO/commands 及对应的目录循环、权限错误、去重、取消和恢复测试。
- 文件夹递归仅属于压缩工具，不得被复用为播放列表自动导入、受管理文件夹或媒体库扫描。
