# ADR 0013：Windows 应用生命周期与桌面歌词控件归属

- 状态：Accepted
- 日期：2026-07-19
- 修订：自 2026-07-23 起，“关闭主窗口即退出”由 ADR 0024 修订为默认询问且可持久化的“每次询问 / 隐藏到托盘 / 退出应用”偏好；其余桌面歌词资源与控件决定继续有效。

## 背景

0.0.10 证明了同进程 Tauri 歌词 WebView、整窗穿透和原生解锁辅助窗口可行，但实机验收发现主窗口关闭后辅助窗口会继续维持 Tauri 应用与播放核心存活。原型还把桌面歌词运行时开关临时放在设置页，原生解锁按钮则一直可见。

Windows WebView2 本身采用多进程架构；增加第二个 WebView 可能增加 renderer 子进程，但不会复制 Rust `RodioPlaybackEngine`。因此不能以进程列表数量直接判断播放核心重复，也不能忽略真正的应用退出和隐藏资源问题。

## 决定

- 当前 Windows 版本中，主窗口是应用生命周期所有者。关闭主窗口表示退出 Resona，同时停止播放并销毁桌面歌词 WebView、原生 helper 和其他应用资源。
- 桌面歌词是辅助窗口，不允许独立维持后台播放。系统托盘或关闭到托盘只有在未来新 ADR 接受后才能改变该语义。
- Resona 使用 Tauri 官方单实例能力防止重复启动创建第二套应用状态；第二实例只请求激活现有主窗口。
- 隐藏桌面歌词必须停止其快照轮询并释放闲置窗口资源；再次显示时按需重建，不用隐藏 renderer 换取微小的再次打开速度。
- 桌面歌词显示/隐藏属于播放运行时操作，主入口归属底部播放控制区。设置页只承载持久偏好，不承载该开关。
- 歌词窗口顶部控件顺序为“上一曲、播放/暂停、下一曲 | 设置、锁定/解锁、关闭”；设置按钮打开主窗口设置页，字号、颜色和背景透明度作为共享偏好保存。
- 解锁歌词窗口的控制条显示在歌词上方；锁定后的原生 helper 空闲不绘制，只有鼠标进入其命中区域后显示解锁图标，离开后隐藏。是否增加淡入淡出由后续视觉微调决定。
- helper 显隐继续由局部 Win32 消息和短时动画处理，不使用全局鼠标 hook、持续轮询或输入注入。空闲状态使用近透明 alpha=1 保留稳定命中；不使用 alpha=0，因为部分 Windows 环境会跳过完全透明 layered window 的首次 hover 命中。

## 理由

- 明确唯一生命周期所有者可以避免不可见后台播放和无法退出的应用状态。
- 官方单实例能力比自建 mutex、socket 或进程枚举更少代码，也能避免两套真实播放核心争用输出和数据库。
- 运行时播放动作位于稳定播放器区域更符合高频工作流；设置页保留给长期偏好。
- 隐藏时释放窗口和轮询符合本地播放器的低常驻开销目标。
- hover 才显示控制可以保留桌面歌词低干扰视觉，同时不改变已验证的整窗穿透架构。
- 第一条歌词开始前由 Rust 保持 `active_line_index == None`，UI 不得提前显示第一行；第一条开始后采用音乐播放器语义，在下一条开始前持续保留最近一行，包括 SRT/VTT cue 间隙和末行之后。

## 后果

- 应用层需要显式协调主窗口关闭、退出清理和重复退出，而不是依赖“最后一个窗口关闭”推断生命周期。
- `DesktopLyricsWindowService` 需要拥有可重复创建和销毁的资源状态，并保证部分失败后仍可再次显示。
- helper 需要 layered alpha、mouse leave 和短时 timer 动画；透明状态的首次命中必须实机验证。
- 未来加入系统托盘、后台播放或文件关联时必须扩展生命周期和第二实例参数转发协议，不能修改 UI 即宣称支持。

## 2026-07-26 置顶恢复补充

- 歌词 WebView 与原生 helper 的 topmost 属于 `DesktopLyricsWindowService` 平台资源状态，不因锁定与否改变。失去焦点、系统恢复或 DPI 变化只触发一次无激活原生校正，不创建后台保活任务。
- helper 的 38 px 逻辑命中区域保持不变；图标改用系统矢量字体并沿用歌词工具按钮的小圆角、白色图标和 hover 层级。组件库样式可作为视觉规范，但原生 helper 不为复用 React 组件增加 WebView。

## 2026-07-20 视觉交互补充

- 桌面歌词增加独立文字透明度偏好；它只影响歌词文字，不改变窗口或背景 alpha。
- 未锁定时，鼠标进入歌词窗口将背景临时切换到统一交互透明度，明确窗口边界和顶部控件区域；离开后恢复用户空闲背景透明度。
- 锁定后歌词 WebView 继续整窗穿透，不能依靠 WebView hover 或全局鼠标监听改变背景；只有既有原生解锁 helper 响应局部 hover。
- 当前行与下一行使用固定高度两行槽滚动切换，主要动画属性限制为 `transform` 和 `opacity`。跨多行 seek、歌词文档 revision 变化或系统减少动态效果时直接定位。
- 如果特定平台无法稳定实现两行滚动，允许降级为只显示当前行；不得保留“下一行消失后重新刷出”的生硬效果。

## 2026-07-22 纠正实现

- 桌面歌词的期望开启状态属于前端偏好，不等同于 Rust 窗口的瞬时 `visible` 状态；底栏开启、窗口关闭和后续播放自动显示均通过持久化偏好协调，未播放时不创建窗口。
- 窗口高度由字号计算并由原生层约束，歌词内容不改变窗口几何。只恢复位置和宽度；未锁定 hover 时显示左右点状握柄，通过仅授予歌词窗口的 Tauri `core:window:allow-start-resize-dragging` capability 启动水平调整。`Resized` 事件将高度恢复到当前字号目标，锁定状态仍完全穿透。
- 可见窗口的字号设置先执行 native fit，再提交 WebView 偏好，避免新字号先渲染在旧窗口高度中造成闪烁。布局测量只读固定隐藏探针，不观察会随模式变化的可见节点。
- 字号设置使用 16–64px 的纯数字输入，Enter/失焦提交、Escape 还原；不提供步进、滚轮和预设菜单。工具栏采用左右等宽、中央严格居中的三分区布局，避免右侧窗口控制向中央偏移。

## 2026-07-22 原生窗口锁边界补充

- `DesktopLyricsWindowService` 不得在持有内部状态锁时创建 Tauri/WebView 窗口，或调用可能同步/异步产生 `WindowEvent` 的尺寸与显示操作。窗口创建、几何恢复和 `set_size` 必须先复制所需句柄与状态，再释放服务锁。
- `Resized` 高度约束属于幂等校正回调；资源尚未安装时直接返回，不得等待正在创建资源的 command。原生 helper 的主线程派发必须有有限失败边界，不能无限等待 UI 线程。
- 桌面歌词几何格式不引入旧版本兼容层。开发阶段若保存状态与当前实现冲突，直接删除 `desktop-lyrics-window.json` 并使用居中默认值；无效 JSON 继续诊断后回退默认值。

## 2026-07-22 多显示器恢复补充

- 桌面歌词保存物理位置与物理宽度；恢复时不得使用窗口创建所在的主显示器缩放因子推导目标尺寸。目标高度和最小宽度必须使用目标显示器的 DPI 计算。
- 保存矩形同时与多个显示器相交时，选择可见交集面积最大的显示器，而不是系统枚举中的第一个相交显示器；完全离屏时选择窗口中心距离最近的显示器。
- 窗口保持隐藏时先移动到目标显示器，再应用最终物理尺寸；跨屏 DPI 变更可能采用 Windows 建议矩形，因此尺寸确定后再次设置保存的物理原点。该过程不得引入持续移动监听或高频磁盘写入。

## 2026-07-20 首帧显示补充

- 桌面歌词 WebView 先以隐藏状态创建，窗口 URL 在 HTML 预绘制脚本中同步声明透明背景，不能先显示黑色默认背景再切换透明度。
- 前端只有在偏好已同步且首个权威播放/歌词快照完成后，才调用幂等 `desktop_lyrics_window_ready` command 显示窗口。加载占位歌词不得进入第一个可见帧。
- `show` 表示用户请求可见并创建资源，`window_ready` 只完成仍然有效的物理显示；若用户已隐藏窗口，迟到的 ready 不得重新显示它。

## 2026-07-22 歌词排版与颜色作用域补充

- 桌面歌词颜色与文字透明度只作用于歌词正文，不得由窗口根节点继承到播放、设置、锁定或关闭控件；工具栏保持独立的中性色和可读对比度。
- 歌词正文使用固定两行总高度并允许当前歌词自然换行，避免长句直接单行省略，也避免歌词切换引起窗口内容跳动；当前歌词为单行时与下一行预览各占一行。
- 当前歌词实际占用两行时隐藏下一行预览，为当前歌词保留完整的两行空间；当前歌词为单行时继续显示下一行。该判断只使用单个元素尺寸观察，不建立轮询或逐字布局状态。
- 超过两行的极端长句降级为正文区域内的水平滚动，动画只使用 `transform`，避免静默截断；普通长句不启用该动画。
- 极端长句在当前歌词的实际展示区间内从头到尾线性滚动一次并停在末端；动画进度由行起止时间和权威播放位置决定，暂停时冻结，定位后直接同步，不往复滚动。
- 不因歌词长度自动缩小用户设置的字号，也不自动改变桌面歌词窗口尺寸，任何歌词布局都不得覆盖工具栏或破坏稳定窗口几何。
