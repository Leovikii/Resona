# ADR 0018：播放列表即当前播放序列

- 状态：Accepted
- 日期：2026-07-21
- 部分替代：[ADR 0014](0014-player-only-scope-and-transient-default-playlist.md) 的播放列表/队列分离决定
- 部分替代：[ADR 0015](0015-playlist-activation-and-single-state-presentation.md) 的独立队列入口决定

## 背景

Resona 0.1.0 是不管理外部媒体库的本地播放器。此前实现采用常见媒体库播放器的双模型：默认或用户播放列表在点击曲目时复制为独立 `PlaybackQueue`，之后两个集合可以分别编辑。该模型适合“歌单/专辑/搜索结果作为来源，临时队列作为播放计划”的产品，但 Resona 当前没有媒体库、歌单聚合或临时插播需求。

项目所有者确认首版采用 Foobar2000/AIMP 风格：播放列表本身就是用户看到和编辑的待播放序列。继续暴露独立队列会带来重复 DTO、commands、抽屉 UI、持久化恢复和同步错误，却没有当前消费者。

## 决定

### 产品模型

- 产品和 UI 只提供“播放列表”，不提供可独立编辑的“播放队列”。
- “默认”是未保存的会话播放列表；用户创建的列表是持久化的已保存播放列表。任意时刻至多一个列表是当前播放列表。
- 点击侧栏列表只浏览其详情；点击列表内曲目时，该列表成为当前播放列表并从目标曲目开始播放。
- 对当前播放列表追加、插入、删除或排序时，变更立即同步到后续播放顺序；编辑非当前列表不影响正在播放的序列。
- 删除正在播放的项目时立即从其原位置播放下一项；列表变空时停止并回到空闲状态。该行为与“删除即修改当前播放序列”保持一致，不保留列表外的隐式游离曲目。
- 底栏最右的列表按钮直接定位当前播放列表，不打开另一份队列抽屉。完整播放器打开时，该动作先退出完整播放器再显示当前列表。
- 删除当前持久化列表时，既有播放序列转移为“默认”临时列表，避免删除保存容器时无故丢失当前播放上下文。
- 会话恢复的路径序列恢复为“默认”临时列表；不在重启后隐式重新绑定并继续修改某个持久化用户列表。

### 播放核心边界

- Rodio actor 仍持有内部有序播放序列、当前索引、预载 source、失败状态和随机遍历状态。这是音频执行状态，不是第二个产品领域对象。
- Rust 播放列表协调服务维护当前列表来源，并把当前列表的结构变更同步给 Rodio actor。React 不传递整个列表来替换播放序列，也不维护竞争状态。
- 随机播放只改变内部遍历选择和历史，不修改用户看到的列表顺序。
- 移除公开的 `replace_queue`、`replace_queue_and_play`、`append_to_queue`、`remove_queue_item`、`move_queue_item` 和 `clear_queue` Tauri commands。引擎内部只保留连续播放实际需要的最小序列操作。
- 不为尚未存在的媒体库预建队列 adapter、动态来源接口或空 UI。未来出现专辑、搜索结果、临时插播等真实需求时，以新 ADR 引入独立队列协调层。

## 理由

- 单一用户可见序列消除“播放列表已经按此顺序排列，但待播放队列为何不同”的歧义。
- 活动列表编辑直接影响后续播放，符合 Foobar2000/AIMP 的高频工作流。
- 保留 Rodio 内部序列可以继续满足预载、连续播放、失败跳过和随机播放，不需要让数据库或 UI 进入音频 actor。
- 删除无消费者的公开接口符合项目“不为未来可能替换或扩展预建抽象”的开发准则；以后新增媒体库时，现有播放引擎仍可作为下游执行 adapter 复用。

## 后果

- `MediaImportService` 在当前阶段同时承担临时默认列表和当前列表来源协调；出现第二个真实列表来源策略前不为命名整洁增加额外层级。
- 持久化列表 command 在事务完成后同步活动播放序列；同步失败返回稳定的 `playback_sequence_sync_failed`，不得静默形成双状态。
- `PlaybackSnapshot.queue` 暂时保留为 Rodio 执行快照，供播放控制、SMTC、会话恢复和诊断使用；主窗口不把它呈现为第二个可编辑集合。后续只有在所有内部消费者完成收口后才评估缩小 DTO，不为字段名称单独进行高风险重写。
- UI 和自动测试必须覆盖：活动列表编辑同步、非活动列表编辑隔离、当前列表按钮定位、暂停/继续时普通内容不重挂载，以及随机播放不改变列表顺序。
