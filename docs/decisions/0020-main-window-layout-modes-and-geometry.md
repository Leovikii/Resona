# ADR 0020：主窗口宽屏/窄屏模式与几何恢复

- 状态：Accepted；rc.4 修订，窄屏导航细节由 [ADR 0021](0021-compact-top-navigation-and-playlist-tabs.md) 替代
- 日期：2026-07-21，修订于 2026-07-25
- 补充：[ADR 0006](0006-application-shell-theme-and-locale.md) 的固定宽屏应用壳
- 补充：[ADR 0017](0017-full-player-as-main-content-view.md) 的完整播放器布局

## 背景

Resona 当前主窗口固定使用“左侧栏 + 右侧主内容 + 底栏”，最小尺寸为 `760×520`。该约束避免普通桌面窗口被动坍缩成不可用的移动网页，但用户也需要主动选择一种竖向窄窗口，在较小屏幕区域内完成列表、设置、播放和歌词操作。

主窗口目前不恢复位置和尺寸。若仅用 CSS 媒体查询实现窄屏，窗口原生最小尺寸、下次启动首帧和用户选择的模式无法保持一致；若让 React 保存操作系统坐标，又会破坏平台边界并造成首次显示后的二次跳动。

## 决定

### 显式布局模式

- 新增类型化 `MainWindowLayoutMode = Wide | Compact`，设置页使用二段选择控件手动切换，默认 `Wide`。
- 布局模式不根据当前宽度自动切换。`Wide` 继续防止窗口缩小为移动布局；只有用户选择 `Compact` 后才允许进入竖向窄窗口。
- `Wide` 默认/最小尺寸保持 `1080×700`/`760×520`；`Compact` 默认/最小尺寸为 `420×720`/`360×600`。
- 切换模式时恢复该模式上次保存的窗口几何；没有记录时使用对应默认尺寸并约束到当前显示器工作区。切换不得重建播放 controller、列表状态、歌词文档或当前页面选择。

### 主窗口几何所有权

- Rust/Tauri 负责布局模式、主窗口位置、尺寸和最大化状态的持久化与显示器可见区域约束，React 不读写屏幕坐标。
- `Wide` 与 `Compact` 分别保存正常窗口几何，避免两种纵横比例互相覆盖。最小化和全屏不作为下次启动状态；最大化只与对应模式一起恢复。
- 主窗口仍先隐藏；Rust 在首帧前应用布局模式、最小尺寸和几何，React 完成主题与应用壳绘制后再显示，不能先显示宽屏再跳成窄屏。
- 普通主窗口与音频压缩窗口可复用无平台特性的几何约束/序列化代码；桌面歌词的透明、置顶、多显示器与 Win32 helper 生命周期继续留在其 platform adapter。

### 窄屏应用壳（具体导航与底栏由 ADR 0021 收束）

- 窄屏使用顶部两层导航和横向播放列表 Tabs；第一层提供品牌、最近播放、工具和设置，第二层提供默认/用户播放列表与新增入口。不保留 Drawer 或第二份 Sidebar，具体约束见 [ADR 0021](0021-compact-top-navigation-and-playlist-tabs.md)。
- 主内容改为单列并占满可用宽度。列表标题与操作允许换行，设置行纵向堆叠，所有可滚动区域使用 Mantine `ScrollArea`，可见轨道只在滚动期间出现并在静止后自动隐藏，不暴露 WebView 原生滚动条或常驻轨道。
- 宽屏底栏使用左右等宽、中间固定控制槽的三列网格：封面与曲目信息靠左，带描边的紧凑音质角标位于时间右侧，上一曲/播放暂停/下一曲相对整个底栏严格居中，音量、播放模式、桌面歌词和当前播放列表靠右。
- 窄屏底栏使用 `120px` 两行结构：第一行显示封面、曲目信息，并与宽屏一致把带描边的紧凑音质角标放在时间右侧；第二行左侧放置音量与播放模式，中间三键严格居中，桌面歌词与当前播放列表靠右且列表按钮固定最右。全部 ActionIcon 继续使用 Mantine `xl` 44 px，不得折叠到更多菜单或因标题换行改变控制组高度。宽/窄底栏的辅助控件使用 Mantine `transparent`，正常、激活和禁用状态均不显示背景；hover/focus 与持久激活只改变 SVG 颜色。上一首/下一首使用中性色，中央播放/暂停使用 Mantine `filled` 圆形实体背景、阴影 token 和白色实心 SVG 建立主次；禁用时保留原生灰色实体轮廓。全部 Mantine 按钮通过 ADR 0006 的主题级 `activeClassName` 使用无位移亮度反馈；按钮本体和浮层锚点始终保持原位，不改变布局高度、外框或 Menu/Popover 定位。
- 底栏曲名等少量单实例高价值文本可在实际溢出时自动滚动；侧栏播放列表名称只在 hover/focus 时滚动。滚动只使用 CSS `transform`/`opacity`，`ResizeObserver` 仅在尺寸变化时判断溢出，`prefers-reduced-motion` 下退化为省略。曲目大列表继续省略并提供完整标题，不为每行建立观察器或动画。
- 窄屏完整播放器使用封面、歌词、播放信息三页，曲名/歌手与关闭按钮共用稳定 header；有歌词默认歌词，无歌词默认封面。宽屏保持左侧封面常驻，右侧在歌词和播放信息两页切换。分页细节见 [ADR 0017](0017-full-player-as-main-content-view.md)。
- 外部文件拖入、播放列表选择/排序、右键菜单、主题和语言继续调用现有 typed 边界；布局组件不得复制领域状态或创建第二个播放器。

## 理由

- 显式模式符合“普通窗口保持桌面布局、需要时主动进入竖屏”的产品意图，比按像素自动猜测更可控。
- 两套几何使用户可以在横向主工作区和竖向伴随窗口之间快速切换，不需要每次重新拖动窗口。
- 在原生窗口显示前恢复模式和几何，可避免启动后二次缩放、白屏和位置跳动。
- Mantine Tabs、Menu、ScrollArea、Stack 和现有 SegmentedControl 足以完成窄屏组合；滚动文本只增加无领域状态的共享展示组件，不引入第二组件库。

## 后果

- 0.0.18 增加主窗口几何 adapter、类型化布局命令/快照、设置项和两套响应式应用壳验收。
- 浏览器只能验证布局、滚动和交互可达性；Windows 位置、最大化、多显示器/DPI 恢复仍需原生测试。
- 该模式只改变主窗口。音频压缩窗口和桌面歌词窗口保持各自独立的尺寸与生命周期规则。
