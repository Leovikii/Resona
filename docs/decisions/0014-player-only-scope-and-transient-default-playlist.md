# ADR 0014：播放器单一范围与临时默认播放列表

- 状态：Accepted；播放列表/队列分离部分已由 [ADR 0018](0018-playlist-as-playback-sequence.md) 替代
- 日期：2026-07-20
- 部分替代：[ADR 0006](0006-application-shell-theme-and-locale.md) 的导航与“正在播放”视图决定
- 替代：[ADR 0010](0010-metadata-index-adapter.md) 的受管理文件夹媒体索引决定

> 当前约束：本文件关于纯播放器范围、临时默认列表、持久化用户列表和媒体库淘汰的决定继续有效；把列表投影为可独立编辑 `PlaybackQueue`、默认列表追加不改变当前播放序列以及默认列表重启必为空的描述属于历史决定。当前播放列表模型和会话恢复语义以 ADR 0018 为准。

## 背景

0.0.7、0.0.8 和 0.0.12 验证了 SQLite 播放列表、受管理文件夹、元数据索引及最小内容交互，但这些能力把 Resona 推向媒体库管理器，并显著扩大扫描、缺失文件、查询、层级和 UI 的维护面。0.1.0 的目标重新收束为纯粹的本地播放器：用户明确选择或从系统打开媒体，Resona 不接管、监听或复制外部音乐目录。

现有侧栏还同时包含“正在播放”“文件夹”“播放列表”和“最近播放”，播放列表入口内又混合当前队列与持久化列表，导致信息架构和交互语义不清。项目所有者要求用临时“默认”播放列表承接外部打开的目录上下文，用持久化用户列表承接明确保存的集合，并把未来完整播放页改为从底部播放器展开的覆盖层。

## 决定

### 产品与持久化范围

- 0.1.0 不提供受管理文件夹、媒体库索引、递归扫描、文件监听、搜索、专辑或艺术家聚合视图。
- 删除侧栏“文件夹”页及受管理文件夹 UI、commands、service、DTO 和运行时代码。
- SQLite 只保存用户播放列表、播放列表项目和“最近播放”历史，不保存默认播放列表、外部目录、媒体记录或封面索引。
- `recent_plays` 是有限长度的播放事件历史，不是媒体库；保留它是为了让明确存在的“最近播放”页能够跨重启工作。
- 已有 `managed_folders` 和 `media_records` 通过版本化 migration 删除。删除这些表不得影响用户播放列表和最近历史。

### 默认播放列表

- “默认”是 Rust 应用服务拥有的会话内临时播放列表，不写入 SQLite；应用重启后为空。
- 打开一个音频文件时，Rust 枚举该文件所在目录的直属受支持音频，按稳定文件名顺序生成候选路径快照，不扫描子目录，也不读取整目录元数据。
- 如果候选路径快照与当前默认列表完全一致且目标文件已存在，只切换目标索引并播放，不重建默认列表；如果目录内容发生变化，则原子替换默认列表后播放目标文件。
- 因为枚举直属目录项成本低，优化以“路径快照相同则不发布新 revision、不重建队列”为边界，不依赖可能失真的目录时间戳，也不缓存解码器或元数据。
- 从命令行、Windows 文件关联、第二实例参数、应用内文件选择器或等价拖入入口打开单个媒体时，都复用同一 `open_media_context` 应用服务。
- 当前播放队列、临时默认列表和持久化用户播放列表保持不同领域对象；只有明确的播放动作才把某个列表投影为权威播放队列。

#### 2026-07-21 手工添加补充

- 默认列表允许用户通过统一“添加”菜单向当前会话列表末尾追加媒体，或把多个文件/文件夹拖到曲目间隔按目标位置插入；该行为不写入 SQLite，也不自动开始或打断播放。
- 文件夹只枚举直属 MP3/WAV/FLAC，不扫描子目录；多个来源按输入顺序合并，文件夹内部沿用稳定文件名顺序，重复路径由 Rust 服务去重并形成结构化拒绝结果。
- 手工组合多个目录后 `source_directory` 为空，UI 显示“多个来源”；若所有曲目仍来自同一目录则继续显示该目录。
- 点击默认列表任意曲目时，以当前完整默认列表原子替换播放队列并从目标索引开始播放；不得再次调用单文件 `open_media_context` 并意外覆盖手工组合列表。
- 默认列表与用户列表右上角复用同一个“添加”菜单，提供“添加文件”和“添加文件夹”两个动作；原生选择器不伪装成同一对话框同时选择文件和文件夹。
- 默认列表非空时，只有曲目滚动区参与外部拖放命中；标题和操作控件不参与。曲目行按中线计算最近插入位置，并复用内部排序的扩展间隔与插入线反馈。

### 播放列表与应用壳

- 侧栏顶部为“最近播放”；其后使用轻量分隔，再显示“播放列表”分组标题与新增按钮。
- 普通冷启动默认选择“最近播放”；从外部打开媒体时切换到“默认”详情并开始播放目标文件。
- “默认”作为播放列表分组内固定的第一个子项；用户列表按持久化顺序显示在其下方。点击任一列表只在右侧显示详情，不隐式替换当前播放队列。
- 用户列表持久化并支持新建、重命名、删除、添加、插入和重排。外部文件拖到某个用户列表时按目标位置插入；拖到侧栏列表间隔时在该位置创建新的用户列表。
- 自动创建列表的名称优先取共同父文件夹名称；无法得到稳定名称或发生冲突时使用本地化缺省名称加稳定序号。
- 删除侧栏“正在播放”页。未来完整播放页由底部播放器展开为覆盖主内容区的专用层，关闭后恢复原来的列表上下文；在该能力实现前不保留无效入口或占位导航。
- 完整播放页只按需读取当前曲目的元数据、音频参数、封面和歌词，不建立媒体库索引。标签编辑入口属于工具能力，但不进入 0.1.0。

### 后置能力

- “格式转换”统一命名为“音频压缩”，0.1.0 只计划 WAV 到 FLAC；其任务、冲突和文件安全设计放在核心播放与交互稳定后完成。
- 标签编辑、托盘和 Tauri updater 检查更新均排在核心功能与 UI 交互之后。更新器只负责用户主动检查和应用更新，不引入账户、遥测或联网激活。

### 桌面歌词平台边界

- 通用代码继续只依赖 `DesktopLyricsWindowService`、状态 DTO、错误码和 capability，不接触 HWND、WebView2 或 Wayland 类型。
- Windows 的原生 helper 和窗口消息只存在于 `platform/desktop_lyrics/windows.rs`。未来 Linux 实现在 `platform/desktop_lyrics/linux.rs` 内根据 Wayland 实际能力实现或降级。
- 当前只有 Windows 实现，不新增动态插件 ABI或为单一实现预建多层 trait。等 Linux 开始开发且出现第二个真实实现时，再从稳定 facade 后面提取共同 backend 契约。

## 理由

- 删除媒体库索引能同时移除数据库、扫描、缺失状态、查询和 UI 层级，符合低开发成本和低维护面的基准。
- 临时默认列表保留“打开一个文件即可播放同目录歌曲”的高频体验，又不把用户文件夹变成受管理数据源。
- 每次打开只枚举文件名并比较路径快照，比维护目录时间戳缓存更可靠；相同快照不重建状态即可获得主要性能收益。
- 最近播放保留独立小表能用现有成熟 persistence 边界实现跨重启，不会重新引入媒体库复杂度。
- 桌面歌词当前 facade 已经隔离平台细节；在没有 Linux 实现前继续增加抽象只会增加代码而没有验证价值。

## 后果

- 0.0.8/0.0.12 的媒体扫描实现作为已验证但被产品范围淘汰的代码删除，不继续维护。
- 需要为默认列表、用户列表顺序、第二实例媒体参数和路径快照比较建立明确契约与自动测试。
- Windows 安装阶段才注册 MP3/WAV/FLAC 文件关联；此前可通过命令行参数验证同一打开协议。
- 不再承诺媒体库搜索、全盘封面缓存或外部目录自动更新。
