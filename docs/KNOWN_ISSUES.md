# 已知问题

只记录仍开放、可复现或有明确重新调查条件的问题。已关闭缺陷不保留流水。

## 外部拖入待原生回归

资源管理器拖入默认列表和用户播放列表的逻辑已实现并有浏览器/单元覆盖，但仍需在安装版验证多文件、目录、重复路径、活动列表编辑和窄屏目标命中。发现丢项、错误目标或播放序列变化时阻塞 0.1.0。

## 多显示器与 DPI

主窗口几何已按显示器工作区归一化并限制最小尺寸；桌面歌词有独立恢复策略。仍需覆盖：100/125/150/200% 缩放、负坐标显示器、拔插副屏、最大化重启、跨屏恢复和 helper 命中。窗口不可见、尺寸失控或歌词位置错误时阻塞 0.1.0。

## Windows 原生封面呈现

SMTC 与 DWM iconic preview 已接入共享封面缓存，自动测试只能验证状态映射和像素生成。仍需在 Windows 10/11 Release 中确认：有/无封面切歌、超宽/超高封面、任务栏大/小缩略图、不同 DPI、Explorer 重启和 SMTC 提交失败回退。任务栏预览过小、裁切、残留旧封面或退回窗口截图时阻塞 rc.2。

## 桌面歌词原生视觉

浏览器覆盖不能证明透明窗口、Mica、穿透和多显示器行为。安装版仍需验证长歌词、双行切换、字体/描边/透明度、helper 显示与点击、任务栏隐藏、睡眠恢复和退出清理。

## 文件选择窗口低频阻塞

Windows 原生文件选择窗口曾低频阻塞，当前没有稳定复现。应用已保持单实例、正确 parent 和后台任务隔离，不增加第二套对话框实现。

重新调查条件：

- 当前版本可稳定复现，或出现可收集的错误/事件日志
- 阻塞影响发布主流程或造成数据损失
- Tauri/dialog/WebView2 上游明确修复相关问题

重新调查时先记录 Windows/WebView2/Tauri 版本、对话框类型、父窗口状态、目标路径类型和阻塞前日志，再决定升级依赖或建立最小复现。

## 发布外部条件

- 正式 GitHub Release 覆盖更新尚需用受保护密钥和真实托管产物完成一次。
- 正式 Windows 发布仍需要 Authenticode 发布者方案；updater `.sig` 只证明更新完整性。
